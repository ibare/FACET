# 하드 링크와 심볼릭 링크

{facet:hardVsSoftLink}

디렉터리 `docs` 에는 이름이 셋 있다. `report.txt` 와 `backup.txt` 는 둘 다 inode 23 을 가리키는 **하드 링크**다 — 어느 쪽이 원본이고 어느 쪽이 사본인 것이 아니라, 한 실체에 이름이 둘 붙어 있을 뿐이다. 그래서 inode 23 의 링크 수는 2 다. `latest` 는 inode 40 을 가리키는데, 이 inode 는 **심볼릭 링크**라서 안에 데이터 대신 이름 `report.txt` 가 적혀 있다.

재생은 여덟 걸음이다. 먼저 `backup.txt` 와 `latest` 로 실체를 찾아간다. `backup.txt` 는 inode 23 에 곧장 닿는다. `latest` 는 inode 40 에 닿은 뒤, 거기 적힌 이름을 꺼내 같은 디렉터리에서 다시 찾아야 inode 23 에 닿는다 — 한 번 찾기가 두 걸음이 된다.

그다음 `report.txt` 를 지운다. 지우기(unlink)는 디렉터리 항목 하나를 없앨 뿐이라 inode 23 의 링크 수가 2 에서 1 로 줄고, 실체는 그대로 남는다. 같은 두 찾기를 되풀이하면 `backup.txt` 는 여전히 inode 23 에 닿지만, `latest` 는 적힌 이름 `report.txt` 를 찾다가 빈자리에서 끊긴다. 끊긴 것은 실체가 아니라 이름이다.

링크 수가 0 이 되어야 — 그리고 파일을 연 프로세스가 없어야 — 파일 시스템은 inode 와 블록을 거둔다. 하드 링크가 파일 시스템의 경계를 넘을 수 없고(inode 번호는 한 파일 시스템 안에서만 뜻이 있으므로) 심볼릭 링크는 넘을 수 있는 것도 같은 차이에서 나온다.

여기의 inode 번호와 이름은 예로 정한 값이다. 실제 파일 시스템에서는 `ls -i` 로 inode 번호를, `ls -l` 의 둘째 칸으로 링크 수를 볼 수 있고, `ln` 과 `ln -s` 가 각각 두 링크를 만든다. 짧은 심볼릭 링크는 적힌 이름을 inode 안에 바로 담기도 한다(ext4 의 fast symlink).
