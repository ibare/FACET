# 인덱스와 질의 꼴

인덱스가 걸려 있는데도 옵티마이저가 표를 통째로 훑는 것은 언제일까. 이 시각화는 같은 질의 하나를 **표 훑기 · B+ 트리 · 해시 인덱스** 세 길에 한꺼번에 걸고, 길마다 실제로 읽을 페이지 수를 센 뒤 가장 적게 읽는 길로 읽는다. 끝으로 `INSERT` 한 번이 걸린 곳마다 페이지를 쓰는 것을 본다.

## 손잡이

- **인덱스** — 없음 · `B+` · 해시 · 둘 다. 걸리지 않은 구조는 흐리게 자리를 지키고, 그 길의 걸음은 건너뛴다.
- **질의** — `= 49` · `30–36` · `30–42` · `30–50`. 화면 위의 SQL 이 그 수만 바뀐다.

질의를 넓히면 B+ 트리의 읽을 잎을 두른 띠가 잎 사슬을 따라 옆으로 번지고, 해시의 띠는 버킷 하나에서 여덟 전부로 번진다. 막대는 앞 판의 길이에서 새 길이로 자라며, 표 훑기 값에 그은 세로선을 B+ 막대가 넘는지가 보인다. "가장 쌈" 표지는 고른 길의 줄로 건너가고, 읽는 점이 질의에서 출발해 인덱스 페이지를 거쳐 표 페이지로 옮겨 간다. 마지막 걸음에서는 `INSERT INTO orders VALUES (16, 38)` 의 줄기가 표 · 잎 · 버킷으로 갈라져 내려간다.

## 걸음

한 판의 걸음 수는 걸음 0(처음 모습)을 넣어 센다. 인덱스가 없음이면 4, `B+` 이나 해시 하나면 5, 둘 다면 6.

0. 처음 — 구조와 질의 SQL, 아직 흐린 `INSERT` 문
1. 표 훑기 값
2. B+ 값 (B+ 가 걸렸을 때만)
3. 해시 값 (해시가 걸렸을 때만)
4. 가장 싼 길을 골라 그 길의 페이지를 읽는다 — 인덱스 페이지를 차례로 지난 뒤 맞은 줄의 표 페이지로
5. `INSERT` 가 걸린 곳마다 쓴다

"끝났다" 는 따로 알리지 않는다. 걸음 5 의 캡션과 계기에 쓴 페이지 수가 뜨면 한 판이 끝난 것이고, 손잡이를 돌리면 다음 판이 처음부터 다시 돈다.

## 세는 법

- 표 `orders (id, price)` 는 줄 열다섯이고 표 페이지 하나에 줄 둘이 든다 — 표 페이지 T1..T8 (T8 에는 빈자리가 하나 있다).
- 페이지 하나를 읽으면 1, 쓰면 1. **캐시는 없다고 본다** — 같은 페이지를 다시 읽으면 다시 센다. 이 데이터에서는 맞은 줄들이 표 페이지 하나를 나눠 쓰는 일이 없다.
- **표 훑기** = 표 페이지 전부.
- **B+ 트리** = 뿌리에서 아래 끝으로 내려가고(가름 열쇠 `k ≥ s` 면 오른쪽), 잎 사슬을 옆으로 건너가며, 위 끝을 넘는 열쇠를 처음 만난 잎에서 멈춘다(그 잎도 읽은 페이지). 값 = 안쪽 페이지 + 읽은 잎 + 맞은 줄마다 표 페이지 하나.
- **해시** = 버킷은 `price mod 8`, 버킷 하나가 페이지 하나. `=` 는 버킷 하나를, 범위는 버킷 여덟을 모두 연다. 값 = 연 버킷 + 맞은 줄마다 표 페이지 하나.
- **고르기** = 값이 가장 작은 길. 값이 같으면 먼저 적힌 길(표 훑기 → B+ → 해시)이 이긴다. 이 데이터의 열여섯 조합에서는 동률이 한 번도 걸리지 않는다.
- **INSERT** 는 쓴 페이지만 센다 — 표 1 + 걸린 인덱스마다 1. 자리를 찾느라 읽는 페이지는 세지 않는다.

## 이 모형이 둔 전제

- 비용은 **실제로 읽을 페이지 수**로 셈했다. 실제 옵티마이저는 통계로 **추정**한 비용으로 고른다 — 그 이야기는 비용 모형 시각화의 몫이다.
- 범위 질의에서 해시 인덱스를 "버킷 전부 연다" 로 둔 것은 비교를 위한 모형이다. 실제 해시 인덱스는 범위 질의에 쓰이지 않는다.
- 잎에 빈자리가 있어 `INSERT` 가 잎 나눔을 부르지 않는다 (L2 의 항목이 넷에서 다섯이 되고 칸은 다섯이다).
- 코드 패널의 셈은 트리 페이지를 걷지 않고 잎 열쇠를 잎 차례로 편 배열로 같은 답을 낸다 — "내려가기가 닿는 잎 = 아래 끝 이하 마지막 열쇠의 잎". 가름 열쇠가 오른쪽 가지 맨 왼쪽 잎의 첫 열쇠라서 둘이 같다.
