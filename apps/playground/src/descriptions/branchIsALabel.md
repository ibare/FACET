
## 브랜치는 커밋을 담지 않는다 — 가리킬 뿐이다

커밋 셋이 줄지어 있다. `A ← B ← C`, 화살은 새 커밋에서 부모 쪽으로 간다. 이름 `main` 이 `C` 를
가리키고, HEAD 는 `main` 을 가리킨다. 여기서 브랜치 `feature` 를 만들고, 그리로 옮겨 커밋 하나를 하고,
다시 `main` 으로 돌아와 커밋 하나를 더 한다. 브랜치를 만들 때 커밋이 가지에 복사되는가, 커밋을 할 때
무엇이 움직이는가.

{facet:branchIsALabel}

브랜치는 **커밋 하나를 가리키는 이름**이다. 커밋을 담는 그릇이 아니다. 그래서 규칙은 셋뿐이다.

- **이름을 만들면**(`git branch feature`) HEAD 가 가리키는 이름의 커밋에 이름이 하나 더 붙는다.
  커밋은 하나도 늘지 않는다.
- **HEAD 를 옮기면**(`git switch feature`) HEAD 가 가리키는 이름만 바뀐다. 어느 이름도 커밋을 바꾸지 않는다.
- **커밋을 하면**(`git commit`) 새 커밋의 부모는 HEAD 가 가리키는 이름의 커밋이다. 그리고 **그 이름 하나만**
  새 커밋으로 옮겨 간다. 다른 이름은 제자리에 있다.

### 걸음 여섯

처음 화면을 넣어 여섯 걸음이다.

| 걸음 | 일어나는 일 | 커밋 수 |
|---|---|---|
| 0 | `A ← B ← C` · `main` → `C` · HEAD → `main` | 3 |
| 1 | 이름 `feature` 가 `C` 에 붙는다 | 3 |
| 2 | HEAD → `feature` | 3 |
| 3 | 새 커밋 `D`, 부모 `C` · `feature` 만 `C` → `D`, `main` 은 `C` 에 | 4 |
| 4 | HEAD → `main` | 4 |
| 5 | 새 커밋 `E`, 부모 `C` · `main` 만 `C` → `E`, `feature` 는 `D` 에 | 5 |

끝에 남는 것은 이름 둘과 커밋 다섯, 그리고 이름마다 가리키는 커밋 하나다. 그렇다면 "`main` 브랜치의 커밋" 은
무엇인가. `main` 에서 부모를 따라 거슬러 닿는 커밋 — `E C B A` 다. `feature` 에서는 `D C B A` 가 닿는다.
`A` `B` `C` 셋은 두 이름 모두에서 닿는다. 커밋은 어느 가지에 담긴 것이 아니라, 이름에서 거슬러 닿을 뿐이다.
걸음 1 에서 커밋 수가 3 그대로인 것도 같은 까닭이다 — 브랜치를 만드는 비용은 이름 하나다.

이름표가 한 칸 옮기는 것은 **새 커밋이 생겨서**다. 커밋을 만들지 않고 이름표가 여러 칸을 한 번에 건너뛰는
경우(빨리 감기 병합)는 따로 볼 문제다.

### 이 그림이 딛고 선 전제

- 커밋은 해시 대신 글자(`A` … `E`)로 부른다. 실제 git 은 커밋을 내용 · 부모 · 저자 · 시각 · 메시지로 셈한
  해시로 부르지만, 이 조각이 말하는 것은 이름이 옮겨 가는 모양이라 해시를 뺐다.
- 병합 커밋(부모가 둘인 커밋)은 없다.
- HEAD 는 늘 이름 하나를 가리킨다. HEAD 가 이름 없이 커밋을 곧바로 가리키는 상태(detached HEAD)는 다루지 않는다.
