# 결정이 갈렸다고 조건이 갈랐다는 뜻은 아니다

`if age >= 18 and hasTicket` 한 줄에는 결정이 하나, 조건이 둘 있다. 분기 커버리지는 결정이 참으로도
거짓으로도 나왔는지만 본다. 변형 조건 · 결정 커버리지(MC/DC, Modified Condition/Decision Coverage)는 한 걸음 더 묻는다 — **각 조건이 혼자서
결정을 뒤집을 수 있음을 시험으로 보였는가.**

{facet:whichConditionDecided}

## 짝이 무엇인가

조건 C 의 짝은 두 시험이다. C 의 값만 다르고, 다른 조건의 값은 모두 같고, 결정이 다르다. 다른 것이
C 하나뿐인데 결정이 뒤집혔으니 뒤집은 것은 C 다. 그런 짝이 있으면 C 가 결정을 **갈랐다**고 확인된다.

| 시험 | 입력 | A `age >= 18` | B `hasTicket` | 결정 |
| --- | --- | --- | --- | --- |
| T1 | `(20, true)` | `true` | `true` | `true` |
| T2 | `(15, true)` | `false` | `true` | `false` |
| T3 | `(20, false)` | `true` | `false` | `false` |

## 일곱 걸음

처음 화면(걸음 0)에는 코드와 아직 돌리지 않은 시험 셋이 있다.

1. T1 을 돌린다 — 결정 `true`. 결정 결과 1/2.
2. T2 를 돌린다 — 결정 `false`. 결정 결과 2/2 — 분기 커버리지는 여기서 이미 찼다.
3. A 의 짝을 찾는다. T1 · T2 는 A 만 다르고 결정이 뒤집힌다 — A 가름 확인 1/2.
4. B 의 짝을 찾는다. 돌린 두 시험은 B 가 모두 `true` 라 짝이 없다. 결정은 양쪽이 다 나왔는데도 B 가
   결정을 가를 수 있는지는 아직 아무 시험도 보이지 않았다.
5. T3 을 돌린다 — 결정 `false`.
6. B 의 짝을 다시 찾는다. T1 · T3 은 B 만 다르고 결정이 뒤집힌다 — B 가름 확인 2/2.

끝에는 조건 둘 모두 가름이 확인되고, 시험은 셋이 들었다. 참 · 거짓 네 조합 가운데 `(false, false)`
는 쓰이지 않는다 — 두 조건을 다 확인하는 데 필요하지 않다.

## 셈법에 대해

- 조건값은 **입력이 정한다.** `and` 는 앞 조건이 거짓이면 뒤 조건을 읽지 않는다(단락 평가). T2 에서
  `hasTicket` 은 실제로 읽히지 않지만, 이 그림은 입력이 준 값 `true` 를 B 의 값으로 둔다. 실제 도구 가운데는
  단락 평가로 읽히지 않은 조건을 "상관없음" 으로 두고 짝을 더 너그럽게 찾는 변형도 있다.
- 짝이 여럿이면 돌린 차례로 앞선 짝 하나만 보인다.
- 조건 둘 · 결정 하나인 경우만 다룬다. 조건이 늘 때 시험이 몇 개 드는가는 이 그림이 말하지 않는다.
