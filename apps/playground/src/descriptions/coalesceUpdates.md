# 모아서 한 번에 그린다

처리기 하나가 상태를 세 번 쓴다: `left = 40`, `top = 20`, `left = 90`. 곧바로 세 번
그렸다면 그린 수는 셋이었을 것이다. 그러나 화면은 처리기가 끝날 때까지 처음 모습
그대로 있다가, 끝나는 순간 딱 한 번 그려진다.

## 쓰기는 모아 두는 자리에 쌓인다

`left = 40` 은 상태를 곧바로 바꾸지 않는다. 모아 두는 자리에 `{left: 40}` 로 들어가고,
그리기가 아직 걸려 있지 않았으니 하나를 건다. `top = 20` 이 오면 모아 둔 것에
`{left: 40, top: 20}` 로 더해지는데, 그리기는 이미 걸려 있어 더 걸지 않는다 — 걸어
둔 수는 늘 많아야 하나다.

## 같은 이름은 옛 값을 덮는다

`left = 90` 이 오면 모아 둔 자리의 `left` 가 40 에서 90 으로 **덮인다**. 40 은 화면에
한 번도 들어가지 못한 채 사라진다 — 처리기 안에서 같은 상태를 여러 번 쓰면 마지막
값만 살아남는다.

## 처리기가 끝나야 비로소 그린다

세 번째 쓰기까지도 화면은 `left 0 · top 0` 그대로다. 처리기가 끝나는 순간 모아 둔
`{left: 90, top: 20}` 이 한 번에 상태로 들어가고, 그리기가 한 번 일어난다. 쓰기는
셋이었지만 그린 수는 하나다.

## 이 그림이 세운 전제

- **그리기(render)와 칠하기(paint)를 가른다.** "그린다" 는 뷰를 다시 셈해 실제
  트리에 반영하는 일이다. 브라우저가 화면을 실제로 칠하는 일은 이 조각의 주장 밖이다.
- **모아 둔 그리기가 정확히 언제 불리는지는 그리지 않는다.** 마이크로태스크로
  터지는지, 다음 프레임에 터지는지는 실제 라이브러리마다 다르다 — React 는 이벤트
  처리기 동안의 `setState` 를 모아 커밋 한 번으로 묶고, Vue 의 반응성 큐도 같은
  틀로 쓰기를 모았다가 한 번에 갱신한다. 이 조각은 "처리기가 끝난 뒤" 까지만
  말한다.
- **어느 값이 누구를 다시 그리는지(구독)는 말하지 않는다.** 뷰가 하나뿐이라 값과
  뷰를 잇는 줄은 이웃 조각 read-is-subscribe 의 몫이다.
