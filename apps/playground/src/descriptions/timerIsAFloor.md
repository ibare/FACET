{facet:timerIsAFloor}

`setTimeout(f, 0)` 은 "0ms 뒤에 부른다"는 뜻이 아니다. 0ms 는 **최소** 지연이지
약속이 아니다. 지연이 다 되면 타이머는 태스크 줄에 설 뿐이고, 실제로 불리는 것은
스택이 비고 그 줄의 차례가 왔을 때다.

이 조각의 다섯 줄은 그 벌어짐을 보여준다.

```js
function first()  { busyFor(4); }
function second() { busyFor(2); }
setTimeout(first, 0);
setTimeout(second, 5);
busyFor(9);
```

`first` 는 지연 0 을 청했지만 스크립트 자신이 9ms 동안 스택을 붙잡고 있어 9ms 뒤에야
불린다 — 늦음 9ms. `second` 는 지연 5 를 청했는데, 5ms 에 태스크 줄에 서고도 `first`
가 스택을 4ms 더 붙잡는 바람에 13ms 에야 불린다 — 늦음 8ms. 타이머는 스택 밖에서
독립적으로 시간을 재지만(스택이 바빠도 만기에는 줄에 선다), 태스크 줄에서 꺼내지는
것은 스택이 완전히 빈 뒤, 제 차례가 왔을 때뿐이다.

이 모형은 단순화다 — 태스크 줄을 하나로, 렌더를 이 조각의 시간 범위 밖으로 두었다.
중첩 타이머의 4ms 최소값(중첩 수준이 5 를 넘을 때 걸리는 규칙)은 이 데이터에는
걸리지 않는다.
