# 한 토큰 앞을 보고 갈래를 고른다

재귀 하강 파서는 문법 규칙마다 함수 하나를 두고, 규칙의 몸을 왼쪽부터 따라가며 토큰을 먹는다. 그런데
규칙에 갈래가 여럿이면 어느 몸을 따라갈지 먼저 정해야 한다. 되돌아가며 이것저것 해 볼 수도 있지만, LL(1)
파서는 **다음 토큰 하나를 들여다보고** 곧바로 정한다. 들여다보기만 하고 먹지는 않는다 — 먹는 일은 고른
갈래가 한다.

{facet:lookaheadOne}

## 입력과 문법

원시 프로그램은 세 줄이다.

```
let n = 5
show n
n = 6
```

이미 잘린 토큰 열은 아홉 개다 — `LET let` · `NAME n` · `OP =` · `NUM 5` · `SHOW show` · `NAME n` · `NAME n` ·
`OP =` · `NUM 6`. 줄바꿈은 토큰이 아니고, 파서는 열 끝에 입력 끝 표식 `EOF` 를 붙인다. 문법은 예로 만든
장난감 문법이다.

| 번호 | 규칙 |
| --- | --- |
| R1 | `Stmts → Stmt Stmts` |
| R2 | `Stmts → ε` |
| R3 | `Stmt → let NAME = NUM` |
| R4 | `Stmt → show NAME` |
| R5 | `Stmt → NAME = NUM` |

`NAME` · `NUM` 토큰은 종류 이름으로, 나머지는 원문 그대로 문법의 단말이 된다.

## 갈래가 받는 단말

갈래마다 **첫머리로 받을 수 있는 단말**을 미리 셈해 둔다. 몸의 첫 기호가 단말이면 그 단말이고, 비단말이면
그 비단말이 시작할 수 있는 단말 전부(FIRST)다. 몸이 비어 있으면(ε) 그 갈래는 아무것도 먹지 않으니, 왼쪽
비단말 **뒤에 올 수 있는** 단말(FOLLOW)을 받는다.

| 갈래 | 받는 단말 |
| --- | --- |
| R1 | `let` · `show` · `NAME` (FIRST(Stmt)) |
| R2 | `EOF` (FOLLOW(Stmts)) |
| R3 | `let` |
| R4 | `show` |
| R5 | `NAME` |

같은 비단말의 두 갈래가 같은 단말을 받지 않으니 한 토큰만 보면 언제나 하나로 정해진다. 이것이 LL(1) 의
1 이다. 두 갈래가 겹쳤다면 이 파서는 고를 수 없다.

## 걸음

걸음은 처음 화면을 넣어 **여덟**이다. 갈래가 둘 이상인 비단말에서 한 번 고르는 것이 한 걸음이고, 갈래가
하나뿐인 규칙 · 토큰 먹기 · 함수 부르기는 걸음이 아니다. 먹힌 토큰은 다음 걸음에서 가라앉은 칸으로 보인다.

| 걸음 | 고르는 비단말 | 들여다본 토큰 | 고른 갈래 |
| --- | --- | --- | --- |
| 0 | — | 시작, 읽는 자리 #0 | — |
| 1 | Stmts | #0 `LET let` | R1 |
| 2 | Stmt | #0 `LET let` | R3 |
| 3 | Stmts | #4 `SHOW show` | R1 |
| 4 | Stmt | #4 `SHOW show` | R4 |
| 5 | Stmts | #6 `NAME n` | R1 |
| 6 | Stmt | #6 `NAME n` | R5 |
| 7 | Stmts | #9 `EOF` | R2 (ε) |

걸음 1 과 2 는 **같은 토큰을 두 번** 들여다본다. `Stmts` 가 `let` 을 보고 R1 을 골랐지만 먹지 않았으니,
R1 의 첫 기호 `Stmt` 가 같은 `let` 을 다시 보고 R3 을 고른다. 먹는 것은 R3 의 몸이다.

마지막 걸음에서 `Stmts` 는 입력 끝 `EOF` 를 보고 빈 갈래 R2 로 간다 — 문장 목록이 거기서 끝난다.
고르기는 일곱 번, 먹은 토큰은 아홉 개다. 들여다본 수와 먹은 수가 다르다는 것이 들여다보기가 먹기와
다른 일이라는 뜻이다.
