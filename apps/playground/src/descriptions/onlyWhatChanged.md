
## 아래가 그대로면 다시 세우지 않는다

작은 도구 하나가 대상 일곱으로 이루어져 있다. 소스 넷이 각자 목적 파일(`.o`)이 되고, 목적 파일
둘씩이 묶음(`front.a` · `back.a`)이 되고, 두 묶음이 `tool` 이 된다. 지난번 빌드 결과가 일곱 모두
남아 있는 채로 `emit.c` 하나를 고쳤다. 다시 빌드하면 무엇을 다시 세우는가.

{facet:onlyWhatChanged}

빌드는 대상을 **입력이 모두 앞에 오는 차례**로 하나씩 들여다본다. 여럿이 가능하면 규칙에 적힌
차례가 앞선 것을 먼저 본다 — 그래서 `lex.o · parse.o · check.o · emit.o · front.a · back.a · tool`
이다. 대상마다 묻는 것은 하나다. **입력 가운데 바뀐 것이 있는가.**

- 없으면 지난번 결과를 그대로 두고 지나간다. 틀이 그 대상 위로 뛰어 건널 뿐 대상은 손대지 않는다.
- 있으면 다시 세운다. 다시 세운 대상은 이제 그 위 대상에게 **바뀐 입력**이 된다.

### 걸음 아홉

처음 화면(지난번 결과 일곱)을 넣어 아홉 걸음이다.

| 걸음 | 일어나는 일 |
|---|---|
| 0 | 지난번 결과 일곱 |
| 1 | `emit.c` 를 고친다 |
| 2 · 3 · 4 | `lex.o` · `parse.o` · `check.o` 그대로 |
| 5 | `emit.o` 다시 — 바뀐 입력 `emit.c` |
| 6 | `front.a` 그대로 — 두 입력 모두 그대로다 |
| 7 | `back.a` 다시 — 바뀐 입력 `emit.o` |
| 8 | `tool` 다시 — 바뀐 입력 `back.a` |

끝에 남는 것은 **다시 세움 3, 그대로 4** 다. 고친 곳에서 꼭대기까지 좁은 한 줄
(`emit.o → back.a → tool`)만 다시 서고, 나머지 넷은 지난번 결과를 그대로 쓴다. `check.o` 는
`back.a` 의 입력이지만 제 입력인 `check.c` 가 그대로라 다시 세우지 않는다 — 위가 다시 선다고 아래가
따라 서지는 않는다. 바뀜은 **위로만** 전해진다.

### 이 그림이 딛고 선 전제

- **무엇이 고쳐졌는지는 주어진다.** 도구가 그것을 어떻게 알아내는지 — 파일의 시각을 견주는지,
  내용의 지문을 견주는지 — 는 이 조각이 다루지 않는다. 그 갈림은 따로 볼 문제다.
- **다시 세운 결과가 우연히 지난번과 같아도 위는 멈추지 않는다.** 실제 도구 가운데는 다시 세운
  출력이 같으면 거기서 전파를 끊는 것도 있다(조기 차단). 이 모형은 make 처럼 "다시 세웠으면 바뀐
  것" 으로 친다.
- 대상의 출력 내용은 그리지 않는다. 판정에 쓰이는 것은 입력이 바뀌었는가 하나뿐이다.
