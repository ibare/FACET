## 돌 준비가 된 프로세스는 어디서 기다렸다가 언제 오르는가

CPU 는 하나뿐이다. 돌 준비가 된 프로세스가 여럿이면 하나만 CPU 에 오르고 나머지는 **준비 큐**라는 줄에 서서
기다린다. 줄 맨 앞이 빠져 오르는 때는 단 하나, **CPU 가 비는 그 순간**이다.

### 줄은 CPU 가 찰 때 길어지고, 빌 때만 줄어든다

위 칸이 CPU 자리, 아래 칸이 준비 큐다. 오른쪽 아래 점선 칩은 아직 오지 않은 프로세스이고, 도착하면 줄 끝으로
걸어 들어온다. 네 프로세스가 온다 — P1 은 틱 0 에 도착해 3 틱을 쓰고, P2 는 틱 1 에 2 틱, P3 는 틱 2 에 4 틱,
P4 는 틱 6 에 1 틱.

- 틱 0 에 P1 이 오면 줄도 CPU 도 비어 있어 줄에 서지 않고 곧장 오른다
- 틱 1 · 2 에 P2 · P3 이 오지만 CPU 는 P1 이 쓰고 있다. 둘은 줄 끝에 차례로 서고, 줄은 길이 2 까지 늘어난다
- 틱 3 에 P1 이 끝나 CPU 가 비는 **바로 그 걸음에** 줄 맨 앞의 P2 가 위로 빠져 오르고 P3 이 한 칸 당겨진다
- 틱 5 에 P2 가 끝나고 P3 이 오른다. 줄이 빈다
- 틱 6 에 P4 가 오지만 P3 이 아직 돌고 있어 빈 줄의 끝(곧 맨 앞)에 선다
- 틱 9 에 P3 이 끝나고 P4 가 오르며, 틱 10 에 P4 가 끝나면 줄도 CPU 도 빈다

시작 화면 하나와 줄이나 CPU 자리가 바뀐 틱 경계 여덟, 모두 9 걸음이다. 오른 차례는 P1 · P2 · P3 · P4 로 도착 차례와
같다 — 줄 맨 앞을 고르는 정책(먼저 온 것 먼저, FCFS)이라서다. CPU 가 차 있는 동안 도착은 줄을 늘리기만 하고,
누구도 줄 중간에서 빠지거나 끼어들지 않는다.

### 전제

- 시각의 단위는 틱이다. 한 틱을 돈다는 것은 틱 t 에서 t+1 까지 CPU 를 쓰는 것이다. 틱 수는 차례를 정하는 데만 쓰고,
  시간 축은 그리지 않았다 — 언제 시작하는지, 얼마나 기다렸는지는 이 조각의 말이 아니다.
- CPU 는 하나, 입출력은 없고, 프로세스를 바꾸는 데 드는 시간은 0 으로 쳤다.
- 한 틱 경계에서 여러 일이 겹치면 **끝이 먼저**, 그다음 도착이 줄 끝에 서고, 그다음 CPU 가 비었으면 줄 맨 앞이 오른다.
  그래서 끝난 자리에 같은 틱의 도착이 곧바로 오를 수 있다. 같은 틱에 도착한 것끼리는 목록 차례로 선다.
- 한 번 오른 프로세스는 끝까지 돈다(선점 없음). 몫을 정해 돌려 세우는 방식은 다른 조각이 다룬다.
