## 컴파일러는 실행하기 전에 무엇을 미리 셈해 둘 수 있는가

`60 * 60 * 1000` 은 프로그램을 몇 번 돌리든 늘 3600000 이다. 그렇다면 그 곱셈을 실행할 때마다 다시 할 까닭이
없다. 컴파일러가 한 번 셈해 두고 코드에 수를 박아 두면 된다. 이것이 상수 폴딩이다. 그런데 `n` 이 끼면 사정이
달라진다 — `n` 은 부를 때마다 다른 값이 들어오니 컴파일 때는 알 수 없다. 컴파일러는 어디까지 셈하고 어디서
멈출까.

{facet:foldAtCompile}

### 식은 나무다

화면의 네 줄은 함수 하나다.

```
function timeout(n)
    let ms = 60 * 60 * 1000
    let tries = (2 + 3) * 4 - n
    return ms * tries
```

식 아래의 받침 하나가 연산 마디 하나다. 받침이 덮는 칸이 그 마디가 셈하는 식이고, 가운데의 짧은 기둥이 그 마디의
연산 기호를 가리킨다. 곱이 더하기 · 빼기보다 먼저 묶이고 같은 높이는 왼쪽부터 묶이므로, `60 * 60 * 1000` 은
`(60 * 60) * 1000` 이고 `(2 + 3) * 4 - n` 은 `((2 + 3) * 4) - n` 이다. 안쪽 마디일수록 받침이 글자에 가깝다.

### 안에서부터 접는다

컴파일러는 줄을 위에서 아래로, 한 줄의 식 안은 가장 안쪽 마디부터 본다 (왼쪽 자식 → 오른쪽 자식 → 자기).
마디의 두 자식이 다 수이면 그 자리에서 셈해 수 하나로 바꾼다. 화면에서 두 수와 기호가 가운데로 모여 오그라들고,
셈한 수가 노랑 바탕으로 돋아난다. 그 수는 한 층 바깥 마디의 자식이 되어, 바깥 마디도 두 자식이 다 수가 될 수 있다.

- L2 — `60 * 60` 이 3600 으로, 이어서 `3600 * 1000` 이 3600000 으로 접힌다. 식 전체가 수 하나가 된다.
- L3 — `2 + 3` 이 5 로 (괄호도 함께 사라진다), `5 * 4` 가 20 으로 접힌다. 그다음 `20 - n` 은 오른쪽이 이름이라
  접지 못한다.

한쪽이라도 수가 아니면 마디는 그대로 남는다. 두 쪽이 안으로 당겨졌다가 되돌아가고, 막은 쪽에 테두리가 선다. 그 마디가
수가 되지 못했으니 그 위의 마디에게도 한쪽이 수가 아니다 — 이름이 걸린 자리에서 접힘이 위로 번지지 않는다.

- L4 — `ms * tries` 는 양쪽이 다 이름이라 그대로다.

걸음은 처음 화면(걸음 0)을 넣어 일곱이다. 연산 마디 여섯을 하나씩 보고, 넷을 접고 둘을 그대로 둔다. 줄은 하나도
없어지지 않는다. 한 번 부를 때 실행 중에 셈하는 연산은 여섯에서 둘(`20 - n` · `ms * tries`)로 준다. 접은 뒤의
함수는 이렇다.

```
function timeout(n)
    let ms = 3600000
    let tries = 20 - n
    return ms * tries
```

앞뒤 함수는 `n` 이 무엇이든 같은 값을 돌려준다 (`n` 이 3 이면 둘 다 61200000).

### 폴딩의 둘레 — 상수 전파는 하지 않는다

L4 의 `ms` 는 바로 위 줄에서 3600000 으로 정해졌다. 그래도 이 조각의 컴파일러는 `ms * tries` 를 건드리지 않는다.
폴딩은 **식 안에 적힌 수**만 보기 때문이다. 이름이 가리키는 값을 그 자리에 바꿔 넣는 것은 상수 전파라는 다른
변환이다. 상수 전파를 곁들이면 `ms` 가 3600000 으로 바뀌어 L4 는 `3600000 * tries` 가 되지만, `tries` 가 `n` 에
매여 있어 거기서도 곱셈은 남는다. 실제 컴파일러는 폴딩과 전파, 쓰이지 않는 줄 지우기 같은 변환을 여러 번 섞어
돌린다. 이 조각은 그 가운데 폴딩 한 가지를 한 번 돌린 모습이다.
