
# 스택이 비어야 다음이 들어온다

```
function a() { b(); }
function b() { c(); }
function c() { setTimeout(done, 0); }
function done() {}
a();
```

`setTimeout(done, 0)` 은 "지금 당장"을 청하는 것처럼 보인다. 하지만 `done` 은
그 자리에서 스택에 올라오지 않는다. `c` 가 아직 스택 위에 있고, `c` 를 부른 `b` 도,
`b` 를 부른 `a` 도, `a` 를 부른 스크립트도 아직 스택 위에 있다. `done` 은 스택이
아니라 **태스크 줄**로 간다.

## 부름은 쌓이고, 맡김은 줄을 선다

`a()` 가 불리면 스크립트 프레임 위에 `a` 가 한 겹 올라간다. `a` 안에서 `b()` 를
부르면 그 위에 `b` 가, `b` 안에서 `c()` 를 부르면 그 위에 `c` 가 올라간다. 넷째
겹까지 쌓인 채로 `c` 가 `setTimeout(done, 0)` 을 부르면, `done` 은 스택 위에
다섯째 겹으로 올라가는 대신 태스크 줄 맨 뒤에 가서 **가만히** 선다.

그러고 나서 `c` 가 끝나 걷히고, `b` 가 끝나 걷히고, `a` 가 끝나 걷히고, 스크립트가
끝나 걷힌다. 이 네 걸음 동안 `done` 은 태스크 줄에서 움직이지 않는다. 지연을 0 으로
청했다고 해서 순서를 새치기하지 않는다.

## 빈 스택이 문을 연다

스택이 완전히 비고 나서야 이벤트 루프가 태스크 줄의 맨 앞을 본다. 거기 `done` 이
있다. 이제야 `done` 이 스택으로 옮겨 오는데, 그 자리는 **맨 아래**다 — 비어 있던
스택에 처음 올라오는 겹이기 때문이다. `done` 은 곧바로 실행되어 걷힌다.

그래서 걸음 열둘의 차례는 이렇다. 스택이 [] · [script] · [script,a] ·
[script,a,b] · [script,a,b,c] 로 자라는 동안 태스크 줄은 비어 있다가 `done` 하나가
서고, 스택이 [script,a,b] · [script,a] · [script] · [] 로 줄어드는 동안 태스크
줄의 `done` 은 그대로다. 스택이 빈 다음에야 `done` 이 [done] 으로 들어와 곧 []
이 된다.

## 이 그림이 세운 전제

- `setTimeout` 호출 자체는 프레임으로 쌓지 않는다 — 브라우저 API 호출은 0 ms 라고
  본다 (모형 단순화). 실제로도 `setTimeout` 을 부르는 데 걸리는 시간은 무시할
  수준이다.
- 이 그림은 **차례**만 말한다. 지연을 몇 ms 로 청했는지, 실제로 몇 ms 뒤에 불렸는지는
  {facet:timerIsAFloor} 의 말이다 — 그 조각은 스택의 겹을 그리지 않고 청한 시각과
  실제 시각의 벌어짐만 그린다.
- 부른 함수가 값을 들고 돌아오는 이야기, 스택이 걷히며 값이 호출자에게 전해지는
  것은 이 그림의 소재가 아니다. `done` 은 아무것도 돌려주지 않는다.
- 이 스크립트에는 마이크로태스크(프로미스)가 없다. 태스크 줄과 마이크로태스크 줄이
  함께 나오는 그림은 {facet:microtaskCutsIn} 이 다룬다.
- 태스크 줄은 하나로 두었다(실제 브라우저는 줄이 여럿이고 우선순위가 있다). 이
  단순화는 이 서브도메인의 다른 조각에도 같다.
