## 값 전달과 참조 전달 — 건너가는 것이 다르다

함수를 부르면 인자 자리에 무언가가 들어간다. 그것이 **값의 복사본**일 수도 있고, 부른 쪽 **변수의 자리 그 자체**일 수도 있다. 두 함수 `bump` 와 `bumpRef` 는 몸이 글자까지 같다 — `n = n + 1`. 다른 것은 머리줄의 `ref` 하나다.

{facet:passByValueVsReference}

### 무엇을 보나

- 왼쪽이 프로그램이고 오른쪽 위 "바깥" 칸에 `a` 와 `b` 의 자리가 선다. 둘 다 처음 값은 `5` 다.
- `bump(a)` 를 부르는 순간 `a` 의 자리에서 값 조각이 하나 떨어져 나와 아래로 내려간다. 내려간 곳은 `bump` 의 틀 안에 **새로 선** 자리 `n` 이다. `a` 의 자리는 제 값을 그대로 쥐고 있다.
- 몸의 `n = n + 1` 은 틀 안의 그 새 자리만 `6` 으로 바꾼다. 돌아오면 틀이 접혀 걷히고, `6` 을 담았던 복사본도 함께 사라진다. 점선으로 남는 것은 그 자리가 있었다는 흔적뿐이다.
- `bumpRef(b)` 를 부르는 순간에는 아무것도 내려가지 않는다. 대신 틀의 이름표 `n` 이 **위로 올라가 `b` 의 자리에 붙는다.** 틀 안에는 새 자리가 서지 않는다.
- 같은 몸 `n = n + 1` 이 이번에는 바깥 칸에서 일어난다 — `n` 이 가리키는 곳이 곧 `b` 의 자리라, `b` 가 곧장 `6` 이 된다. 돌아오면 이름표만 떨어져 틀로 돌아가고 `b` 의 자리에는 `6` 이 남는다.
- 마지막 두 줄이 `a` 와 `b` 를 출력한다 — `5` 와 `6`.

### 요점

- 값 전달에서 피호출 쪽이 받는 것은 **새 자리와 그 안의 복사본**이다. 안에서 무엇을 넣어도 부른 쪽 변수에는 닿지 않는다.
- 참조 전달에서는 새 자리가 서지 않는다. 인자 이름이 부른 쪽 변수의 자리에 **이름을 하나 더 붙일** 뿐이라, 안에서 넣으면 곧 부른 쪽 변수가 바뀐다.
- 화면의 `ref` 는 이 조각의 표기다. 실제 언어마다 적는 법이 다르다 — C# 은 인자 앞에 `ref` 를 붙이고(부르는 쪽에도 `ref` 를 적는다), C++ 는 인자 타입 뒤에 `&` 를 붙인다. 자바와 파이썬에는 변수의 자리를 넘기는 방법이 없다 — 늘 값(객체라면 그 객체를 가리키는 값)이 복사되어 건너간다.

### 걸음

줄 하나를 밟으면 한 걸음이고, 부르기는 부름 걸음과 돌아옴 걸음이 하나씩이다. 시작 · `let a = 5` · `let b = 5` · `bump(a)` 부름 · 몸의 `n = n + 1` · 돌아옴 · `bumpRef(b)` 부름 · 몸의 `n = n + 1` · 돌아옴 · `show a` · `show b` — 모두 열한 걸음이다. 인자 자리가 새로 선 부르기가 하나(`bump`), 새로 서지 않은 부르기가 하나(`bumpRef`)이고, 끝에 `a` 는 `5`, `b` 는 `6` 이다.
