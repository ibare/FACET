
# 그리기 직전에

소켓에서 값이 쉴 새 없이 들어오는데 화면은 1 초에 예순 번만 바뀐다. 값이 들어올 때마다
그리면 대부분은 화면에 나오기도 전에 다음 그리기에 덮인다. 그래서 흔히 이렇게 쓴다.

```js
let latest = 0;
socket.onmessage = (e) => { latest = e.data; };
function draw() {
  box.textContent = latest;
  requestAnimationFrame(draw);
}
requestAnimationFrame(draw);
```

메시지 처리는 값 하나를 **덮어쓰기만** 하고, 그리기는 `requestAnimationFrame` 에 맡긴다.
그러면 `draw` 는 몇 번, 언제 불릴까.

{facet:justBeforePaint}

## 모였다가 한 번

박자 1 (16.7 ms) 전에 메시지가 셋 온다. `latest` 는 5, 8, 6 으로 세 번 바뀌지만 `draw` 호출
수는 0 그대로다. 박자가 오면 `draw` 가 **한 번** 불려 그 순간의 값 6 을 `box` 에 넣고, 곧바로
스타일 · 레이아웃 · 페인트가 뒤따라 화면에 6 이 나온다. 5 와 8 은 화면에 한 번도 나오지 않는다.

박자 2 (33.3 ms) 앞에는 메시지가 둘(9, 4), 박자 3 (50.0 ms) 앞에는 하나(7)다. 모인 수는 달라도
박자마다 `draw` 는 한 번씩 불린다. 끝에 세면 메시지 6 · `draw` 호출 3 · 페인트 3 이고, 화면에
나온 값은 6 · 4 · 7, 한 번도 안 나온 값은 5 · 8 · 9 다.

## 다시 건 요청은 다음 박자로

`draw` 는 안에서 `requestAnimationFrame(draw)` 를 또 부른다. 그런데 같은 박자에 두 번 불리지 않는
것은 브라우저가 박자의 렌더링 단계에 들어설 때 **걸려 있던 콜백 목록을 그 순간 떠 두고** 그
목록만 부르기 때문이다 (HTML 표준의 동작). 콜백 안에서 새로 건 요청은 떠 둔 목록에 없으니 다음
박자를 기다린다. 화면 오른쪽 아래 "걸린 콜백" 칸에서 `draw` 가 박자 하나씩 밀려 가는 것이 그것이다.

그리고 그 부름이 스타일 · 레이아웃 · 페인트의 **바로 앞**이라, 콜백에서 바꾼 값이 같은 박자의
화면에 실린다. 제목의 "그리기 직전에" 는 이 차례를 가리킨다.

## 이 그림이 세운 전제

- 화면은 60 Hz 다. 박자 k 의 시각은 k × 1000 / 60 ms 이고, 끝까지 셈한 뒤 표시할 때만 소수 첫째
  자리로 반올림한다.
- 메시지 여섯의 도착 시각(4 · 9 · 13 · 22 · 29 · 44 ms)과 값은 예로 정한 것이다. 박자 시각과 겹치는
  메시지는 없다.
- 메시지 처리는 도착한 그 시각에 0 ms 로 끝난다고 본다.
- 박자 안의 차례는 콜백 → 스타일 → 레이아웃 → 페인트 → 합성이다. 이 그림은 합성을 따로 그리지
  않고, 단계마다 걸리는 시간도 셈하지 않는다.
- 박자 1 부터 3 까지만 본다. 박자 3 의 `draw` 가 건 요청은 박자 4 를 기다린 채로 남는다.
- `setTimeout` · 마이크로태스크와의 차례는 이벤트 루프의 이야기라 여기서 다루지 않는다.
