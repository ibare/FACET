# 링커는 이름을 잇고 주소를 옮겨 적는다

링커는 오브젝트 파일 여럿을 받아 실행 파일 하나를 만든다. 하는 일은 둘이다. **해석** — 파일이 쓰기만 하고 정의하지
않은 이름(`U area`)을 다른 파일의 정의(`D area`)에 잇는다. **재배치** — 파일마다 0 부터 셌던 자리를 실제 주소로 옮기고,
명령 속 주소 칸(`@0` · `+0`)을 셈한 수로 고쳐 적는다. 두 일 모두 **파일을 읽는 차례**를 따른다. 그래서 차례를 바꾸면
링크가 깨지기도 하고, 깨지지 않아도 같은 칸의 수가 달라진다.

{facet:linker}

위 그림은 링커가 받은 파일 셋이고, 아래 코드 패널은 **그 파일들을 잇고 칸을 고치는 링커의 코드**다. 코드는 이름 · 파일을
글자가 아니라 번호로 받는다.

## 파일 셋

명령 하나는 4 바이트, 파일 안 자리는 제 절의 시작을 0 으로 센다.

| 파일 | 항목 | text | data |
| --- | --- | --- | --- |
| `main.o` | `D main` · `D count` · `U area` · `U width` | `+0 load r1, @0` (count, 절대) · `+4 call +0` (area, 상대) · `+8 store @0, r1` (width, 절대) · `+12 ret` | count 8 바이트 |
| `shape.o` | `D area` · `U square` | `+0 call +0` (square, 상대) · `+4 add r1, r1, r1` · `+8 ret` | — |
| `calc` | `D square` · `D width` | `+0 load r2, @0` (width, 절대) · `+4 mul r1, r1, r2` · `+8 ret` | width 4 바이트 |

`calc` 는 손잡이에 따라 오브젝트 `calc.o` 이거나 라이브러리 `libcalc.a` 다. text 절은 @1000 부터, data 절은 @2000 부터
놓는다. 이 두 주소와 명령 크기 4 바이트는 예로 정한 값이다.

## 규칙

- **해석** — 파일을 차례대로 읽는다. 파일 하나가 한 걸음이다. 파일 안에서는 `D` 항목을 먼저, 그다음 `U` 항목을 적힌 차례로
  본다. `D` 는 정의 표에 이름을 올리고, 그 이름을 기다리던 자리가 있으면 메운다. `U` 는 이미 정의가 있으면 곧바로 메우고,
  없으면 기다림 목록 끝에 선다. 같은 이름을 두 번 정의하면 링커가 멈춘다(이 자료에는 없다).
- **라이브러리** — 오브젝트는 늘 넣는다. 라이브러리는 **그 순간 기다리는 이름 가운데 자기가 정의하는 것이 하나라도 있을 때만**
  끌려온다. 없으면 건너뛰고, 다시 돌아가 보지 않는다. 한 번 훑는 링커의 규칙이다.
- **정의 없음** — 파일을 다 읽고도 기다림이 남으면 링크가 멈춘다. 놓기와 고치기는 하지 않는다.
- **놓기** — 넣은 파일 차례대로 text 절을 이어 붙이고, data 절도 따로 이어 붙인다.
- **고치기** — 심볼 주소 S 는 제 절이 놓인 자리 + 절 안 자리다. 고칠 명령의 주소를 P 라 하면 절대 칸은 S, 상대 칸은 S − P 다.
  상대 칸은 부호를 늘 붙인다(`+12` · `-28`).

## 손잡이

**링크 차례**는 파일 셋을 읽는 차례, **calc 의 꼴**은 calc 가 오브젝트인지 라이브러리인지다. 여섯 칸을 모두 셈하면 이렇다.

| 차례 | calc | 가장 긴 기다림 | 넣은 파일 | 고친 칸 |
| --- | --- | --- | --- | --- |
| main · shape · calc | 오브젝트 | 2 | 3 | main.o+0 `@2000` · main.o+4 `+12` · main.o+8 `@2008` · shape.o+0 `+12` · calc+0 `@2008` |
| main · shape · calc | 라이브러리 | 2 | 3 | 위와 같음 (끌려옴 — 기다림에 width · square) |
| calc · main · shape | 오브젝트 | 1 | 3 | calc+0 `@2000` · main.o+0 `@2004` · main.o+4 `+12` · main.o+8 `@2000` · shape.o+0 `-28` |
| calc · main · shape | 라이브러리 | 2 | 2 | 정의 없음 2 (width · square) — 링크 멈춤 |
| main · calc · shape | 오브젝트 | 2 | 3 | main.o+0 `@2000` · main.o+4 `+24` · main.o+8 `@2008` · calc+0 `@2008` · shape.o+0 `-12` |
| main · calc · shape | 라이브러리 | 2 | 3 | 위와 같음 (끌려옴 — 기다림에 width) |

- **깨지는 칸은 하나뿐이다.** calc 가 라이브러리이고 맨 앞에 서면, 그 순간 기다리는 이름이 없어 끌려오지 않는다. 뒤에 main.o 와
  shape.o 가 width · square 를 기다리지만 링커는 돌아가지 않는다. 오브젝트면 차례와 상관없이 다 메운다.
- **이웃으로 선 둘은 상대 칸이 그대로다.** `main.o+4`(area 를 부르는 칸)는 main · shape 가 이웃인 두 차례에서 모두 `+12` 다.
  둘이 함께 @1000 에서 @1012 로 옮겨 가도 둘 사이 거리는 변하지 않는다. calc 가 둘 사이에 끼면 `+24` 로 는다.
- **부르는 쪽이 뒤에 서면 음수가 된다.** `shape.o+0`(square 를 부르는 칸)은 `+12` · `-28` · `-12` 다.
- 절대 칸은 심볼의 새 주소 그대로라, 차례가 data 절의 자리를 바꾸면 따라 바뀐다 (`main.o+8` 은 `@2008` 과 `@2000`).

## 걸음

기본값(main · shape · calc, 라이브러리)은 처음 화면(걸음 0)을 넣어 열둘이다 — 해석 셋 · 놓기 셋 · 고치기 다섯.

| 걸음 | 하는 일 | 기다림 |
| --- | --- | --- |
| 0 | 시작 | — |
| 1 | main.o 읽음 — 정의 main · count | area · width |
| 2 | shape.o 읽음 — 정의 area, area 메움 | width · square |
| 3 | libcalc.a 끌려옴 — 정의 square · width, 둘 다 메움 | — |
| 4 ~ 6 | 놓기 main.o (text @1000~@1015 · data @2000~@2007) · shape.o (text @1016~@1027) · libcalc.a (text @1028~@1039 · data @2008~@2011) | — |
| 7 ~ 11 | 고치기 `load r1, @2000` · `call +12` · `store @2008, r1` · `call +12` · `load r2, @2008` | — |

깨지는 칸(calc · main · shape, 라이브러리)은 걸음 다섯이다 — libcalc.a 건너뜀 · main.o · shape.o · 정의 없음.

계기는 걸음마다 지금 값이다. **기다리는 이름**은 기다림 목록의 길이, **넣은 파일**은 지금까지 넣은 파일 수, **고친 칸**은
지금까지 고친 주소 칸 수다.

## 전제

- 명령 4 바이트 · 놓는 자리 @1000 · @2000 은 예로 정한 값이다.
- 실제 CPU 의 상대 주소는 대개 **다음 명령**에서 잰다 — 여기 셈에 −4 가 붙는다. 이 그림은 고칠 명령 자신의 주소에서 잰다.
- 한 번 훑는 링커의 규칙이다. 라이브러리를 다시 훑는 링커도 있고, 라이브러리 묶음을 되풀이해 훑게 하는 옵션도 따로 있다.
- 실제 링커는 이것 말고도 절 맞춤 · 약한 심볼 · 공유 라이브러리 같은 일을 더 한다. 여기서는 해석과 재배치를 한 차례로 보이는
  한 방식만 그렸다.
