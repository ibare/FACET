# 반복을 고치는 변환은 반복 횟수에 값을 건다

컴파일러가 반복을 고치는 흔한 변환이 둘 있다. **꺼내기**는 바퀴마다 같은 값을 내는 줄을 반복 앞으로 옮겨 한 번만
셈하게 하고, **펼치기**는 몸을 여러 벌 이어 붙여 조건 셈과 올림을 배수만큼 줄인다. 둘 다 "빨라진다" 로 알려져
있지만, 실제로 얼마를 아끼는지는 **반복이 몇 번 도는가**에 걸려 있다.

## 두 층

위 무대의 프로그램은 컴파일러가 **받은** 프로그램이고, 아래 코드 패널은 그 프로그램을 **고치는** 컴파일러의 코드다.
코드 패널의 `loopCost` 는 반복 몸의 줄을 번호 배열(줄마다 연산 수 · 넣는 이름 · 읽는 이름)로 받아, 불변 판정을 새 불변이
없을 때까지 되풀이하고 몇 바퀴 · 몇 벌 · 나머지 몇 벌인지로 줄마다 몇 번 셈하는지 센다. 무대가 보이는 세 수와 같은 값을 낸다.

```
function weigh(list, rate)
    let total = 0
    let i = 0
    while i < 10
        let w = rate * 2
        total = total + list[i] * w
        i = i + 1
    return total
```

`while i < 10` 의 10 이 반복 횟수 손잡이다 (0 · 1 · 4 · 10).

## 한 판의 걸음

한 판은 늘 원래 여덟 줄에서 출발한다. 차례는 **꺼내기 다음 펼치기**다 — 펼친 뒤에는 같은 줄이 몸에 여러 번 들어가
"한 번만 넣는다" 는 불변 조건에 걸리기 때문이다.

1. **판정** (꺼내기 켬) — 몸의 줄마다 넣는 이름을 몸에서 한 번만 넣는지, 읽는 이름이 몸에서 바뀌지 않는지 본다.
   `let w = rate * 2` 는 불변이고, `total = …` 은 `total` 과 `i` 를, `i = i + 1` 은 `i` 를 읽어 변한다.
2. **꺼냄** — 불변 줄이 몸에서 들려 나가 `while` 바로 위에 붙는다.
3. **벌 붙이기** (배수 F ≥ 2) — 일하는 줄이 한 벌씩 옆으로 펴진다. 화면의 "벌 2" 는 칸 읽기가 `list[i + 1]`,
   "벌 3" 은 `list[i + 2]` 다 — 벌 n 은 `list[i + n − 1]` 로 밀린다 (원래 줄이 벌 1).
4. **조건 · 올림 고치기** — 도는 바퀴가 N div F 번이 되도록 조건의 끝과 올림 폭이 고쳐 적힌다.
5. **나머지** — N mod F 벌이 반복 밖으로 떨어져 나와 `return` 앞에 곧은 줄로 붙는다.
6. **셈** — 실행 연산 · 반복 관리 · 코드 줄을 세고 오른쪽 두 막대가 원래 길이(점선)에서 새 길이로 옮겨 간다.

기본값(반복 10 · 배수 4 · 꺼내기 켬)에서 걸음은 처음 모습을 넣어 열이다.

## 세는 법

- **실행 연산** — 식 안의 연산 기호(`+ - * <`) 하나를 한 번으로 센다. `list[i + 1]` 의 `+` 도 센다. 곧은 줄은 한 번,
  조건은 (도는 바퀴 + 1) 번, 몸의 줄은 도는 바퀴만큼 셈한다.
- **반복 관리** — 조건 셈과 올림 셈을 더한 것. 실행 연산의 일부다 (막대 안의 다른 색).
- **코드 줄** — 머리줄과 `return` 을 넣은 줄 수.

## 무엇을 읽나

| 반복 | 꺼내기 끔 → 켬 (배수 1) |
| --- | --- |
| 0 | 실행 연산 1 → 2 |
| 1 | 6 → 6 |
| 4 | 21 → 18 |
| 10 | 51 → 42 |

꺼내기는 두 바퀴부터 이득이고, 한 바퀴면 본전이며, **한 번도 돌지 않으면 한 연산 손해다** — 꺼낸 줄은 반복이 돌든
말든 한 번 셈하기 때문이다. 반복 횟수를 0 으로 내리면 꺼내기 켬의 실행 막대가 원래 점선보다 길어진다.

반복 10 · 꺼내기 켬에서 배수를 1 · 2 · 4 로 올리면 두 저울눈이 반대로 움직인다 — 반복 관리는 21 · 11 · 5,
실행 연산은 42 · 37 · 33 으로 줄지만 코드 줄은 8 · 9 · 13 으로 는다. 벌마다 칸 읽기에 더하기가 하나씩 얹히므로 반복
관리가 준 만큼 실행 연산이 줄지는 않는다. 반복 1 에서 펼치면 반복이 한 번도 돌지 않고 나머지 한 벌이 일을 한다.

## 전제

- 이것은 컴파일러가 이렇게 한다는 **한 방식**이다. 실제 컴파일러는 패스를 여러 번 섞어 돌리고 비용 모형도 더 크다.
- 연산 하나 = 식의 연산 기호 하나로 친 비용이다. 실제 CPU 는 칸 읽기의 더하기를 주소 계산에 흡수하기도 한다.
- 반복 횟수를 컴파일할 때 아는 반복이라 나머지를 곧은 줄로 뒤에 붙였다. 모르면 나머지를 도는 반복이 따로 필요하다.
- 한 번도 돌지 않는 반복에서 꺼낸 줄은 값이 달라지지 않아도 연산을 한 번 치른다. 부작용이 있는 줄이면 꺼내면 안 된다
  (이 프로그램에는 없다).
- 배수 4 는 예로 정한 값이다. 동률을 가를 자리는 없다 — 판정은 줄마다 참 · 거짓이고 셈은 정수 더하기뿐이다.
