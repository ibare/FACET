## 두 번 돌려주면 한 칸이 두 번 나간다

`free(a)` 는 빌린 칸을 할당기에 돌려주는 줄이다. 돌려받은 덩이는 **빈 자리 목록**에 오르고, 다음
`allocate` 가 그 목록에서 꺼내 다시 내준다. 그런데 같은 칸을 두 번 돌려주면 목록에 같은 칸이 **두 번**
오른다. 목록은 그것이 같은 칸인 줄 모르고, 뒤따르는 빌림 둘에게 차례로 한 번씩 내준다.

{facet:doubleFree}

### 목록에 두 번 오른다

첫 줄 `let a = allocate(1)` 은 목록이 비어 있어 새 땅에서 칸 `100` 을 떼어 a 에게 준다. 새 땅의 시작은
`101` 로 밀린다. 둘째 줄 `free(a)` 가 `100` 을 목록 맨 앞에 올리고, 셋째 줄 `free(a)` 가 **또** 올린다.
a 의 자리에는 여전히 `100` 이 들어 있으니 두 번째 부르기도 같은 주소를 넘긴다. 목록은 `[100, 100]` 이 된다.

### 한 칸을 두 이름이 받는다

넷째 줄 `let b = allocate(1)` 은 목록 맨 앞의 `100` 을 꺼내 b 에게 준다. 다섯째 줄 `let c = allocate(1)`
도 목록에서 꺼낸다 — 남아 있던 것이 또 `100` 이다. 이제 b 와 c 는 **같은 칸**을 제 것이라 믿는다. 새 땅의
시작은 끝까지 `101` 그대로다. 빌림은 셋이었지만 새 땅에서 쓰인 칸은 `100` 하나뿐이다.

### 덮이고, 엉뚱한 값이 나온다

여섯째 줄 `valueAt(b) = 5` 가 칸 `100` 에 5 를 넣고, 일곱째 줄 `valueAt(c) = 9` 가 같은 칸에 9 를 넣어 5 를
덮는다. 마지막 줄 `show valueAt(b)` 는 b 가 넣은 5 를 기대하지만 출력은 `9` 다. b 에게는 아무 일도 하지
않았는데 b 가 가리키는 칸의 값이 바뀌었다. 실제 프로그램에서는 이 칸이 서로 다른 두 자료 구조의 일부가 되어, 한쪽을
고치면 다른 쪽이 조용히 망가진다. 할당기 자신이 쓰는 장부를 덮어 더 큰 사고로 번지기도 한다.

그림은 모두 아홉 걸음이다 — 시작 하나와 줄 여덟.

### 이 그림의 모형

- 주소 `100` (힙) 과 `500` · `501` · `502` (스택) 는 흐름을 보이려고 **예로 정한 값**이다. 실제 주소가
  아니며, 실제 스택은 대개 아래로 자란다. 이 그림은 방향을 말하지 않는다.
- 이 할당기는 **검사하지 않는 장난감**이다. 돌려받은 덩이가 이미 목록에 있는지 보지 않고 그대로 올린다.
  실제 할당기의 다수는 이런 이중 해제를 알아채 프로그램을 멈춘다. 알아채지 못하는 경우에 일어나는 일이
  바로 이 그림이다.
- `allocate(n)` 은 목록을 앞에서부터 보아 칸 수가 n 인 첫 덩이를 꺼내고, 없으면 새 땅에서 떼어 준다.
  `free(p)` 는 p 에서 시작하는 덩이를 목록 맨 앞에 넣을 뿐, 칸의 내용도 이름 칸의 주소도 지우지 않는다.
- 코드는 어느 언어도 아닌 읽히는 표기다. `allocate` · `free` · `valueAt` 은 C 의 `malloc` · `free` · `*p`
  자리에 해당한다.
