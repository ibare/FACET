# 고친 쪽의 줄을 그대로 쓴다

같은 파일을 두 사람이 나눠 고쳤다. 한 사람(우리 쪽, ours)은 요금과 마지막 호출을, 다른 사람(그쪽, theirs)은
계산식 한 줄을 고쳤다. 둘이 손댄 자리가 서로 다르다면 병합된 파일은 무엇으로 채워질까. 어느 한쪽의 사본을 고르는
것이 아니라, **줄 덩이마다 한 쪽에서 줄을 옮겨 담아** 새 파일을 세운다.

{facet:oneSideChanged}

## 덩이 하나씩 채워진다

그림 위에는 세 벌이 나란하다 — 가운데가 두 사람이 갈라지기 전의 조상(base), 왼쪽이 우리 쪽, 오른쪽이 그쪽이다.
아래의 병합 결과는 처음에 비어 있고, 걸음마다 한 덩이씩 위에서부터 채워진다. 덩이마다 어느 쪽의 줄이 옮겨 가는지는
정해져 있다.

- 아무도 고치지 않은 덩이 — 조상의 줄이 옮겨 간다 (세 벌 모두 같은 줄이다)
- 한쪽만 고친 덩이 — **고친 쪽의 줄**이 옮겨 간다. 다른 쪽은 조상과 같으니 옛 줄을 지키려는 뜻이 없다

이 파일에서는 여섯 줄이 여섯 덩이가 된다.

1. 조상 1 줄 `let rate = 2` — 아무도 안 고쳤다 → 조상의 줄
2. 조상 2 줄 — 우리 쪽만 고쳤다 → 우리 쪽의 `let fee = 7`
3. 조상 3 줄 `function cost(n)` — 아무도 안 고쳤다 → 조상의 줄
4. 조상 4 줄 — 그쪽만 고쳤다 → 그쪽의 `    let c = n + rate`
5. 조상 5 줄 `    return c + fee` — 아무도 안 고쳤다 → 조상의 줄
6. 조상 6 줄 — 우리 쪽만 고쳤다 → 우리 쪽의 `show cost(4)`

그림은 처음 화면(세 벌과 빈 결과)을 넣어 일곱 걸음이다. 다 채운 결과는 여섯 줄이고, 조상 그대로가 셋, 우리 쪽에서
둘, 그쪽에서 하나, 충돌은 없다. 결과 파일 한 벌 안에 우리 쪽의 고침 둘과 그쪽의 고침 하나가 함께 들어 있다 — 어느
쪽의 사본도 아니다.

## 덩이는 어떻게 나뉘나

조상을 기준으로 조상 → 우리 쪽, 조상 → 그쪽을 각각 줄 단위로 견준다. 줄 비교는 글자 그대로다 — 앞의 빈칸(들여쓰기)도
줄의 글자이고, 비슷한 줄을 "바뀐 줄" 로 짝 짓지 않는다. 두 견줌 **모두에서** 그대로 남은 조상의 줄이 안정 줄이고,
안정 줄 사이에 낀 세 쪽의 조각이 한 덩이가 된다. 이것이 diff3 의 덩이 나누기다.

덩이를 판정할 때 조상이 기준이 된다. 두 쪽이 모두 조상과 같으면 아무도 안 고친 것이고, 한쪽만 조상과 다르면 그쪽이
고친 것이다. 두 사람이 **같은 자리를 서로 다르게** 고쳤다면 어느 한쪽을 고를 근거가 없어 충돌이 된다 — 이 그림의
데이터에는 그런 덩이가 없다.

## 전제

- 이 그림의 덩이 나누기는 git 의 병합(xdiff)을 단순화한 모형이다. git 은 서로 붙어 있는 두 고침도 충돌로 보는 등 세부가
  다르다. 여기서는 고친 줄이 안정 줄 하나씩을 사이에 두고 떨어져 있다
- 쪽 이름 ours · theirs 는 git 이 병합할 때 쓰는 이름이다 — 지금 서 있는 브랜치가 ours, 합쳐 들이는 브랜치가 theirs 다
- 파일의 줄은 어느 언어도 아닌 읽히는 표기다
