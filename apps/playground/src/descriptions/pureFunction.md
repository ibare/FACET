## 순수와 차례

"같은 입력이면 같은 출력" 을 **차례를 바꿔** 시험한다. 원본 목록 `[3, 6, 2]` 에 같은 셈 `change(slot, mul, add)` 를
세 번 부른다 — A 는 칸 0 에 5 를 더하고, B 는 칸 0 에 4 를 곱하고, C 는 칸 1 에 10 을 더한다. 부르기마다 **바뀐 목록의 합**을
돌려준다.

받은 목록을 **고치면** 앞 부르기가 남긴 흔적 위에서 다음 부르기가 셈한다. A 와 B 가 같은 칸을 만지고 덧셈과 곱셈은 바꿔
섞이지 않으니, 차례 여섯 가지가 답 여섯 가지를 낸다. A 만 해도 16 · 25 · 26 · 35 를 오간다. 끝의 원본도 `[32, 16, 2]` 와
`[17, 16, 2]` 두 가지로 갈린다.

**새로 만들면** 부를 때마다 원본을 사본에 베끼고 사본의 칸만 바꾼다. 원본은 한 번도 바뀌지 않으니 어느 차례로 불러도
A 16 · B 20 · C 21, 끝의 원본은 처음 그대로 `[3, 6, 2]` 다.

### 화면 읽기

- 위의 점선 자리가 원본이 사는 곳이다. 고치기에서는 원본 판 그 자체가 상자에서 상자로 건너가고, 새로 만들기에서는 원본은
  제자리에 있고 사본이 떨어져 나와 상자로 들어갔다가 합을 돌려준 뒤 걷힌다.
- 상자 A · B · C 는 이 판의 차례대로 자리 1 · 2 · 3 에 선다. 차례를 바꾸면 상자가 자리를 바꾼다.
- 아래 결과 카드는 **부르기 이름 자리에 붙박여** 있다. 차례를 바꿔도 A 의 카드는 늘 같은 자리라, "A 를 맨 앞에서 부르든 맨
  끝에서 부르든 A 가 돌려주는 수는 같은가" 를 카드 하나로 견준다.
- 돌려준 값(결과 카드)과 바깥에 남은 것(끝의 원본)은 따로 선다. 돌려준 값만 보아서는 원본이 바뀌었는지 모른다.
- 칸 번호는 코드의 색인 그대로 0 부터, 부르기 자리는 1 부터 센다.
- 계기는 그 판 하나의 값이다 — 원본에 쓴 횟수(고치기 3 · 새로 0), 만든 사본(고치기 0 · 새로 3), 원본의 합(고치기 50 또는
  35 · 새로 11). 합을 견주는 자리는 없어 동률 규칙이 필요 없다.

### 코드 패널과 언어별로 다른 자리

- 코드 패널의 `fresh` 는 "새 목록을 만든다" 의 자리다. 코드 패널의 IR 은 목록을 지을 수 없어서 부르는 쪽이 버퍼를 건네고,
  `changeCopy` 는 부를 때마다 그 버퍼를 통째로 덮어쓴다. 실제 언어에서는 사본을 짓는다 — 자바스크립트 `[...xs]` · 파이썬
  `list(xs)` · 자바 `new ArrayList<>(xs)` · C# `new List<int>(xs)` · C++ 은 목록을 값으로 받기.
- 여섯 언어 모두 목록 매개변수를 **공유**로 건넨다 — 그래서 고치기가 부른 쪽의 목록을 바꾼다. C++ 은 코드 패널이
  `std::vector<int>&` 로 받아 같은 뜻을 맞춘다. `&` 없이 받으면 부를 때마다 복사되어 고치기도 부른 쪽을 바꾸지 못한다.
  정수 인자(`slot` · `mul` · `add`)는 여섯 언어 모두 값으로 건너간다.
- 부르기 셋은 한 함수의 인자 셋이다. 코드에서는 번호 0 · 1 · 2 로 `slots` · `muls` · `adds` 의 같은 자리를 읽고, A · B · C
  는 화면의 이름표일 뿐 코드에는 없다.
