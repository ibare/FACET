## 합칠 것이 앞서 있기만 할 때

병합이라고 하면 두 줄기의 변경을 섞어 새 커밋을 하나 만드는 일을 떠올린다. 그런데 합칠 쪽이 받는 쪽에서
갈라져 나간 적 없이 그 뒤로 커밋을 더 쌓았을 뿐이라면, 섞을 것이 없다. 받는 쪽의 커밋은 이미 합칠 쪽 줄기
안에 들어 있다. 그때 병합은 무엇을 만드는가.

{facet:fastForward}

### 커밋 다섯, 이름 둘

커밋은 A · B · C · D · E 다섯이고 저마다 바로 앞 커밋 하나를 부모로 가리킨다 — 화살은 늘 새 커밋에서 부모
쪽으로 난다. 브랜치는 커밋을 담는 그릇이 아니라 커밋 하나를 가리키는 이름이다. `main` 은 B 를, `feature` 는
E 를 가리키고, HEAD 는 `main` 에 붙어 있다. 할 일은 `feature` 를 `main` 에 합치는 것이다.

### 네 걸음

처음 모습(걸음 0)을 넣어 네 걸음이다.

1. **판정** — `feature` 의 커밋 E 에서 부모를 따라 거슬러 가면 E · D · C · B 를 지나 `main` 의 커밋 B 를
   만난다. `main` 은 `feature` 의 조상이고, 두 줄기의 병합 기준점(merge base)은 B 자신이다. 이 길은 한 걸음에
   결과로 그어진다. 기준점을 한 커밋씩 찾아 내려가는 모습은 다른 조각의 몫이다.
2. **건너감** — `main` 이름표가 C 와 D 에 멈추지 않고 한 번에 E 로 건너가 붙는다. HEAD 는 `main` 에 붙은 채
   함께 간다. 이름표가 지나간 C · D · E 가 차례로 칠해진다 — 이제 `main` 에서 거슬러 가면 닿는 커밋이다.
3. **셈** — 새 커밋 0, 옮긴 이름 1, 커밋 수는 5 에서 5. `main` 에서 새로 닿는 커밋은 3 이다.

병합이 만든 것은 없다. 이름 하나가 앞으로 옮겨졌을 뿐이다. 이것을 빨리 감기(fast-forward)라 부른다.

### 명령과 잇기

`main` 에서 `git merge feature` 를 하면 git 은 이 경우를 스스로 알아보고 기본으로 빨리 감기를 한다.
`git merge --no-ff` 는 빨리 감기가 될 수 있어도 병합 커밋을 굳이 만들어 "여기서 합쳤다" 는 흔적을 남기고,
`git merge --ff-only` 는 빨리 감기가 안 되면 병합을 거절한다.

두 줄기가 갈라졌다면 — `main` 에도 B 뒤에 커밋이 생겼다면 — `main` 의 커밋은 `feature` 줄기에 없으니 이름표를
옮기는 것만으로는 `main` 쪽 커밋을 잃는다. 그때는 부모가 둘인 병합 커밋이 새로 생긴다. 이 조각은 그 경우를
그리지 않는다.

### 이 모형이 뺀 것

거슬러 가기는 첫 부모만 따라간다. 이 데이터에는 부모가 둘인 커밋이 없어 이것으로 충분하다. 실제 git 은 부모를
모두 따라가 공통 조상을 찾는다. 커밋은 글자로만 부르고 해시는 보이지 않는다.
