## 하이브리드 검색

낱말로 찾은 등수와 뜻으로 찾은 등수를 섞을 때, 어느 쪽에 얼마를 주느냐에 따라 위에 오는 것이 어떻게 바뀔까.

{facet:hybridSearch}

### 무엇을 찾는가

질의는 `update fails with error 0x80070005` 하나이고 문서는 여덟이다. 사람이 정답으로 매긴 것은 셋이다.

- **d1** 오류 번호를 그대로 적고 풀이를 단 문서
- **d2 · d5** 번호는 없이 "권한이 없어 설치가 멈춘다" 를 다른 낱말로 풀어 쓴 문서

함정도 있다. **d6** 은 같은 오류 번호를 적었지만 프린터 이야기다.

### 두 줄

왼쪽 줄은 **낱말 쪽**이다. 질의와 문서를 소문자로 바꾸고 `[a-z0-9]+` 로 가른 뒤 불용어 스물둘을 뺀 토큰으로 BM25 점수를 매긴다 (k1 = 1.2, b = 0.75, 어간 처리 없음 — `fails` 와 `fail` 은 다른 토큰이다). 질의 토큰은 `update fails error 0x80070005` 넷이다. d2 · d5 · d7 · d8 은 이 넷 가운데 하나도 갖고 있지 않아 0 점이다.

오른쪽 줄은 **뜻 쪽**이다. 문서마다 질의와의 유사도를 두었다. 이 수는 **예로 정한 값**이다 — 임베딩 모형이 낸 것이 아니라, 뜻이 가까운 문서가 위에 오도록 사람이 정했다.

등수는 점수 내림차순이고 **같으면 번호가 작은 쪽이 앞선다**. 이 규칙은 이 자료에서 실제로 걸린다 — BM25 0 점 넷이 번호 차례로 5 · 6 · 7 · 8 위에 선다.

### 섞기

가운데 합친 줄은 두 등수를 몫대로 섞는다 (가중 RRF). 낱말 쪽 몫을 w/4 라 하면

점수 = w / (60 + 낱말 등수) + (4 − w) / (60 + 뜻 등수)

w = 4 이면 낱말 등수 차례 그대로, w = 0 이면 뜻 등수 차례 그대로다. 점수가 아니라 **등수**를 섞는다는 데 주의한다 — BM25 0 점인 문서도 낱말 쪽에서 5 위를 받았으면 5 위만큼의 몫을 받는다.

두 점수를 견줄 때는 실수 합으로 견주지 않고 통분한 정수로 정확히 견준다. 동률이면 번호가 작은 쪽이 앞선다. 이 자료에서 동률은 **한 번** 난다 — 몫 50 % 에서 d1 (낱말 1 위, 뜻 5 위) 과 d2 (낱말 5 위, 뜻 1 위) 가 정확히 같다. 가중 RRF 가 두 등수에 대칭이라는 것이 그대로 드러나는 자리이고, 화면의 점수도 소수 넷째 자리까지 둘이 같다. 둘 다 정답이라 위 3 은 달라지지 않는다.

### 손잡이를 돌리면

띠의 굵기가 그 문서가 그쪽에서 받는 몫이다. 낱말 쪽 몫을 올리면 왼쪽 띠가 굵어지고 오른쪽 띠가 가늘어진다. 그리고 합친 줄의 문서들이 한 걸음에 하나씩 새 자리로 옮겨 가며 서로를 지나친다.

| 낱말 쪽 몫 | 합친 차례 (1 위부터) | 위 3 의 정답 | 위 3 중 질의와 낱말이 하나도 안 겹친 문서 |
| ---: | --- | ---: | ---: |
| 0 % | d2 d5 d7 d8 d1 d4 d3 d6 | 2 | 3 |
| 25 % | d2 d5 d1 d7 d8 d4 d3 d6 | 3 | 2 |
| 50 % | d1 d2 d5 d4 d6 d7 d3 d8 | 3 | 2 |
| 75 % | d1 d6 d4 d2 d3 d5 d7 d8 | 1 | 0 |
| 100 % | d1 d6 d4 d3 d2 d5 d7 d8 | 1 | 0 |

- **뜻으로만 찾으면**(0 %) 오류 번호를 그대로 적은 d1 이 5 위로 밀려난다. 뜻이 비슷할 뿐 엉뚱한 d7 · d8 이 그 위에 선다.
- **낱말로만 찾으면**(100 %) d1 은 맨 위로 올라가지만, 같은 번호를 적은 프린터 문서 d6 이 2 위로 따라 올라오고 d2 · d5 는 위 3 밖으로 내려간다.
- **섞으면**(25 % · 50 %) 서로 못 찾는 것을 메워 위 셋이 모두 정답이 된다.

위 3 의 정답은 2 → 3 → 3 → 1 → 1 로 **뒤집힌 U** 를 그린다. 몫을 한쪽으로 많이 줄수록 좋은 것이 아니다 — 어느 쪽으로든 치우치면 다시 잃는다. 둘째 계기는 3 → 2 → 2 → 0 → 0 으로 한쪽으로만 내려간다. 몫을 낱말 쪽으로 옮길수록 "낱말은 하나도 안 겹치는데 뜻으로 올라온" 문서가 위에서 빠진다.

### 코드 패널

코드 패널은 **섞는 자리만** 편다. BM25 는 토큰을 가르고 같은 토큰을 세는 문자열 셈인데, 코드 패널의 코드는 여섯 언어로 옮겨지고 그중에는 문자열을 `==` 로 견줄 수 없는 언어도 있다. 그래서 BM25 와 두 등수는 바깥에서 셈해 정수 배열로 건네고, 패널의 `fuseTop` 은 그 두 등수를 몫대로 섞어 화면처럼 여덟 자리를 1 위부터 끝까지 차례로 고르고(고른 자리를 `taken` 에 적는다), 앞 `top` 자리 가운데 정답 수를 돌려준다. 고를 때마다 남은 문서를 훑으며 통분한 정수로 견주고, **엄격히 클 때만** 바꾼다 — 그래서 동률이면 앞 번호가 남는다.

### 이어지는 조각

한쪽은 낱말을 맞추고 한쪽은 뜻을 맞춘다는 것은 {facet:sameWordVsSameMeaning} 에서, 각자의 순위를 모아 다시 매기는 셈은 {facet:fuseTwoRankings} 에서 따로 떼어 볼 수 있다.
