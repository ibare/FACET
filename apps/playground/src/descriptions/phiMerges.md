# 파이 — 갈라진 판이 만나는 자리

SSA 에서는 이름마다 넣을 때마다 새 판을 준다. 곧은 줄 코드라면 읽는 자리마다 어느 판인지가 하나로 정해진다. 그런데
두 갈래가 같은 이름에 서로 다른 판을 넣고 다시 만나면, 만난 뒤에 읽는 이름은 어느 판이어야 할까. 글만 보고는 정할 수
없다 — 어느 갈래로 왔는지는 돌려 봐야 안다. 그래서 만나는 블록의 머리에 **파이(φ)** 를 세운다. 파이는 갈래마다 인자를
하나씩 쥐고, 돌 때 흐름이 실제로 들어온 쪽의 인자를 고른다.

{facet:phiMerges}

## 무엇을 보는가

원래 프로그램은 이렇다.

```
function f(a)
    let x = a
    let y = 1
    let z = a * 2
    if x > 5
        x = x - 5
    else
        y = 2
    return x + y + z
```

이것을 세 주소 코드로 낮추면 명령 11 줄이 되고, 블록 넷으로 나뉜다 — B1(1~5 줄) · B2(6~7 줄) · B3(8 줄) · B4(9~11 줄).
B2 와 B3 이 갈래이고, B4 는 둘이 만나는 블록이다. 화면은 B1 을 위에, 갈래 둘을 가운데에, B4 를 아래에 세운다.

처음 화면(걸음 0)을 넣어 모두 6 걸음이다.

- 걸음 0 — B1~B3 은 이미 판이 매겨져 있다(`x1` · `y1` · `z1` · `x2` · `y2`). B4 만 아직 `x` · `y` · `z` 를 판 없이 읽는다.
- 걸음 1 — `x`. B2 끝의 판은 `x2`, B3 끝의 판은 `x1` 이다. 두 판이 간선을 타고 B4 머리로 흘러들고, 서로 다르니 파이 하나로
  모인다: `x3 = φ(B2: x2, B3: x1)`. B3 은 `x` 에 넣지 않았는데도 파이가 선다 — 한쪽만 바꿔도 두 쪽의 판은 달라진다. 첫 파이가 서면서 블록 머리의 라벨 `L2` 는 이 파이 줄로 옮겨 붙는다.
- 걸음 2 — `y`. 이번에는 B2 쪽이 손대지 않은 판(`y1`)이고 B3 쪽이 새 판(`y2`)이다. 역시 파이: `y3 = φ(B2: y1, B3: y2)`.
- 걸음 3 — `z`. 두 쪽 다 `z1` 이다. 모일 것이 없으니 파이를 두지 않고 `z1` 이 그대로 지나간다.
- 걸음 4 — B4 몸의 읽기가 모인 판으로 바뀐다. `t2 = x + y` 는 `t2 = x3 + y3`, `t3 = t2 + z` 는 `t3 = t2 + z1` 이 된다.
  바뀐 읽기 자리는 셋이다.
- 걸음 5 — `a = 8` 로 한 번 돌린다. `x1 > 5` 가 참이라 B1 에서 뛰지 않고 B2 로 흘러내리고, B2 끝의 `goto L2` 로 B4 에
  닿는다. B2 에서 들어왔으니 두 파이는 B2 쪽 인자를 고른다: `x3 = x2`(3) · `y3 = y1`(1). `z1` 은 16 이고, 돌려준 값은 20 이다.

끝의 B4 에는 파이 둘과 파이 없이 지나간 이름 하나가 남는다.

## 임시는 판을 받지 않는다

`t1` · `t2` · `t3` 은 낮추기가 만든 임시다. 임시는 처음부터 한 번씩만 넣어지므로 판을 줄 까닭이 없다 — `t1` 의 `1` 은
판 번호가 아니라 임시의 차례다. 인자 `a` 도 코드 안에서 넣어지지 않으므로 판이 없다.

## 전제

- `a = 8` 은 예로 정한 값이다. `a = 3` 이었다면 `x1 > 5` 가 거짓이라 B1 → B3 → B4 로 가고, 파이는 B3 쪽 인자를 골라
  돌려준 값은 11 이 된다. 값을 바꿔 다시 돌리는 것은 이 조각의 일이 아니다.
- 파이는 앞선 블록이 둘 이상인 블록의 머리에만 서고, 이름마다 앞선 블록들 끝의 판을 견줘 다를 때만 선다. 이 데이터에는
  되돌아오는 간선(고리)이 없다.
- 세 주소 코드와 SSA 의 표기(판 번호 · `φ(B2: x2, B3: x1)`)는 이 조각의 장난감 표기다. 실제 컴파일러는 파이 인자에 블록을
  다른 모양으로 붙이기도 한다.
