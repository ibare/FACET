## 차례는 더해 줘야 한다

**셀프 어텐션은 토큰의 차례를 보지 못한다.** 줄을 뒤바꿔도 한 토큰이 얻는 결과는 한 자리도 달라지지 않는다. 차례를 알게 하려면 자리마다 다른 표시를 입력에 **더해** 줘야 한다.

{facet:orderMustBeAdded}

### 숫자로 보면

토큰 셋 A (1, 0) · B (0, 1) · C (1, -2) 를 A B C 로 놓고, A 가 묻는 줄 하나를 셈한다. 무게는 0.40 · 0.20 · 0.40, A 의 결과는 **(0.80, -0.60)** 이다.

줄을 C B A 로 뒤바꿔도 A 가 C · B · A 에 주는 무게는 0.40 · 0.20 · 0.40 그대로다. 무게가 토큰을 따라 옮겨 갈 뿐이라 섞인 결과도 **(0.80, -0.60)**, 두 결과의 차이는 **0.00** 이다. 점수는 두 입력의 내적이라 입력이 어느 자리에 있든 같고, 합은 더하는 차례와 무관하기 때문이다.

이제 자리 p 마다 위치 표시 PE(p) = (sin p, cos p) 를 붙인다 — 자리 0 은 (0.00, 1.00), 자리 1 은 (0.84, 0.54), 자리 2 는 (0.91, -0.42). 이것을 입력에 더하면 같은 A 가 자리 0 에서는 (1.00, 1.00), 자리 2 에서는 (1.91, -0.42) 로 다른 입력이 된다.

- A B C 에 더하면 무게 0.40 · 0.53 · 0.07, A 의 결과 **(0.98, 1.05)**
- C B A 에 더하면 무게 0.23 · 0.09 · 0.68, A 의 결과 **(1.60, -0.38)**

두 결과의 차이는 **1.56**. 표시 없이는 0.00 이던 거리다. 화면은 처음 화면을 넣어 일곱 걸음이다.

### 왜 이렇게 되나

어텐션의 셈은 짝마다 내적을 구하고, 무게를 매겨 더하는 것뿐이다. 어느 셈에도 "몇 번째" 가 들어가지 않는다. 그래서 줄의 차례를 바꾸면 무게와 값이 함께 자리를 옮기고 결과는 그대로 남는다 — 어텐션은 줄을 차례 있는 목록이 아니라 **집합**으로 다룬다.

위치 표시는 이 틈을 입력 쪽에서 메운다. 표시를 **이어 붙이지 않고 더하는** 것도 뜻이 있다. 입력의 크기가 그대로라 뒤따르는 셈을 고칠 필요가 없고, 같은 토큰이라도 자리에 따라 조금 다른 벡터가 되어 점수와 무게가 달라진다.

### 이 그림이 줄인 것

- **투영을 생략했다.** 실제 어텐션은 입력에 행렬을 곱해 물음 · 열쇠 · 값을 따로 만든다. 여기서는 셋 다 입력 그대로다 (q = k = v = x). 투영을 두어도 차례를 모르는 성질은 같다.
- **입력 · 토큰 수 · 차원 2 는 예로 정한 값이다.** 점수는 √2 로 나누고, softmax 는 최댓값을 빼고 셈한다 (결과는 같다).
- **차원이 2 라 주파수가 하나뿐이다.** 교과서의 사인 · 코사인 인코딩은 PE(p, 2i) = sin(p / 10000^(2i/d)) · PE(p, 2i+1) = cos(p / 10000^(2i/d)) 인데, d = 2 면 i = 0 하나라 (sin p, cos p) 가 된다. 실제 모형은 d 가 수백이라 느린 것부터 빠른 것까지 주파수가 여럿이다.
- **한 층, 어텐션 한 번만** 셈했다. 마스크 · 잔차 · 층 정규화는 없다.
