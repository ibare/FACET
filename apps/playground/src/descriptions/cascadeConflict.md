
# 규칙이 다투면 무게로 정해진다

CSS 를 처음 배울 때 흔히 듣는 말이 "나중에 쓴 것이 이긴다" 다. 반은 맞다. 같은 요소의 같은
속성을 여러 규칙이 서로 다른 값으로 정하면, 브라우저는 먼저 **무게**를 견주고, 무게가 꼭 같을
때만 나중 것을 고른다.

{facet:cascadeConflict}

## 무게는 선택자 글자에서 센다

무게(명시도)는 수 셋 `(a, b, c)` 이다. `a` 는 선택자 안의 아이디(`#lead`) 수, `b` 는 클래스
(`.note`) 수, `c` 는 태그(`p`) 수다. 화면의 다섯 규칙은 이렇게 된다.

| 차례 | 선택자 | 값 | 무게 |
| --- | --- | --- | --- |
| #1 | `p` | `black` | (0,0,1) |
| #2 | `.card p` | `gray` | (0,1,1) |
| #3 | `p.note` | `green` | (0,1,1) |
| #4 | `#lead` | `navy` | (1,0,0) |
| #5 | `.card .note` | `teal` | (0,2,0) |

견줄 때는 `a` 부터 본다. `a` 가 다르면 거기서 끝이고, 같을 때만 `b` 로, 그다음 `c` 로 넘어간다.
그래서 클래스가 둘인 `.card .note` 도 아이디 하나인 `#lead` 를 이기지 못한다 — 자릿수가 다른
수를 견주는 것과 같다.

## 자리를 뺏고, 밀려난다

화면은 규칙을 원본 차례대로 하나씩 들여보낸다. 오른쪽 "자리" 에는 지금 이기고 있는 규칙이 앉아
있고, 새로 들어온 규칙은 그 규칙과 무게를 맞댄다. 걸음은 처음 화면까지 일곱이다.

1. `#1 p` 가 빈 자리를 쥔다.
2. `#2 .card p` (0,1,1) 이 `p` (0,0,1) 보다 무겁다 — 자리를 뺏는다.
3. `#3 p.note` (0,1,1) 은 `.card p` 와 무게가 같다 — **나중 것이라서** 뺏는다.
4. `#4 #lead` (1,0,0) 이 더 무겁다 — 뺏는다.
5. `#5 .card .note` (0,2,0) 은 더 가볍다 — **가장 나중에 왔는데도** 밀려난다.
6. 끝까지 자리를 지킨 `#4` 의 `color: navy;` 가 요소에 붙는다.

자리가 바뀐 것이 셋, 쥔 쪽이 지킨 것이 하나다. 나중에 왔다는 까닭 하나로 이긴 것은 셋째
걸음뿐이다. 둘째 · 넷째 걸음은 나중 것이 이기기는 했지만 무거워서 이겼고, 다섯째 걸음은
"나중에 쓴 것이 이긴다" 의 반례다.

## 이 그림이 세운 전제

- **다섯 규칙은 모두 이 요소에 맞는다고 두고 시작한다.** 선택자가 요소에 맞는지 따지는 일은
  선택자를 오른쪽부터 읽는 이웃 조각이 다룬다. 이 화면은 조상을 거슬러 오르지 않는다.
- **다툼은 무게와 차례만으로 가린다.** 실제 캐스케이드는 그 앞에 출처(브라우저 기본 · 사용자 ·
  저자)와 `!important`, 인라인 `style`, `@layer` 를 먼저 견준다. 여기 규칙은 모두 저자
  스타일시트의 보통 선언이라 그 단계가 전부 비긴다.
- **상속은 없다.** 부모 `div.card` 에 걸린 `color` 가 내려오는 일은 이 모형에 없다. 상속된 값은
  요소에 직접 맞은 규칙이 하나라도 있으면 그보다 약하다.
- 선택자는 태그 · 클래스 · 아이디와 자손 결합자(빈칸)만 쓴다. 가상 클래스 · 속성 선택자 ·
  `:is()` · `:where()` 처럼 무게를 다르게 세는 모양은 없다.
