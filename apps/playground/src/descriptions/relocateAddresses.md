# 재배치 — 주소를 옮겨 맞춘다

컴파일러는 파일을 하나씩 따로 기계 명령으로 바꾼다. 그래서 오브젝트 파일은 저마다 제 명령과 자료를 **0 부터** 센다. `app.o` 의 첫
명령도 +0 이고 `lib.o` 의 첫 명령도 +0 이다. 둘을 이어 붙이면 둘 중 하나는 0 에 있을 수 없다. 게다가 명령 속에는 다른
자리를 가리키는 주소 칸이 있는데, 컴파일할 때는 그 자리가 어디에 놓일지 몰라 칸을 0 으로 비워 두었다. 링커는 이 칸들을
어떻게 채우는가.

## 무엇을 보는가

왼쪽은 오브젝트 파일 둘이다. 파일마다 명령이 든 **text 절**과 자료가 든 **data 절**이 있고, 줄 앞의 `+0` · `+4` 는 제 절의
시작에서 센 자리다. 명령 하나는 4 바이트다.

- `app.o` — text 16 바이트(`load r1, @0` · `call +0` · `store @0, r1` · `ret`), data 8 바이트(`count`)
- `lib.o` — text 12 바이트(`load r2, @0` · `mul r1, r1, r2` · `ret`), data 4 바이트(`limit`)

점선 칸은 비어 있는 주소 칸이다. 칸마다 **재배치 항목**이 붙어 있다 — 이 칸에 어느 심볼의 주소를 어떤 식으로 적어야 하는지를
적은 쪽지다. `ABS` 는 심볼의 주소 그 자체(`@` 로 적는다)를, `REL` 은 이 명령에서 심볼까지의 거리(`+` 로 적는다)를 적으라는
뜻이다. 어느 이름이 어느 파일에 있는지는 이미 풀려 있어서, 여기서는 심볼 표가 주어진다.

오른쪽은 이어 붙인 뒤의 메모리다. text 는 @1000 부터, data 는 @2000 부터 놓는다.

처음 화면(걸음 0)을 넣어 모두 9 걸음이다.

1. **놓기 (걸음 1~4)** — 절이 하나씩 파일에서 떨어져 나와 메모리의 제자리로 옮겨 간다. text 절을 파일 차례로 먼저,
   다음에 data 절을 파일 차례로. `app.o` text 는 @1000~@1015, `lib.o` text 는 그 바로 뒤 @1016~@1027, `app.o` data 는
   @2000~@2007, `lib.o` data 는 @2008~@2011 이다. 절이 놓이면 그 안의 심볼도 주소가 정해진다 — 심볼 주소는 **제 절이 놓인
   자리 + 절 안 자리**다. `main` @1000 · `scale` @1016 · `count` @2000 · `limit` @2008.
2. **고치기 (걸음 5~8)** — 재배치 항목을 차례로 하나씩 처리한다. 심볼 주소를 S, 고칠 명령의 주소를 P 라 하면 절대 칸에는
   S 를, 상대 칸에는 S − P 를 적는다. 수가 칸으로 날아와 비어 있던 0 을 밀어낸다.
   - 걸음 5 — `app.o`+0 (P = @1000) 절대 `count`: `load r1, @0` → `load r1, @2000`
   - 걸음 6 — `app.o`+4 (P = @1004) 상대 `scale`: `call +0` → `call +12`. 1016 − 1004 = 12 를 P 와 S 사이 꺾쇠가 잰다
   - 걸음 7 — `app.o`+8 (P = @1008) 절대 `count`: `store @0, r1` → `store @2000, r1`
   - 걸음 8 — `lib.o`+0 (P = @1016) 절대 `limit`: `load r2, @0` → `load r2, @2008`

마지막 걸음에서 네 칸이 모두 채워진다. 같은 `count` 를 가리키는 두 칸은 같은 값 2000 을 받는다. 절대 칸은 심볼이 옮겨 간
만큼 그대로 따라 밀리지만, 상대 칸은 명령과 심볼이 **둘 다** 옮겨 가므로 둘 사이의 차로 다시 잰다. `mul` · `ret` 처럼 다른
자리를 가리키지 않는 명령은 손대지 않는다.

## 예로 정한 것

- 놓는 자리 @1000 · @2000, 명령 하나 4 바이트는 보기 쉽게 정한 값이다. 실제 링커는 운영체제와 실행 파일 형식이 정한 자리에
  절을 놓고, 절 사이에 정렬을 위한 빈틈을 두기도 한다.
- 상대 거리는 여기서 **명령 자기 주소**(P)에서 잰다. 실제 CPU 는 대개 **다음 명령**(또는 주소 칸의 끝)에서 재므로, 실제 재배치
  식에는 −4 같은 덧셈이 더 붙는다.
- 명령은 특정 CPU 가 아닌 가상 레지스터 기계의 것이다.
