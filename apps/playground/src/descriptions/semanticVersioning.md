## 세 자리는 누구와 누구의 약속인가

버전 `1.4.2` 의 세 수는 그냥 차례 번호가 아니다. 꾸러미를 내보내는 쪽은 이번 바뀜이 얼마나 무거운지에 따라
세 자리 가운데 하나를 올리고, 그 꾸러미를 쓰는 쪽은 범위를 적어 어느 자리의 오름까지 받아들일지 정한다.
두 쪽이 서로를 보지 않고도 "이 새 버전을 받아도 되는가" 에 같은 답을 내려면 이 약속이 지켜져야 한다. 그리고
잠금 파일은 그 약속 위에 한 겹을 더 얹는다 — 범위가 받아도 된다고 해도 받지 않는다.

{facet:semanticVersioning}

### 한 꾸러미, 한 받는 쪽

꾸러미는 `units` 하나, 받는 쪽에 깔린 버전은 `1.4.2` 다. 한 판에 새 버전이 하나 나오고, 받는 쪽은 그것을
받거나 받지 않는다.

손잡이 **내보낸 바뀜**이 이번에 무엇을 내보냈는지 고른다.

- **고침** — 겉으로 보이는 쓰임새는 그대로이고 잘못만 고쳤다. patch 자리를 올린다 → `1.4.3`
- **기능 추가** — 있던 쓰임새는 그대로 두고 새것을 더했다. minor 자리를 올리고 patch 를 0 으로 → `1.5.0`
- **호환 깨짐** — 있던 쓰임새를 바꾸거나 뺐다. major 자리를 올리고 minor · patch 를 0 으로 → `2.0.0`

위쪽 세 칸에서 `+1` 표지가 오르는 자리로 옮겨 가고, 그 오른쪽 칸의 수가 0 으로 떨어진다. 계기
**0 으로 떨어진 자리**는 오른쪽 자리 가운데 본디 0 이 아니었다가 0 이 된 것을 센다 — `1.4.2` 에서 고침은 0,
기능 추가는 1, 호환 깨짐은 2 다.

### 범위는 두 끝이다

손잡이 **받는 쪽**이 범위를 고른다. 범위는 아래 끝을 넣고 위 끝을 빼는 두 끝으로 푼다.

- `^1.4.2` → [1.4.2, 2.0.0) — 가장 왼쪽의 0 이 아닌 자리(여기서는 major)만 그대로면 받는다
- `~1.4.2` → [1.4.2, 1.5.0) — minor 까지 그대로여야 받는다. patch 의 오름만 받는다

새 버전을 두 끝에 댄다. 버전은 세 수를 앞에서부터 **수로** 견준다(`1.10.0` 은 `1.9.4` 보다 크다). 아래 끝보다
작으면 아래로 벗어나고, 위 끝과 **같거나** 크면 위로 벗어난다. 이 데이터에서는 경계에 딱 걸리는 자리가 둘 있다 —
`~1.4.2` 에게 `1.5.0`, `^1.4.2` 에게 `2.0.0` 은 위 끝과 같아서 벗어난다. 안에 들면 설치 표식이 새 점으로
건너가고, 벗어나면 제자리에 남는다.

손잡이를 돌려 받는 쪽마다 바뀜 셋을 차례로 보면, 새것을 받는 판은 `^` 에서 둘(고침 · 기능 추가), `~` 에서
하나(고침)다. 계기 **받음**은 판마다 0 이나 1 이고 판을 건너 쌓이지 않는다.

### 잠금은 범위보다 먼저 읽힌다

셋째 칸 `^` + 잠금은 범위가 `^1.4.2` 로 같지만 잠금 파일에 `units 1.4.2` 가 적혀 있다. 이때는 범위를 풀기
**전에** 잠금 파일을 읽고, 거기 적힌 버전을 그대로 깐다. 그래서 이 칸에서는 걸음이 하나 적고(범위의 두 끝을
세우지도, 새 버전을 대 보지도 않는다), 바뀜이 무엇이든 깔린 것은 `1.4.2` 에 머문다. 범위 안의 `1.4.3` 도 받지
않는다.

### 코드 패널

`receive` 는 화면과 같은 길을 간다 — 자리를 올리고, 잠금이 있으면 곧바로 2 를 돌려주고, 없으면 위 끝을 셈해
새 버전을 두 끝에 대어 받음 1 · 거절 0 을 돌려준다. 코드에서 범위 기호는 번호(0 = `^`, 1 = `~`)로, 버전은 세 수로
건네고, 새 버전은 부르는 쪽이 만든 세 칸 버퍼에 쓴다. 위 끝은 `upperPart` 를 자리마다 한 번씩 불러 얻는다.

### 이 그림이 줄인 것

- **새로 고를 때 범위 안에서 가장 큰 버전을 고르는 것**은 npm 의 기본 동작이다. 여기서는 새 버전이 한 판에 하나라
  "가장 큰 것" 을 고를 일이 없다.
- **0.x 의 관례** — major 가 0 이면 아직 약속이 굳지 않았다고 보고 `^` 가 더 좁아진다. `^0.3.1` 은 [0.3.1, 0.4.0),
  `^0.0.4` 는 [0.0.4, 0.0.5) 다. 이 데이터에는 없지만 코드 패널의 `upperPart` 는 이 경우도 푼다.
- **프리릴리스**(`1.5.0-beta.1`) 와 빌드 표식(`+sha`), 앞붙이 `v` 는 뺐다. 버전은 늘 세 수다.
- **잠금 파일**은 이름과 버전 두 칸으로 줄였다. npm 의 `package-lock.json` 은 이보다 훨씬 많은 것(받은 곳,
  무결성 값, 의존의 나무)을 적는다.
- **잠금과 범위가 어긋날 때**는 도구마다 다르다. npm 의 `npm install` 은 `package.json` 의 범위가 잠긴 버전을
  더는 품지 않으면 범위를 다시 풀어 잠금 파일을 고친다. `npm ci` 는 잠금 파일과 `package.json` 이 어긋나면
  고치지 않고 오류를 내며 멈춘다. 이 데이터의 잠긴 버전은 늘 범위 안이라 어느 쪽도 일어나지 않는다.
