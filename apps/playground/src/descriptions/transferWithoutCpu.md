
## CPU 를 거치지 않고 옮기기 (DMA)

디스크나 네트워크 카드 같은 장치에서 데이터가 들어오면 누군가는 그것을 메모리로
옮겨야 한다. 가장 단순한 방법은 CPU 가 직접 하는 것이다 — 장치에서 낱말 하나를 읽어
손에 쥐고, 메모리의 다음 주소에 쓰고, 다시 읽고 쓰기를 되풀이한다. 그동안 CPU 는
다른 일을 하나도 못 한다.

DMA(직접 메모리 접근)는 이 옮기기를 **옮기는 일만 하는 작은 장치**, DMA 제어기에
맡긴다. CPU 는 처음에 제어기에 세 값만 적는다 — 어디로 넣을지(주소), 몇 개인지(개수),
어느 쪽으로인지(방향). 그다음부터는 제어기가 스스로 센다.

## 한 걸음에 두 쪽이 함께 나아간다

화면의 한 걸음은 한 **틱**이다. 틱은 이 그림에서 예로 정한 시간 단위로, 낱말 하나를
옮기는 데 한 틱, CPU 가 수 하나를 더하는 데 한 틱이 든다고 둔다. 실제 장치의
나노초를 흉내 내지는 않는다.

옮기는 틱마다 제어기는 장치의 다음 낱말을 제 주소 칸에 넣고, 주소를 하나 올리고,
개수를 하나 줄인다. 낱말은 제어기의 통로를 지나 메모리로 가고, **CPU 는 그 길 위에
없다.** 같은 틱에 CPU 는 하던 일 — 3 · 1 · 4 · 1 · 5 · 9 를 차례로 더하는 일 — 을 한
칸 나아간다. 낱말 여섯이 주소 200 부터 205 까지 들어가는 여섯 틱 동안 CPU 의 합은
3 · 4 · 8 · 9 · 14 · 23 으로 커진다.

개수가 0 이 되면 제어기가 CPU 를 **한 번** 부른다(인터럽트). 여섯 낱말을 옮기는 데
CPU 가 쓴 것은 처음에 세 값을 적은 걸음 하나와, 끝났다는 부름을 받아 적은 걸음
하나뿐이다. CPU 를 거친 낱말은 0 이다. 처음 화면부터 부름을 받아 적기까지 모두 열
걸음이다.

## CPU 가 직접 옮겼다면

같은 여섯 낱말을 CPU 가 손수 옮겼다면, 옮기는 여섯 틱 동안 CPU 의 합은 0 에서
움직이지 않았을 것이다. 틱마다 낱말을 읽고 쓰는 것이 CPU 의 일이 되기 때문이다.
화면에서 합이 23 까지 커진 것은 그 여섯 틱이 CPU 에게 고스란히 돌아왔다는 뜻이다.
낱말이 여섯이 아니라 수천이면 돌려받는 틱도 그만큼 많아진다.

## 이 그림이 덜어 낸 것

실제 컴퓨터에서 제어기와 CPU 는 같은 메모리 통로(버스)를 쓴다. 제어기가 낱말을
쓰는 순간에 CPU 도 메모리에 가려 하면 둘 중 하나가 기다린다 — 제어기가 CPU 의 몫을
잠깐씩 빌려 쓴다고 해서 "사이클 훔치기" 라 부르기도 한다. 이 그림은 그 다툼을 두지
않는다. CPU 가 제 일을 캐시 안에서 해서 메모리 통로를 쓰지 않는다고 두었다.
그래서 두 쪽이 틱마다 한 칸씩 막힘 없이 나아간다.
