# 두 브랜치가 갈라진 곳은 두 끝에서 내려온 표시가 겹치는 곳이다

병합하거나 다시 놓기 전에 git 은 먼저 **두 브랜치가 어디서 갈라졌는지**를 찾는다. 이 커밋을 병합 기준점(merge-base)이라
부르고, `git merge-base main feature` 가 그것을 알려 준다. 커밋은 부모만 가리키고 부모는 자식을 모르니, 찾는 길은
두 끝에서 **거슬러 내려가는** 것뿐이다.

{facet:whereTheyParted}

## 두 표시가 번갈아 내려온다

`main` 은 E 를, `feature` 는 I 를 가리킨다. 두 끝에 각자의 표시를 붙이고, 둘을 꺼낼 줄에 넣는다. 가로축은 커밋을 만든
시각이라 오른쪽일수록 늦다.

- 줄에서 **시각이 가장 늦은** 커밋 하나를 꺼낸다. 세로 점선이 그 시각이다.
- 그 커밋이 두 표시를 모두 가졌으면 거기가 갈라진 자리다. 멈춘다.
- 아니면 제 표시를 부모에게 넘기고(표시가 화살을 따라 내려간다) 부모를 줄에 넣는다.

늦은 것부터 꺼내므로 점선은 오른쪽에서 왼쪽으로만 간다. 그러다 보니 `feature` 쪽 I · H · G 를 먼저 내려가고, E 를
하나 꺼낸 뒤 다시 F 로 돌아간다. `feature` 의 표시가 F 에서 C 로, `main` 의 표시가 D 에서 C 로 내려오면 C 가 두 표시를
함께 가진다. C 를 꺼내는 걸음에 답이 난다. 처음 화면까지 걸음 여덟, 꺼낸 커밋 일곱이다.

두 쪽이 내려온 거리는 같지 않다. `main` 에서 C 까지는 둘, `feature` 에서는 넷이다. 두 끝에서 같은 수만큼 내려가 만나는
것이 아니라, 시각 차례로 꺼내다가 **처음 겹치는 곳**에서 멈춘다. 그래서 A 와 B 도 두 브랜치의 공통 조상이지만 꺼내지
않는다. 공통 조상 셋 가운데 두 끝에 가장 가까운 C 하나만 답이다.

## 이 그림이 세운 전제

- **부모가 하나인 커밋만 있다.** 병합 커밋이 끼면 한 커밋이 두 부모에게 표시를 넘기고, 공통 조상 가운데 "가장 가까운"
  것이 둘 이상일 수도 있다. 이 화면은 그 경우를 다루지 않는다.
- **시각은 정수 차례로 두었다.** 커밋 그래프 파일이 있으면 git 은 세대 번호를 먼저 보고, 날짜는 동률일 때 가린다.
  이 화면은 날짜 차례의 꼴만 남겼고, 데이터에 시각이 같은 커밋은 없다.
- **처음 겹친 곳에서 멈춘다.** 실제 git 은 답 후보를 찾은 뒤에도 줄에 남은 커밋을 더 꺼내, 한 후보가 다른 후보의
  조상이면 걸러 낸다. 부모가 하나뿐인 이 데이터에서는 첫 겹침이 곧 답이다.
