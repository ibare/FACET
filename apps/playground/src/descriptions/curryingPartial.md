## 인자를 하나씩 받아 함수를 남긴다

인자 셋을 받는 함수는 보통 셋을 한꺼번에 받는다. 커링은 그 함수를 **인자를 하나씩 받는 함수들의 사슬**로
적는 방식이다. 하나를 주면 답이 나오는 대신, 남은 인자를 기다리는 함수가 나온다.

{facet:curryingPartial}

### 칸이 하나씩 닫힌다

`add` 는 `a => b => c => a + b + c` 다. 인자 칸 셋(`a` · `b` · `c`)이 열린 함수다.

- `add(5)` — 5 가 맨 앞 칸 `a` 에 들어가 그 칸이 닫힌다. 남는 것은 칸 둘이 열린 새 함수
  `b => c => 5 + b + c` 이고, 이것이 `add5` 에 담긴다.
- `add5(2)` — 2 가 칸 `b` 를 닫는다. 칸 하나짜리 `c => 5 + 2 + c` 가 `add7` 에 담긴다.
- `add7(10)` — 10 이 마지막 칸 `c` 를 닫는다. 열린 칸이 없으니 이번에는 함수가 아니라 **값** 17 이 나온다.

인자를 줄 때마다 남은 칸이 3 · 2 · 1 · 0 으로 준다. 모두 여섯 걸음(시작 · 네 줄의 담기 · 출력)이다.

### 앞의 함수는 그대로다

인자를 준다고 `add` 가 바뀌지 않는다. 끝까지 가도 `add` 는 칸 셋, `add5` 는 칸 둘이 열려 있다. 인자를
받을 때마다 **새 함수**가 생길 뿐이다. 그래서 `add5` 를 다른 인자로 다시 부를 수도 있다 — 5 를 미리 채워 둔
함수를 여러 번 쓰는 것, 이것이 부분 적용이다.

### 그림의 글자에 대하여

그림은 남은 함수를 `c => 5 + 2 + c` 처럼 받은 값을 채워 넣은 글자로 보인다. 무엇이 채워졌는지 보이려는
표기일 뿐이다. 실제 런타임은 받은 값(`a` 는 5, `b` 는 2)을 쥐고 있을 뿐 함수의 글자를 다시 쓰지 않는다.
