## 한 문장이 실패하면 앞의 문장들은 어떻게 되는가

트랜잭션은 여러 문장을 한 덩어리로 묶는다. 원자성(atomicity)은 그 덩어리가 **다 되거나
하나도 안 되거나** 둘 중 하나로만 끝난다는 약속이다. 가운데 한 문장이 실패하면, 이미 성공해
줄에 값을 써 둔 앞 문장들까지 없던 일이 되어야 한다. 엔진은 그것을 되돌림 기록(undo log)으로
해낸다 — 쓰기마다 옛 값을 적어 두었다가, 실패하면 **적힌 역순으로** 한 칸씩 옛 값을 되쓴다.

### 걸음 여섯

Ann 이 가게에서 펜 셋을 한 개 10 에 산다. 돈 30 이 Ann 에서 가게로 옮겨 가고, 재고에서
펜 셋이 빠져야 한다. 표는 둘이고, 둘 다 값이 0 아래로 내려가지 못하게 막아 두었다.

```sql
accounts(id, balance)  CHECK (balance >= 0)   -- ('ann', 100) · ('shop', 20)
stock(item, qty)       CHECK (qty >= 0)       -- ('pen', 2)
```

```sql
BEGIN;
UPDATE accounts SET balance = balance - 30 WHERE id = 'ann';
UPDATE accounts SET balance = balance + 30 WHERE id = 'shop';
UPDATE stock SET qty = qty - 3 WHERE item = 'pen';
COMMIT;
```

0. **처음 모습.** ann 100 · shop 20 · pen 2, 되돌림 기록은 비어 있다.
1. **첫 문장이 성공한다.** ann 100 → 70. 옛 값 100 이 되돌림 기록 1 번 칸으로 간다.
2. **둘째 문장이 성공한다.** shop 20 → 50. 옛 값 20 이 2 번 칸으로 간다.
3. **셋째 문장이 튕겨 난다.** pen 2 에서 3 을 빼면 −1 이라 `CHECK (qty >= 0)` 에 걸린다.
   CHECK 는 새 값을 쓰기 **전에** 보므로 pen 은 그대로 2 이고, 되돌림 기록에도 칸이 붙지 않는다.
   엔진이 트랜잭션을 되돌리기 시작하고, `COMMIT` 줄은 실행되지 않는다.
4. **마지막 칸부터 되감는다.** 2 번 칸: shop 50 → 20.
5. **다음 칸.** 1 번 칸: ann 70 → 100. 되돌림 기록의 두 칸이 모두 되감겼고, 세 줄 모두 처음 값에 선다.

### 되돌리지 않았다면

걸음 3 에서 멈췄다면 표는 ann 70 · shop 50 · pen 2 로 남는다. 돈은 옮겨 갔는데 펜은 하나도
나가지 않았다. 흥미로운 것은 두 경우 모두 잔액의 합이 120 이라는 점이다 — 깨지는 것은 합이
아니라 **돈과 펜의 짝**이다. 원자성이 지키는 것은 이 짝이다.

### 이 그림이 정한 것

- 문장 하나는 줄 하나의 값 하나만 바꾼다. 한 문장이 여러 줄을 바꾸는 경우에도 그 문장 자체가
  하나의 단위로 다 되거나 안 되는데(문장 단위 원자성), 이 그림은 그 안을 들여다보지 않는다.
- 값은 예로 정한 것이다. 실패 뒤 되돌림을 엔진이 스스로 하는지, 응용이 `ROLLBACK` 을 보내야
  하는지는 엔진과 설정마다 다르다. 여기서는 엔진이 곧바로 되돌리는 것으로 그렸다.
- 되돌림 기록은 메모리 안의 목록으로만 그렸다. 실제 엔진은 이것을 로그와 함께 디스크에도
  남겨, 도중에 멎은 트랜잭션을 다시 켤 때 되돌린다.
