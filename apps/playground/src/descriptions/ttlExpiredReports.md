## 수명이 다하면 알려 준다

IP 패킷에는 TTL 이라는 수명이 붙어 있다. 라우터는 패킷을 넘길 때마다 이 수를 1 줄이고, 0 이 되면 그
패킷을 더 넘기지 않고 버린다. 길이 꼬여 빙빙 도는 패킷이 망에 영원히 남지 않게 하려는 장치다. 그런데
라우터는 버리기만 하지 않는다. 보낸 쪽에 "시간 초과" 라는 알림을 돌려보낸다. 이 알림을 거꾸로 쓰면, 보낸
쪽은 제 패킷이 어느 라우터들을 지나가는지 알아낼 수 있다.

### 한 칸씩 더 멀리

보내는 이 `10.0.0.5` 는 목적지 `192.0.2.77` 로 가는 길을 모른다. 그래서 TTL 을 1 로 둔 탐침을 먼저
보낸다. 첫 라우터 R1 이 TTL 을 줄이면 곧바로 0 이 되므로, R1 은 탐침을 버리고 ICMP type 11 code 0(시간
초과)을 돌려보낸다. 이 알림은 R1 의 주소 `10.0.0.1` 에서 온다 — 보낸 쪽은 이렇게 첫 라우터의 주소를 안다.

다음 탐침은 TTL 을 2 로 쥐고 나간다. R1 에서 1 이 되어 살아남고, R2 에서 0 이 되어 R2 의 주소
`172.16.8.1` 로 알림이 온다. TTL 3 은 R3 까지 가서 `198.51.100.1` 을 알려 준다. 탐침마다 한 라우터씩 더
멀리 닿고, 그 자리의 라우터가 제 주소를 실어 돌려보내는 셈이다.

### 목적지에서는 다른 답이 온다

TTL 4 인 탐침은 R1 · R2 · R3 을 지나며 3 · 2 · 1 로 줄어든 채 목적지에 닿는다. 목적지는 패킷을 더
넘기지 않으므로 TTL 을 줄이지 않는다 — 남은 TTL 은 1 이다. 대신 탐침은 아무도 듣고 있지 않은 UDP 포트로
보냈으므로, 목적지는 ICMP type 3 code 3(포트 닿을 수 없음)으로 답한다. 시간 초과가 아닌 이 답이 오면 보낸
쪽은 끝에 닿았음을 알고 멈춘다.

탐침 넷으로 알아낸 길은 `10.0.0.1` · `172.16.8.1` · `198.51.100.1` · `192.0.2.77` 이다. traceroute 가
하는 일이 바로 이것이다.

### 전제

- 탐침은 TTL 마다 **하나**만 보낸다. 실제 traceroute 는 TTL 마다 셋을 보내 응답 시간을 셋 잰다 — 여기서는
  줄였다. 왕복 시간도 다루지 않는다.
- 라우터가 알려 주는 주소는 탐침이 **들어온 쪽** 인터페이스의 주소다. 한 라우터라도 인터페이스마다 주소가
  다르므로, 다른 방향에서 재면 다른 주소가 보일 수 있다.
- 받는 포트는 33434 에서 시작해 탐침마다 1 씩 늘린다. 예로 정한 값이며 traceroute 의 관례값을 따랐다.
- 쓰인 주소는 모두 사설 대역이거나 문서용 대역이다. 실제 기관의 주소가 아니다.
- 실제 망에서는 시간 초과를 보내지 않도록 막아 둔 라우터도 있다. 그런 자리는 traceroute 에 `*` 로 비어
  나온다. 여기서는 모든 라우터가 답한다.
