## 커밋 하나만 가져오면 무엇이 오는가

커밋은 그 순간의 파일 전체를 적어 둔 스냅숏이다. 그러니 다른 브랜치의 커밋 하나를 골라 가져온다고 하면, 그 커밋의
파일을 통째로 들고 오는 일처럼 들린다. 그런데 실제로 건너오는 것은 파일이 아니다. 그 커밋이 **부모와 견주어 바꾼
줄 한 뭉치**다.

{facet:pickOneOut}

### 커밋 다섯, 이름 둘

파일 하나를 두고 커밋 다섯이 있다. 바탕 B 에는 `let name = "app"` 과 `let timeout = 10` 두 줄이 있다.
`main` 은 B 위에 M 을 쌓아 `let port = 80` 을 넣었다. `feature` 는 B 위에 X · Y · Z 를 쌓았다 — X 는
`let retry = 3` 을 넣었고, Y 는 `let timeout = 10` 을 `let timeout = 30` 으로 바꿨고, Z 는 `show name` 을
넣었다. HEAD 는 `main` 에 붙어 있다. `feature` 에서 Y 하나만 `main` 으로 가져온다.

### 네 걸음

처음 모습(걸음 0)을 넣어 네 걸음이다.

0. **처음** — 위에 이력, 아래 왼쪽에 고른 커밋 Y 의 파일(세 줄), 오른쪽에 `main` 의 파일(M 의 세 줄)이 있다.
1. **차이 셈** — Y 를 그 부모 X 와 줄 단위로 견준다. 같은 줄 `let name = "app"` · `let retry = 3` 은 흐려지고,
   바뀐 줄 한 뭉치 −`let timeout = 10` +`let timeout = 30` 에 테두리가 쳐진다. 지운 줄 1, 넣은 줄 1.
2. **얹기** — 그 뭉치만 떼어져 `main` 의 파일로 건너간다. 지울 줄과 글자가 똑같은 `let timeout = 10` 을 찾아 그
   위에 내려앉고, 그 자리에 `let timeout = 30` 이 선다. `main` 의 파일은 `let name = "app"` /
   `let timeout = 30` / `let port = 80` 세 줄이 된다. 왼쪽의 뭉치는 점선으로 남는다 — Y 는 그대로 있다.
3. **새 커밋** — `main` 위에 새 커밋 Y' 가 생기고(부모 M), `main` 이름표가 M 에서 Y' 로 옮긴다.

끝 화면의 `main` 파일에는 `let retry = 3` 이 없고 `show name` 도 없다. `let port = 80` 은 그대로다. Y 앞의 X 가
넣은 줄도, Y 뒤의 Z 가 넣은 줄도 따라오지 않았다. Y 의 스냅숏을 통째로 가져왔다면 `let retry = 3` 이 따라오고
`let port = 80` 이 사라졌을 것이다.

### 명령과 잇기

이것이 `git cherry-pick` 이 하는 일이다. `main` 에서 `git cherry-pick <Y>` 를 하면 git 은 Y 와 그 부모의 차이를
셈해 지금 커밋 위에 적용하고 새 커밋을 만든다. 새 커밋은 부모가 다르니 Y 와 다른 커밋이다 — 이 조각은 그 새
커밋을 Y' 로 부른다. 해시가 어떻게 달라지는지는 다른 조각의 몫이다.

### 이 모형이 뺀 것

- **충돌 없는 얹기.** 여기서는 지울 줄이 대상 파일에 글자 그대로 딱 한 번 있어야 얹히고, 없거나 둘이면 멈춘다. 실제
  git 은 앞뒤 줄의 맥락과 세 갈래 병합(3-way merge)으로 자리를 찾고, 맞지 않으면 충돌로 멈춰 사람에게 묻는다.
  이 데이터는 깨끗이 얹힌다.
- **줄 차이는 가장 긴 공통 부분열(LCS)로 셈한다.** 줄은 앞뒤 빈칸까지 같아야 같은 줄이다. git 의 기본 차이 셈
  (Myers)과 결과가 다를 수 있으나 이 데이터에서는 같다.
- 커밋은 글자로만 부르고 해시를 보이지 않는다. 파일 줄은 어느 언어도 아닌 읽히는 표기로 적었다.
