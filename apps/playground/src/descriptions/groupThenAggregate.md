## 묶어서 하나로 줄인다

`SUM(amount)` 는 표 전체의 합을 한 줄로 돌려준다. 그런데 도시마다 합을 알고 싶으면 합을 여러 번 구해야 한다.
`GROUP BY` 는 그 일을 한 질의로 끝낸다. 줄을 먼저 묶고, 묶음마다 집계 함수를 한 번씩 부른다. 결과에는
묶음마다 한 줄이 남는다. 그렇다면 묶기 전의 줄들은 어디로 가는가.

{facet:groupThenAggregate}

### 모이고, 접힌다

표 `orders` 에는 주문 일곱 줄이 있다. 질의는 이렇다.

```sql
SELECT city, COUNT(*) AS n, SUM(amount) AS total
FROM orders
GROUP BY city
ORDER BY city;
```

그림은 다섯 걸음이다. 걸음 0 은 표와 질의다. 걸음 1 에서 `city` 값이 같은 줄끼리 모여든다 — Busan 은 id 1 · 5,
Daegu 는 id 3 · 7, Seoul 은 id 2 · 4 · 6. 묶는 열쇠는 값이 **같은가** 하나뿐이다. 그다음 세 걸음은 묶음을
하나씩 접는다.

- Busan: 30 + 10 → `n` 2 · `total` 40
- Daegu: 15 + 35 → `n` 2 · `total` 50
- Seoul: 20 + 40 + 30 → `n` 3 · `total` 90

일곱 줄이 세 줄이 된다. 접힌 줄에 남는 것은 묶는 열(`city`)과 집계 값(`COUNT(*)` · `SUM(amount)`)뿐이다.
`id` 나 하나하나의 `amount` 는 결과에 없다 — 한 묶음에 id 가 여럿인데 한 줄에는 하나만 적을 수 있기 때문이다.
그래서 표준 SQL 은 `GROUP BY` 에 없는 열을 집계 함수로 감싸지 않고 `SELECT` 에 두면 받아 주지 않는다.

### 전제

데이터는 예로 정한 일곱 줄이다. 묶음과 결과 줄의 차례는 `ORDER BY city` 가 정한다 — 글자 차례로
Busan · Daegu · Seoul. `ORDER BY` 가 없으면 결과의 줄 차례는 약속되지 않는다. 묶음 안의 줄 차례도 SQL 이
약속하지 않는 것이라, 여기서는 원래 표의 차례(id 차례)로 보였다. 모여드는 걸음과 접히는 걸음은 이해를 돕기
위해 나눈 것이고, 실제 엔진은 정렬이나 해시 표로 한 번에 묶고 집계하기도 한다.
