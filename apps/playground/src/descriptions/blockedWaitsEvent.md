## 잠든 프로세스는 무엇이 깨우는가

프로세스가 디스크를 읽거나 키 입력을 기다리면 CPU 를 쥐고 있을 까닭이 없다. 그래서 운영체제는
그 프로세스를 재운다. 궁금한 것은 그다음이다 — 잠든 프로세스는 언제 다시 일어나는가. CPU 가
비면 일어나는가, 아니면 기다리던 것이 와야 일어나는가.

### 사건마다 따로 선 줄

잠든 프로세스는 한곳에 뭉쳐 있지 않다. **기다리는 사건마다 대기 줄이 따로 있고**, 프로세스는
제가 기다리는 사건의 줄 끝에 선다. 디스크 응답을 기다리는 것은 디스크 줄에, 키 입력을 기다리는
것은 키 입력 줄에 선다.

사건이 도착하면 **그 사건의 줄에서만** 맨 앞 하나가 빠져나와 준비 줄 끝으로 간다. 곧장 CPU 로
가지 않는다 — 준비 줄에 다시 서서 차례를 기다린다. 이 예에서는 준비 줄이 비어 있어 같은 틱에
바로 실행된다.

### CPU 가 비어도 일어나지 않는다

틱 8 에 복사가 끝나면 준비 줄도 CPU 도 빈다. 그래도 편집기는 키 입력 줄에서 움직이지 않는다.
틱 8 과 9, 두 틱 동안 CPU 는 놀고 편집기는 잔다. 키 입력이 틱 10 에 와서야 편집기가 깬다.

편집기는 틱 1 에 잠들어 틱 10 에 깼고(9 틱), 복사는 틱 3 에 잠들어 틱 6 에 깼다(3 틱).
나중에 잠든 쪽이 먼저 깬 것이다. **깨는 차례는 잠든 차례가 아니라 사건이 오는 차례다.**

### 이 그림이 정해 둔 것

- CPU 는 하나이고, 시간은 **틱**으로 센다. 틱 수(CPU 에 쓰는 틱 · 디스크가 응답하기까지 3 틱 ·
  키 입력이 오는 틱 10)는 예로 정한 값이며 실제 기계에서 잰 수가 아니다.
- 빼앗기가 없다. 프로세스는 CPU 할 일을 다 쓰거나 잠들 때만 CPU 를 내놓는다.
- 한 틱에 여러 일이 겹치면 (1) 실행 중인 것이 다음 할 일로 넘어가고 (2) 도착한 사건이 제 줄을
  깨우고 (3) CPU 가 비었으면 준비 줄 맨 앞을 올린다.
- 무언가 일어나는 틱만 걸음이 된다. 일이 없는 틱은 건너뛰고, 그 빈 동안은 위쪽 CPU 띠의
  칠해지지 않은 칸으로 드러난다.
