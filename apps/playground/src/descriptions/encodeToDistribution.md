## 점이 아니라 퍼짐으로 담는다

보통의 오토인코더는 입력 하나를 잠재 공간의 점 하나로 옮긴다. VAE 의 인코더는 그러지 않는다. 입력 하나를
받으면 머리 둘이 따로 수를 낸다 — 한 머리는 그 입력이 놓일 가운데 μ 를, 다른 머리는 그 자리가 얼마나 넓게
번질지 정하는 σ 를. 입력은 점이 아니라 μ 를 가운데로 σ 만큼 퍼진 종 모양으로 담긴다.

{facet:encodeToDistribution}

### 두 머리의 셈

가운데 머리는 입력 칸에 무게를 곱해 더한다: μ = Σ wᵢxᵢ + b. 퍼짐 머리는 σ 를 곧바로 내지 않고 log σ² 를
낸다: log σ² = Σ vᵢxᵢ + b′. 그러면 σ = exp(½ · log σ²) 로 늘 양수가 되어, 머리가 음수를 내도 폭이 뒤집히지
않는다. 교과서의 VAE 가 분산 대신 log σ² 를 내는 까닭이 이것이다.

### 이 예에서

처음 화면을 넣어 걸음 여덟이다. 입력 A · B · C 마다 두 걸음 — 점이 축 위의 μ 에 내려앉는 걸음과, 그 점이
σ 만큼 양옆으로 번지는 걸음이다.

- A [1, 1, 0, 0] → μ −1.50, log σ² −0.20, σ 0.90, μ±σ −2.40 .. −0.60
- B [0, 1, 1, 0] → μ 0.00, log σ² 0.00, σ 1.00, μ±σ −1.00 .. 1.00
- C [0, 0, 1, 1] → μ 1.50, log σ² −0.40, σ 0.82, μ±σ 0.68 .. 2.32

입력마다 폭이 다르다. B 가 번지면 A 와 0.40 만큼 겹치고, C 가 번지면 B 와 0.32 만큼 겹친다.

마지막 걸음은 A 와 B 의 μ 사이 가운데 자리 z = −0.75 를 짚는다. 이 자리는 어느 μ 점과도 같지 않다 — 점으로만
담았다면 어떤 입력도 이 자리를 말하지 않는다. 그런데 퍼짐으로 보면 이 자리는 A 와 B 의 μ±σ 안에 들고, 그
자리에서 정규 밀도는 A 0.313 · B 0.301 · C 0.011 이다. 이웃한 입력 둘의 퍼짐이 사이의 빈 자리를 함께 덮는다.

### 밝혀 둘 전제

- 두 머리의 무게와 치우침은 예로 정한 값이다. 학습한 값이 아니다.
- 잠재 차원을 하나로 줄였다. 실제 VAE 의 잠재 공간은 여러 차원이고 차원마다 μ 와 σ 가 따로 나온다.
- 퍼짐의 폭은 μ±σ 로 그렸다 (±2σ 가 아니다).
- 이 조각은 뽑지 않는다. 퍼짐에서 z 를 하나 뽑아(z = μ + σ·ε) 디코더에 넣는 일은 다른 이야기다.
- 학습도 KL 항도 없다. 학습하면 KL 항이 각 퍼짐을 표준 정규 쪽으로 당겨, 이웃한 입력의 퍼짐이 이렇게 겹치게
  된다.
