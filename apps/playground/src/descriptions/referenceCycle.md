## 순환 참조 — 서로 붙든 채 남는다

참조 계수는 객체마다 **자기를 가리키는 것이 몇인가**를 센다. 이름 칸이든 다른 객체의 필드든, 가리킴 하나가 1 이다. 수가 0 이 되면 아무도 그 객체에 닿을 수 없으니 치운다. 그런데 두 객체가 **서로를** 가리키면, 이름이 모두 놓아도 서로에게 받은 1 이 남는다. 수는 0 에 닿지 않고, 두 객체는 치워지지 않는다.

{facet:referenceCycle}

### 무엇을 보나

- 가리킴 하나가 **화살 하나**이고, 객체 밑의 **표 하나**다. 오른쪽 위 동그라미의 수는 그 표의 개수다. 이름이 가리키는 화살과 표, 필드가 가리키는 화살과 표는 색이 다르다.
- `let a = new Node()` · `let b = new Node()` — 객체 `A` · `B` 가 생기고 이름 `a` · `b` 가 하나씩 가리킨다. 수는 1 · 1.
- `a.next = b` — `A` 의 필드 `next` 에서 화살이 `B` 로 자라고, 표 `A.next` 가 건너가 `B` 의 수가 2 가 된다. `b.next = a` 로 `A` 도 2.
- `a = null` — 이름 `a` 의 화살이 거둬지고 표 `a` 가 칸으로 돌아간다. `A` 의 수는 1. 이제 `A` 를 가리키는 이름은 없지만, 상자 밑에는 `B.next` 의 표 하나가 남아 있다.
- `b = null` — `B` 에서도 표 `b` 가 빠진다. 끝에는 객체를 가리키는 이름이 0 개인데, 두 객체는 수 1 · 1 로 서로의 화살을 붙든 채 남는다. 치운 객체는 0 개다.

### 요점은 "0 에 닿는 걸음이 오지 않는다" 이다

- 참조 계수는 수가 0 이 되는 **그 순간**에만 치운다. 여기서는 수가 2 에서 1 로 내려간 뒤 더 내려갈 까닭이 없다 — 남은 1 을 준 것이 바로 치워져야 할 상대 객체이기 때문이다.
- 프로그램은 이 두 객체에 다시 닿을 길이 없다. 쓸 수 없는데 자리는 차지하고 있다.
- 뿌리에서 닿는 것만 남기는 **추적 수거**는 이 둘을 치운다 — 가리킴의 수를 세지 않고, 이름(뿌리)에서 출발해 닿는가만 보기 때문이다. 그 수거는 뿌리에서 표시가 번지는 조각이 따로 보인다. 참조 계수를 쓰는 환경은 이 빈틈을 따로 메운다 — 한쪽 가리킴을 수에 넣지 않는 약한 참조를 쓰거나, 순환만 찾아 치우는 수거를 곁들인다.

### 전제

- 코드는 어느 언어도 아닌 읽히는 표기다. `Node` 는 필드 `next` 하나를 가진 객체이고, `next` 의 처음 값은 `null` 이다. 클래스 정의 줄은 주장 밖이라 화면에 두지 않았다.
- 수를 세는 규약 — 이름 칸이나 필드가 객체를 가리키게 되면 +1, 가리키던 것을 놓으면 −1. 새 값을 먼저 올리고 옛 값을 내린다. 줄이 끝났을 때 수가 0 인 객체를 치운다.

### 걸음

시작 · `let a = new Node()` · `let b = new Node()` · `a.next = b` · `b.next = a` · `a = null` · `b = null` — 일곱 걸음. 수는 `A` 1 → 2 → 1, `B` 1 → 2 → 1 로 움직이고, 치움 걸음은 한 번도 오지 않는다. 마지막 걸음이 곧 끝의 모습이다.
