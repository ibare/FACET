# 누가 고쳤는지는 조상이 안다

두 사람이 한 파일을 가져가 따로 고쳤다. 합치려면 줄마다 "누가 고쳤나" 를 알아야 한다 — 고친 쪽의 줄을
받아들이면 되기 때문이다. 그런데 **고친 뒤의 두 벌만 놓고는 그것을 알 수 없다.** 갈라지기 전의 파일,
공통 조상이 있어야 판정이 선다.

## 두 벌만 보면

우리 쪽(ours)과 그쪽(theirs)은 둘 다 다섯 줄이다.

| 줄 | 우리 쪽 | 그쪽 |
| --- | --- | --- |
| 1 | `let w = 4` | `let w = 4` |
| 2 | `let h = 5` | `let h = 2` |
| 3 | `let area = w * h` | `let area = w * h` |
| 4 | `show w` | `show area` |
| 5 | `show area` | `show h` |

두 벌을 줄 단위로 견주면 다른 자리가 셋 나온다 — 2 줄의 `let h` 값, 우리 쪽에만 있는 `show w`, 그쪽에만
있는 `show h`. 하지만 자리마다 이야기가 둘이다. `show w` 는 "우리가 넣었다" 로도, "그쪽이 지웠다" 로도
읽힌다. `let h = 5` 와 `let h = 2` 도 어느 쪽이 원래 값인지 모른다. 이 걸음에서 화면의 자리마다 물음표가
양쪽에 하나씩 서는 것이 그 뜻이다.

## 조상이 들어오면

조상(base) 은 `let w = 4` · `let h = 2` · `let area = w * h` · `show w` · `show area` 다섯 줄이다. 이제 자리마다
세 벌을 견준다. **조상과 같은 쪽은 손대지 않은 쪽이고, 다른 쪽이 고친 쪽이다.**

- 2 줄: 조상 `let h = 2` 는 그쪽과 같다 → 우리 쪽이 고쳤다 (바꿈)
- `show w`: 조상에 있고 우리 쪽에도 있다 → 그쪽이 고쳤다 (지움)
- `show h`: 조상에도 우리 쪽에도 없다 → 그쪽이 고쳤다 (넣음)

끝에는 우리 쪽이 고친 자리 1, 그쪽이 고친 자리 2, 판정 못 한 자리 0 이 남는다. 이 조각은 판정까지만 한다 —
판정대로 줄을 옮겨 담아 병합 결과를 만드는 일은 다음 이야기다.

재생은 처음 화면을 넣어 **여섯 걸음**이다. 처음 화면 · 두 벌 견주기 · 조상 들어옴 · 자리 셋의 판정.

## 전제

- 비교는 **줄 단위, 글자 그대로**다. 앞의 빈칸도 줄의 글자이고, 비슷한 줄을 짝으로 치지 않는다. 그래서
  "바꿈" 은 줄 하나를 지우고 하나를 넣은 것과 같다 — 여기서는 조상과 고친 쪽에 모두 줄이 있는 자리를 바꿈이라
  부를 뿐이다.
- 두 벌의 다른 자리는 최장 공통 부분 수열을 따라 앞에서부터 걷는 diff 로 찾는다.
- 조상과의 판정은 3-way 병합(diff3)의 덩이 나누기를 단순화한 것이다. 조상의 줄 가운데 두 쪽 모두와 짝이
  지어진 줄을 기준으로 덩이를 나누고, 덩이마다 조상과 같은 쪽을 가린다. git 의 병합(xdiff)은 세부가 다르다 —
  예를 들어 두 쪽이 서로 붙어 있는 줄을 고치면 git 은 그것도 충돌로 본다.
- 두 쪽이 **같은 자리를 서로 다르게** 고치면 조상과 같은 쪽이 없어 판정이 서지 않는다. 그것이 충돌이며,
  이 조각의 데이터에는 그런 자리가 없다.
- 실제 도구에서 조상은 두 브랜치의 병합 기준 커밋(merge base)에 있는 파일이다. 그 커밋을 찾는 일은 이
  조각이 다루지 않는다.
