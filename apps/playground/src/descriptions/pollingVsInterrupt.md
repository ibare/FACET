# 폴링과 인터럽트

{facet:pollingVsInterrupt}

장치가 언제 일을 끝낼지 CPU 는 미리 알 수 없다. 기다리는 길은 둘이다. 틱마다 장치에게 "준비됐나?" 하고 묻는 것(폴링)과,
제 일을 하다가 장치가 부를 때 들어가는 것(인터럽트)이다.

그림은 같은 장치 · 같은 준비 시각을 두고 두 CPU 를 나란히 돌린다. 한 걸음이 한 틱이고, 틱마다 두 기둥에 한 칸씩 쌓인다.
같은 높이의 칸은 같은 틱이다.

- 장치는 틱 0 에 일을 시작해 틱 7 부터 준비됨이 보인다.
- 폴링 CPU 는 틱 0 부터 6 까지 일곱 번 "아니오" 를 듣고, 틱 7 에 여덟 번째로 물어 "예" 를 듣는다. 틱 8 에 데이터를 받아 가고 t = 9 에 끝난다.
- 인터럽트 CPU 는 틱 0 부터 6 까지 딴 일을 일곱 틱 한다. 틱 7 에 불려 처리기로 들어가는 데 한 틱을 쓰고, 틱 8 에 받아 가 역시 t = 9 에 끝난다.

두 쪽이 데이터를 받아 가는 틱은 같다. 달라진 것은 그 앞에 쌓인 것이다 — 한쪽은 묻기 여덟, 다른 쪽은 딴 일 일곱과 들어가기 하나.
들어가기 한 틱은 인터럽트가 치르는 값이라 공짜로 그리지 않았다. 장치가 금방 준비되는 경우라면 이 값이 묻기 몇 번보다 비쌀 수 있다.

전제: 틱은 설명을 위해 정한 단위다. 묻기 하나 · 딴 일 하나 · 들어가기 · 받아 가기가 각각 한 틱이라고 두었고, 실제 나노초를 흉내 내지 않는다.
부름은 명령 경계에서 받는데, 여기서는 딴 일이 한 틱 단위라 준비되는 틱이 곧 경계다.
