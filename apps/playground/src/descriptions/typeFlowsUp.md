# 타입이 식을 타고 오른다

`let` 에 타입을 적지 않으면 컴파일러는 그 이름의 타입을 어디서 얻을까. 답은 오른쪽의 식이다. 컴파일러는 식의
맨 아래 잎부터 타입을 정하고, 그 타입들을 연산마다 규칙으로 합치며 한 칸씩 위로 올린다. 뿌리에 닿은 타입이 이름의
타입이 된다.

{facet:typeFlowsUp}

## 무엇을 보는가

프로그램은 세 줄이고 어디에도 타입이 적혀 있지 않다.

```
let count = 4
let price = 2.5
let big = count * 3 + price > 10
```

줄 셋이 맨 아래에 나란히 놓이고, 연산자 글자마다 그 위로 노드가 서서 식의 나무가 위로 자란다. 맨 위 띠가 이름 표다.
처음 화면(걸음 0)을 넣어 모두 13 걸음이다.

- L1 · L2 — 값 글자 `4` 는 int, `2.5` 는 float 다. 잎 하나짜리 식이라 그 타입이 곧장 이름 표까지 올라 `count` 와
  `price` 에 붙는다.
- L3 — 식의 노드는 일곱이다(잎 넷 · 연산 셋). 왼쪽 아이 → 오른쪽 아이 → 자기 차례로 밟는다. 이름 잎 `count` 와
  `price` 는 앞 줄이 이름 표에 올려 둔 타입을 읽는다.
  - `count * 3` — int 와 int 가 만나 int. 타입이 그대로 오른다.
  - `+ price` — int 와 float 가 만나 float. 오르는 도중 int 가 float 로 넓혀진다.
  - `> 10` — float 와 int 를 견주면 bool. 두 아이 어디에도 없던 타입이 나온다.
  - 뿌리의 bool 이 이름 `big` 으로 올라가 붙는다.

연산 셋을 지나며 타입은 int → float → bool 로 두 번 바뀐다. 끝의 이름 표는 `count` int · `price` float · `big` bool 이다.

## 값은 셈하지 않는다

화면에는 `4 * 3` 이 얼마인지, `big` 이 참인지가 뜨지 않는다. 컴파일러는 프로그램을 돌리지 않고 글을 한 번 읽을 뿐이다.
오르는 것은 타입뿐이다. 끝나는 것도 프로그램이 아니라 추론이다.

## 전제

여기의 타입 규칙은 이 조각의 장난감 언어가 정한 것이다. 정적 타입 언어의 흔한 모양(자바 · C# 에 가깝다)을 따랐다.

- `+` `-` `*` 는 int 끼리면 int, 한쪽이라도 float 면 float 다. int 가 float 로 넓혀지는 것은 이 자리뿐이다.
- 크기 견줌(`<` `>` 따위)은 수끼리 받아 bool 을 낸다.
- bool 은 수가 아니다.

실제 언어는 저마다 다르다. 자바스크립트 · 파이썬은 bool 을 수처럼 더하고, C 는 float 를 int 로 조용히 좁힌다.
타입을 적지 않고 오른쪽에서 얻는 방식은 여러 언어에 있다 — 자바 · C# 의 `var`, C++ 의 `auto`, 러스트 · 코틀린 · 스위프트의 `let` · `val`.
