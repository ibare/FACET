# 토큰화 조각 여섯 — 배치 기록

2026-09-12. `facets/ai-engineering/` 의 첫 facet 묶음이다.

규범은 `tasks/piece-batch-protocol.md` 와 `rules/specifics/S-piece.md` 에 있다.

## 만든 것

| 조각 | 주장 | origin |
| --- | --- | --- |
| `between-letter-and-word` | 낱말도 글자도 아닌 크기로 자른다 | subword-segmentation |
| `merge-the-frequent-pair` | 가장 많이 붙은 짝을 하나로 합친다 | bpe-training |
| `unknown-becomes-known` | 아는 조각으로 쪼개어 받아 낸다 | vocabulary |
| `space-is-part-of-it` | 띄어쓰기가 조각에 붙어 다닌다 | subword-segmentation |
| `tokens-per-language` | 같은 뜻인데 조각 수가 몇 배 차이 난다 | vocabulary |
| `boundary-shift` | 자른 자리가 달라지면 뜻이 흔들린다 | subword-segmentation |

## 계측

```
평균 코드 유사도   0.19   (임계 ≤ 0.35)
최고 코드 유사도   0.33   (임계 ≤ 0.50)  between-letter-and-word ↔ unknown-becomes-known
최고 좌표 겹침     0.24   (임계 ≤ 0.60)  between-letter-and-word ↔ boundary-shift
그림 어휘          4종    (임계 ≥ 5종)   [rect text g line]      ← FAIL
운동 있는 조각     6/6    (임계 ≥ 70%)
```

**어휘 한 항목만 미달이고 나머지 셋은 저장소 최저 축이다.** 골격 복제가 아니다 —
rule-guard 가 근거 셋을 들어 소재의 수렴으로 판정했다. 골격이 실제로 다르고(나란한
세 띠 · 네 줄과 이음매 · 세로 3층 · 문장과 선반의 짝맞춤 · 다섯 줄의 오른쪽 뻗음 ·
2레인 벌어짐), 동사가 갈렸으며(갈라진다 · 닫힌다 · 맞물린다 · 미끄러진다 · 밀려난다 ·
부서진다), **곡선 0건은 소재가 정한다** — 토큰은 상자에 담긴 부분문자열이라
`circle`/`path` 가 뜻을 지지 않는 장식이 된다.

**고치지 않았다.** 넷이 아직 도는 중에 "어휘를 넓혀라" 를 보내면 같은 지시를 받은
넷이 같은 어휘를 쓰게 되어 호스트가 새 관성의 원천이 된다. 앞 배치에서 운동
1/4 FAIL 을 만났을 때도 같은 판단을 했고 다음 배치가 5/5 로 뒤집혔다.

### 다음 배치에 남길 경계 — rule-guard 가 짚었다

여섯이 공유하는 진짜 관용구는 그림씨가 아니라 **"글자를 담은 타일을 한 줄로
늘어놓기"** 다. 토큰이 곧 상자에 담긴 부분문자열이라 지금은 정당하지만, 이 도메인의
다음 조각들(임베딩 · 검색 · 디코딩)까지 같은 타일 띠로 가면 **도메인 전체가 한
그림으로 읽히기 시작한다.** 그쪽 소재는 벡터 · 분포 · 연결 강도라 곡선과 농담이
본디 필요하므로, 어휘를 넓힐 자리는 이번 여섯이 아니라 거기다.

## 호스트가 틀린 것 — **새로운 종류다**

앞 배치들의 사양 결함은 **값이 틀린 것**이었다(비트 폭의 합이 주소 폭과 안 맞음,
나노초가 한 클럭에서 안 나옴, "네 번" 이 다섯 번). 이번 것은 다르다 —
**값은 전부 맞고, 그 값을 재현하는 규약이 빠졌다.**

BPE 는 같은 말뭉치에서도 규약에 따라 다른 어휘를 낸다. 셋을 안 적었다.

| 빠진 규약 | 안 지키면 |
| --- | --- |
| 낱말 끝 표식 `</w>` 를 **독립 기호로** 붙인다 | 26 병합에서 9 가 아니라 **7조각** |
| 짝 빈도가 같으면 **사전순** 앞선 짝 | `id` 가 12 가 아니라 **13** |
| 자르는 것은 어휘 목록이 아니라 **병합 규칙 열을 배운 차례대로 재적용** | `ai` 가 죽어 역시 어긋남 |

**서로 못 보는 셋이 각각 다른 자리에서 걸렸다.** `between-letter-and-word` 가
끝표식을, `tokens-per-language` 가 동점과 재적용을 실측으로 갈라 확정했고,
`boundary-shift` 는 호스트의 보충이 닿기 전에 끝표식을 스스로 잡았다.

한 에이전트가 한 문장으로 정리했다 — **어휘 목록은 표시용 산물이고 자르는 것은
규칙 열이다.** `space-is-part-of-it` 에서 `nd` 가 선반 열넷에 없던 것도 같은
뿌리였다(그것은 `▁and` 를 만드는 도중에 한 번 쓰이고 만 중간 조각이다).

이 결함은 **검사도 감사도 원리적으로 못 본다.** 화면에 뜨는 수가 사양과 다를 뿐
그 자체로는 멀쩡하기 때문이다. 매번 잡은 것은 **사양대로 만들어 보고 대조한
사람**이었다.

### 프로토콜에 올렸다

`piece-batch-protocol.md` 의 "화면에 뜰 값은 호스트가 계산해 넘긴다" 아래에
**"값과 함께 그 값에 이르는 규약을 준다"** 를 세웠다.

## 실측에 일곱 번 걸렸다

토큰화는 **지어내기 가장 쉬운 소재**다. 로컬에 토크나이저가 하나도 없어서
(tiktoken · transformers · sentencepiece · gpt-tokenizer 전부 부재) "GPT 는
한국어가 영어의 몇 배" 같은 수는 전부 날조가 됐을 것이다. BPE 를 직접 구현해
돌린 값만 썼고, 그 과정에서 호스트가 여섯 번 틀렸다.

| | |
| --- | --- |
| 동률 | 교과서 예시 말뭉치가 첫 걸음에 **1등이 셋**이라 "가장 많이 붙은 짝" 의 근거가 사라진다. 117,128 조합을 훑어 동률 0 을 찾았다 |
| 병합 횟수 | 끝까지 돌리면 낱말이 통째로 어휘에 들어가 **조각 수 = 낱말 수**가 된다. "사이" 가 사라진다 |
| 어간 부재 | `warmness` 를 아는 조각으로 쪼개려면 `warm` 이 어휘에 있어야 하는데 말뭉치에 넣지 않고 시험했다. 0/6 |
| 지어낸 낱말 | 경계 이동 쌍에 `bane` · `hane` 을 넣었다 — **영어 낱말이 아니다** |
| `.size` | 배열에 `.size` 를 써 "짝 종류" 가 전부 `undefined` |
| 예산 손잡이 | 최종 조각만 어휘에 넣고 중간 산물을 빼 **어떤 병합도 통과 못 하게** 만들어 놓고 "손잡이가 약하다" 고 판정할 뻔했다 |

마지막 것이 가장 위험했다. 프로토콜이 "안 나오면 내 코드부터 의심한다" 고 **두 번
데인 것을 기록해 둔 자리**였고, 고치니 34 → 6 조각으로 멀쩡히 갈렸다.

## 에이전트가 스스로 잡은 것

- **`boundary-shift` 가 동점 규칙을 검증할 수 없다고 밝혔다.** 여섯 가름법
  (처음 · 나중 · 사전순 · 역순 · 길이순 · 짧은순)을 전부 돌렸더니 26회 뒤 아홉
  낱말의 분할이 **모두 같았다.** 재현성은 저작 결정이라 사전순으로 못박되,
  "이 조각은 그 규칙의 대조 표본이 되지 못한다" 고 적었다. **지켰다고만 하지 않았다.**
- **`unknown-becomes-known` 이 정규식의 온폭 글자 리터럴을 스스로 고쳤다.**
  호스트가 수리 목록에 올려 둔 것을 `\u` 부호 표기로 바꾸고 여섯 소스에 잔존
  0건을 확인했다. 앞 배치에서 `byte-order` 가 걸렸던 바로 그 자리다.
- **`space-is-part-of-it` 이 사양의 모순을 지어내지 않고 그렸다.** 어휘 열넷과
  `and → a · nd` 가 어긋나는 것을 보고, 선반에는 열넷만 세우고 `and` 는 "통째로
  남지 못한다" 로만 갈라 **화면이 `nd` 가 어휘에 있다고 주장하지 않게** 했다.
- **`tokens-per-language` 가 `done` 에서 상수를 걷어냈다.** projector 에 `'en'` 을
  두었다가 선언에 이미 `baseCode` 가 있어 두 벌이 되는 것을 보고 발신에 실었다.
- **`merge-the-frequent-pair` 가 병합 규칙 목록을 화면에서 뺐다.** 값을 그림에서
  떼어 옆 계기로 날리는 몸짓이 되고(S-piece PREFER), 최종 네 줄 자체가 곧 어휘다.

## rule-guard — 위반 하나, 갈림 셋

**C8 하나**(5:1) — `tokens-per-language` 가 `waitForInput` 루프의 앞 검사를 루프
**밖**에 두어 `continue` 경로를 안 덮었다. C8 이 "예시를 베낀 쪽과 본문을 읽은 쪽이
갈렸다" 며 문면을 좁힌 바로 그 자리다. 고쳤다.

**표본 재기 지시가 또 작동했다.** 통일 권고 둘이 저장소 전체 비율과 함께 왔다.

| 갈린 자리 | 배치 안 | 저장소 전체 | 판정 |
| --- | --- | --- | --- |
| projector 가 stage 를 옵셔널로 부르는가 | 4:1:1 | 170:87 | **손대지 않음** — 고쳐도 저장소가 정리되지 않는다 |
| translator fallback | 5:1 | **217:3** | **고침** — 소수 쪽이 압도적으로 얇다 |
| `destroy()` 의 회수 수단 | 3:3 | — | S-piece 가 둘 다 명시. 갈림도 아니다 |

**권고 둘도 받았다.** `unknown-becomes-known` 의 ko 문안 다섯이 `"{word}" 는` 꼴로
**낱말 뒤에 조사**를 달고 있었다 — S-piece 의 MUST 는 문면상 *수*에 한정되지만
위험은 같고, 지금 데이터가 모두 모음으로 끝나 **우연히 맞을 뿐**이었다. 죽은
translator 두 줄과 `void t;` 도 걷어내고 표식을 이름 붙인 상수로 올렸다.

이 세션이 모은 "못 보는 것" 목록에 `{line}` 에 들어간 칸 번호와 같은 줄이 하나 더
붙는 셈이다 — **데이터가 우연히 맞아 드러나지 않는다.**

## 호스트의 도구가 또 틀렸다

셸 인용이 **세 번** 깨졌다 — `--include=*.md` 가 zsh glob 에 걸리고, `['\"]` 가
단어 분리되고, `node -e '...'` 안의 작은따옴표가 바깥 인용과 충돌했다. 이 세션이
앞서 겪은 "텍스트를 구조로 착각한" 셋과 결이 다르다. 그쪽은 **읽는 방식**이
틀렸고 이쪽은 **넘기는 방식**이 틀렸다.

`catalog.json` 편집은 앞 배치의 사고를 되풀이하지 않으려 **쓴 뒤 디스크를 다시
읽어** 검증했다. +12/−6 으로 여섯 항목에 한 줄씩만 붙고 다른 줄은 흔들리지 않았다.
