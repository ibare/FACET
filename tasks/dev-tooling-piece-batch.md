## 호스트가 수를 틀렸다

카탈로그의 조각을 "서른일곱" 으로 셌다가 등록 때 디렉터리가 서른셋인 것을 보고서야 바로잡았다 — 7 + 8 + 6 + 6 + 6 이다.
사용자에게도 한동안 틀린 수를 알렸다. 수는 손으로 세지 않고 카탈로그에서 센다(`state.md` 첫 줄을 스크립트로 채울 것).

## 사양에서 호스트가 정한 것

- **표기**: 파일 줄 · 테스트 대상 코드는 pseudo-notation. 특정 도구의 표기가 곧 주장인 자리(unified diff 의 `-`/`+`, 충돌 표식,
  semver 범위 `^` · `~`, 커밋 해시)는 `@notation native`. `piece-check` 의 표기 검사는 버전 문자열을 잡지 않는다.
- **장난감 해시**: 해시를 보이는 조각은 FNV-1a 32 비트 앞 일곱 자리 — git 의 SHA-1 대신이라는 것은 설명 글이 밝힌다.
- **stage 가 같은 조각의 algorithm export 를 부르는 것**: 세 조각이 `principles.md` 1 절("View 는 Algorithm 을 참조하지 않는다")과
  계약 카드("바탕에서 결정되는 셈은 같은 함수를 부른다")가 어긋난다고 물었다. 카드가 이긴다 — 원칙은 packages 의 범용 View 를 두고 한
  말이다. 공통 안내문에 덧붙여 뒤 조각은 묻지 않았다.

## 감사가 잡은 것

지적의 대부분은 **C6 — 모르는 것을 조용히 넘김**이었다. 조각 서른셋 중 열다섯이 한 자리 이상 걸렸다.

| 꼴 | 예 |
| --- | --- |
| scene `reduce` 의 `default: return scene` | 모르는 이벤트가 변화 없는 걸음 하나를 더 만든다 |
| 이벤트가 가리키는 커밋 · 줄 · 자리를 바탕과 대조하지 않음 | 없는 커밋의 표시가 그리기에서 조용히 사라진다 |
| stage 운동 함수의 `if (!x) return` | 손잡이를 못 찾으면 운동만 빠진 화면 |
| `?? 0` · `?? ''` · `findIndex` −1 | 캡션에 "멈춘 줄: 0" 같은 지어낸 수 |

`piece-check` 의 정적 검사도 `piece-self-check` 도 이 꼴을 못 잡는다 — 감사만 잡았다. 계약 카드 scene 절에 한 줄로 올렸다.
공통 안내문에 중간에 덧붙인 뒤로 나온 조각(이력 · 차이 쪽)도 여전히 걸렸다 — 안내문 한 줄로는 덜 먹힌다.

**설명 글의 도구 사실**이 둘째로 많았다. 대부분 사양이 아니라 조각이 스스로 쓴 문장이었다.

- make 가 고리를 만나면 "멈춘다" — 실제로는 화살 하나를 버리고 경고한 뒤 계속 세운다(ninja · Bazel 은 멈춘다)
- "실제 도구는 잠긴 줄을 새로 푼다" — `npm install` 은 풀고 `npm ci` · `--frozen-lockfile` 은 멈춘다
- Node 의 모듈 찾기가 "뿌리 폴더까지" — 파일 시스템 맨 위까지 오르고 전역 폴더도 본다
- 구문 커버리지를 줄 단위로 정의 — 문 단위다(줄 커버리지와 다르다)
- MC/DC 를 "조건 · 결정 커버리지" 로 — **변형** 조건 · 결정 커버리지다. 뿌리는 호스트가 준 사양의 "개념" 줄이었다

그 밖에: 셈하지 않은 결론을 박은 걸음 0 캡션 하나(`timestamp-vs-fingerprint`), 같은 길을 두 번 그린 점선 하나(`fast-forward`).
