# 조각(piece) facet — 실험 경위와 판정

작성 2026-09-07 · 커밋 `39f1aca`(분석) ~ `1ef1180`(서명 조각) 구간

facet 이 콘텐츠에 붙을 자리가 없다는 문제에서 출발해, 두 가지 방식을 차례로
시험하고 하나를 폐기한 기록. 결론은 `rules/specifics/S-piece.md` 로 옮겼고
이 문서는 **왜 그 결론에 이르렀는지**를 남긴다.

---

## 1. 문제

호스트 커리큘럼(샘플)에 facet 을 붙여 보니 붙을 자리가 예상보다 적었다. 한
샘플 기준으로 노드 28칸 중 10칸만 채워졌고, 그 트리에 해당하는 facet 은 19종
중 7종뿐이었다.

첫 진단은 "facet 조각이 너무 크다" 였다. 연결 리스트 facet 하나가 노드 구조 ·
참조 연결 · 순회 · 삽입/삭제를 전부 담고 있어, 어느 한 칸에 붙이면 나머지 칸에
대해서도 이미 답을 해버린다.

> **주의** — 그 커리큘럼 트리는 파이프라인이 학습자 요청에 따라 비결정적으로
> 생성한 샘플 하나다. FACET 은 커리큘럼과 종속 관계가 없으므로 그 트리의 형태를
> 명세로 삼아서는 안 된다. 실제로 실험 도중 그쪽으로 기울어 한 번 바로잡았다.

## 2. 첫 시도 — 발췌 (폐기)

`concept-types.ts` 가 예고해 둔 `aspects` ("canonical 1 + aspect N") 를 채웠다.
같은 algorithm · projector · stage view 를 공유하고 `initialData` 와 `layout` 만
좁힌 facet 15종을 자료구조 5종에 붙였다.

**선언만으로 만들어진다는 점이 장점처럼 보였는데, 그것이 바로 한계였다.**

| 판정 | 내용 |
| --- | --- |
| 정지 조각 | 움직임이 없으니 그림 한 장이다. SVG 를 렌더할 이유가 없다 |
| 움직이는 조각 | canonical 과 다를 바 없다. 같은 파이프라인에 작은 입력을 넣은 것뿐 |

근본 원인은 **축척이 그대로**라는 데 있었다. `-node` 는 "노드를 확대한 그림" 이
아니라 "노드가 1개인 연결 리스트" 였다. 같은 stage view, 같은 좌표계, 같은 카드
크기 — 데이터만 작다. 명세를 부모에게서 물려받으면 그림도 물려받는다.

여기서 두 가지가 따라 나왔다.

- **선언만으로 되는 일은 데이터 축소뿐이고, 데이터 축소는 설명이 되지 않는다.**
  설명이 되려면 다른 시각 표현이 필요하고 그것은 코드다 — 즉 신규와 같은 비용이다.
- 커리큘럼 한 칸이 비어 있던 것은 facet 이 커서가 아니라 **그 칸이 다른 그림을
  요구**하기 때문이었다. 하나를 넷으로 나눠도 넷이 되지 않는다.

관련 커밋: `11378b1`(시험) → `60226b7`(폐기). `autoDemoSequence` 와
`FacetJson.autoStart` 는 발췌와 무관한 개선이라 남겼다.

## 3. 방향 전환 — 무엇이 쪼개기의 기준인가

쪼개기 자체는 필요하다. 문제는 **기준**이었고, 답은 "맥락" 이다.

학습 맥락이 없는 조각은 쓸모가 없다. 맥락이 곧 그림의 명세이기 때문이다 —
"노드는 값 하나와 참조 하나를 담는다" 는 맥락이 있으면 축척(노드 하나가 화면을
채울 만큼) · 라벨(value/next) · 움직임(참조가 어디를 가리키는지)이 저절로
결정된다. 맥락 없이 만들면 참조할 것이 부모밖에 없다.

이로부터 조각의 정의가 바뀌었다.

- **작다 = 데이터가 적다** (X)
- **작다 = 말하는 것이 하나다** (O)

그리고 **레고 조립은 폐기했다.** 자료구조 시각화의 조각은 상태를 공유하고 문맥에
의존해서, 원자를 모아 완제품을 만드는 모델이 성립하지 않는다. 공유는 제작 측이
아니라 **소비 측**에서 일어난다 — 조각 하나를 여러 주제의 글이 가리킨다.

## 4. 두 번째 시도 — 조각 (채택)

한 번도 만들지 않은 영역(암호학적 해시)에서 맥락을 도출해, 물려받을 축소 대상이
없는 상태로 시험했다. 조각은 독립 facet 이며 기존 개념과 같은 단위다.

해시에서 12개 맥락을 뽑아 잣대("그림 없이 이해시킬 수 있는가")를 적용해 7개를
남겼고, 서명에서 2개를 더했다.

| 조각 | 답하는 질문 |
| --- | --- |
| `hashFixedLength` | 한 글자를 넣든 파일을 넣든 왜 결과 길이가 같은가 |
| `hashAvalanche` | 한 글자만 바꿨는데 왜 전혀 달라지는가 |
| `pigeonholeCollision` | 충돌은 왜 반드시 존재하는가 |
| `hashIntegrityCheck` | 받은 파일이 원본 그대로인지 어떻게 아는가 |
| `hashSalt` | 같은 비밀번호를 쓴 두 사람이 왜 다르게 저장되는가 |
| `hashChain` | 지난 기록을 몰래 고치면 왜 들통나는가 |
| `merkleTree` | 무엇이 바뀌었는지 전부 다시 읽지 않고 어떻게 찾는가 |
| `signatureKeyDirection` | 같은 키 쌍인데 왜 방향이 반대인가 |
| `signatureOnHash` | 왜 문서 전체가 아니라 해시에 서명하는가 |

**해시 한 덩어리에서 7개** — "덩어리마다 몇 개인가" 의 첫 실측이다.

## 5. 만들면서 드러난 것

### 조각은 reactive 여야 한다

처음에는 "한 번 재생하고 끝나니 coroutine 이 자연스럽다" 고 판단했는데 틀렸다.
컨트롤바 없는 조각이 필요로 하는 두 가지를 reactive 만 준다 — mount 시 스스로
시작(`ensureStarted`)과 걸음 간격을 스스로 정하기(`ctx.sleep`). coroutine 은
`BASE_DELAY_MS` 100ms 고정이고 속도 조정이 speed-slider 로만 가능하다.

부수적으로 `FacetJson.autoStart` 는 조각에 불필요해졌다. 다만 완결형 coroutine
facet 을 글에 박을 때는 여전히 필요해 남겼다.

### 규범을 두 번 고쳤다

- **"조작 없음" → "필수 조작 없음"** — 다시 보기는 있어야 한다. 격자가 물드는
  운동 자체가 메시지인데 최종 상태만 남으면 놓친 사람이 되돌릴 길이 없다.
  "눌러야 완성되는 것" 과 "놓쳤을 때 되돌리는 것" 은 다르다.
- **캔버스 폭 480 → 620** — playground 컨테이너가 아니라 글의 문단 폭에 맞춰야
  한다. viewBox SVG 는 늘리면 글자까지 커지므로 상한은 유지하되 값을 올렸다.

### 조각이 짧을수록 전제를 감추기 쉽다

비둘기집 조각에서 드러났다. 16칸을 하나씩 채우는 입력 16개는 내가 고른 것이고
무작위로는 백만분의 1 확률이다(실제로는 여섯 번째쯤 겹친다). 감추면 화면이
"해시는 고르게 퍼진다" 는 거짓을 말하게 된다.

그런데 이것은 **고칠 결함이 아니라 밝힐 전제**였다. 비둘기집 원리의 정확한
서술이 "아무리 고르게 나눠도" 이므로, 최선의 경우를 보이고 그 사실을 밝히면
논증이 오히려 강해진다. 그래서 각주가 규범이 되었다.

### 시각 부품은 하나도 공유되지 않았다

조각 아홉이 `el()` 헬퍼와 design-tokens 를 빼면 겹치는 코드가 없다. 표본
아홉이면 말할 수 있다 — **조각은 각자 다른 그림을 요구하고, 공유 view 를 미리
만들지 않은 판단이 옳았다.**

대신 겹침은 다른 층에서 나타났다. `contrastWith` 가 조각들을 엮고,
`hashChain` ↔ `merkleTree` 는 "같은 재료, 반대 모양" 이라는 짝을 이룬다.
**조각끼리의 관계는 코드가 아니라 개념 층에서 자란다.**

시각 어휘는 공유해야 한다는 것도 드러났다. `signatureKeyDirection` 은 RSA facet 과
코드를 공유하지 않으면서 자물쇠·열쇠 어휘를 맞췄다. 부품이 아니라 어휘다.

## 6. 남은 것

- **출처와 소속** — 조각은 소속이 N개지만 출처는 하나다. 디렉터리와 playground
  배치는 출처를 뜻한다. `signatureOnHash` 가 첫 사례(해시를 쓰지만 서명 출처)다.
  조각이 늘면 이 구분을 코드 필드로 둘 필요가 생길지 다시 볼 것.
- **뷰포트 진입 시 재생** — 글에 조각이 여럿 박히면 전부 mount 시점에 재생되고
  끝난다. 독자가 도달했을 때는 정지 화면만 남는다. `packages/host-tiptap` 의
  NodeView 가 `runFacet` 을 부르는 지점이 그 자리다.
- **10개 언어 확장** — 조각 아홉의 title/description/messages 가 en·ko 뿐이다.

  다른 도메인.
