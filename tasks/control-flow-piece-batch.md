# 제어 흐름 조각 여덟 · 개념 여덟 — 배치 기록

2026-09-25. 프로그래밍 기초 분야의 첫 조각 묶음이자 **튜닝(2026-09-25) 뒤 첫 실험 배치**다.
규범은 `piece-batch-protocol.md` · `concept-meta-batch-protocol.md`. 사용자 지정으로 **칸 다섯**, 에이전트를 직접 띄웠다
(Workflow 아님). 완제품 넷(반복문 · 분기 · 재귀 호출 · 예외 처리)은 이번 범위가 아니다.

## 만든 것

| 조각 | 주장 | origin | 걸음 |
| --- | --- | --- | ---: |
| `branch-take-one-path` | 갈림길에서 한쪽만 간다 — 안 간 쪽의 변수는 끝내 생기지 않는다 | conditional | 6 |
| `multiway-branch` | 위에서부터 묻다 처음 참에서 빠져나간다 — 아래 조건은 셈조차 안 된다 | branching | 7 |
| `loop-back` | 몸 끝에서 조건 줄로 되돌아가 같은 줄을 다시 밟는다 | loop | 14 |
| `loop-termination` | 조건이 읽는 변수를 몸이 바꾸지 않으면 끝나지 않는다 | loop | 12 |
| `recursion-self-call` | 흐름이 새 인자를 들고 같은 몸의 첫 줄로 들어간다 | recursive-call | 12 |
| `call-stack-unwind` | 틀이 얹힌 차례의 거꾸로 걷히며 돌려준 값이 아래로 이어진다 | recursive-call | 9 |
| `base-case` | 바닥에 닿아야 돌아온다 — 건너뛰면 틀 한도에서 넘친다 | recursive-call | 13 |
| `exception-propagate` | 던지면 잡지 않는 틀을 건너뛰어 부른 자리를 거슬러 오른다 | exception | 11 |

소재가 **코드**인 첫 분야다. 사양 초안이 정한 규약: 파이썬 표기의 작은 부분집합(빈칸 넷 들여쓰기 · 주석 없음 · 식별자와
문자열은 영어 자료), 줄마다 `{indent, text, stmt}` 구조를 두고 **알고리즘이 그 구조를 해석해** 걸음을 낸다(걸음표를 손으로
적지 않는다). 걸음은 줄 걸음이 기본이고 call-stack-unwind · base-case 만 호출 걸음이다. 값을 넣은 식 글자(`0 < 3`)를 payload
로 싣는 것은 감사가 C10 판정 3(수식 · 기호 표기)으로 **위반 아님** 판정했다.

## 실측 — 09-18 과 견줌

| | 09-18 (AI · 컴퓨터 구조) | **이번** |
| --- | --- | --- |
| rule-guard 한 번 | 50 턴 · **6.9M** · 6~11 분 | 10 턴 · **0.43M** · 1.2 분 |
| 조각 하나 (감사 고침 포함) | 1.82M · 16.1 분 | **2.92M** · 12.1 분 |
| 첫 파일까지 | 중앙 3.8 분 | 중앙 4.3 분 |
| 사양 초안 (서브도메인 하나) | 5~7 분 | 7.5 분 · 0.78M |
| 호스트 | 턴당 363K | 턴당 385K (71 턴 · 27.3M, 시작 컨텍스트 314K) |

- **rule-guard 는 16 분의 1 로 줄었다.** "배치 감사" 절 — 검사기를 먼저 돌리고, 기계가 잡는 것은 세지 않고, 파일은 `Read` 로
  한 번만. 그러면서도 **검사기가 전부 초록인 채로 난 결함을 여섯 조각에서 잡았다** (아래).
- **조각은 토큰이 60% 늘었다.** 턴이 28 → 37. 조각마다 작은 해석기를 짜야 하는 소재라 코드가 길다(재귀 조각은 첫 파일까지 7.8 분).
  튜닝이 늘린 것인지 소재가 늘린 것인지 이 한 배치로는 가르지 못한다 — 다음 배치(코드 소재가 아닌 분야)에서 다시 잰다.
- **호스트는 줄지 않았다.** 튜닝과 같은 세션에서 이어 돌려 시작 컨텍스트가 이미 314K 였다. 에이전트 쪽 합(29.9M)과 호스트(27.3M)가
  거의 같다. **"분야마다 새 세션" 조항의 필요를 거꾸로 보여 준 셈이다** — 새 세션이었다면 호스트 몫은 수 M 에 그쳤을 것이다.

## 감사가 잡은 것 — 검사기 초록인 채로

| 조각 | 지적 |
| --- | --- |
| recursion-self-call | **캡션 "멈춰 있는 앞선 몸: 3" 인데 화면의 멈춤 표시는 4** (원본 줄에도 표시) — facet-shot 글자 요약 대조로 잡음 |
| call-stack-unwind | 장면이 알고리즘 해석기를 통째로 다시 돌림(이행 프로토콜 "함수를 내주고 장면이 부른다" 경계) + 그 `catch` 가 조용히 삼킴(C6) · 설명 글의 "열네 걸음" 근거 없음 |
| multiway-branch | 설명 글 "여섯 갈래" — 실제 다섯 |
| loop-back | 설명 글 "아래" 방향 말 · 출력 칸 높이를 변수 둘에 박음 |
| loop-termination · recursion-self-call · call-stack-unwind · base-case · exception-propagate | **글자 폭 셈용 크기 상수** (`CODE_PX = 12` · `Math.min(8.4, …)`) — 코드 글자를 그리는 조각의 공통 함정 |

글자 폭 상수는 `check-lib` 에 **경고**로 넣었다 (기존 조각에도 열여섯 곳 있어 오류로는 못 올린다). 계약 카드에도 한 줄 넣었다.
설명 글의 수는 이번에도 사람(감사)만 잡았다 — 09-18 의 C(16,4) 와 같은 자리다.

## 에이전트가 짚은 것

- **첫 걸음 앞 멈춤** — 계약 카드("빈 화면을 두지 않는다")와 공통 안내문("첫 걸음도 800ms 이상") 사이에서 셋이 같은 판단을 했다:
  걸음 0 이 프로그램 전체가 보이는 화면이면 멈춘다. 카드 문구를 그렇게 고쳤다.
- **`CanvasView` 는 제네릭이 아니다** — 카드가 `SceneRenderer<S>` 와 섞어 적어 제네릭처럼 읽혔다. 고쳤다.
- **밝은 테마에서 `primary` 와 `success` 가 같은 검정**(`#171717`)이라 흐름과 "참" 이 한 색이 됐다 (multiway-branch 가 `itemActive` 로 갈랐다).
  토큰 결정 트리가 이 짝을 막지 않는다 — 기록만 한다.
- **긴 번역이 칸을 넘는다** — loop-termination 의 pt `verdadeiro` 가 셈 칸보다 길어 답을 위아래로 엇갈려 두었고, 그 언어에서 "같은 답의
  되풀이" 모양이 조금 흐려진다.
- 한 에이전트가 설명 글 형식을 보려 `ls -t` 로 형제 조각의 설명 글 하나를 열었다고 스스로 밝혔다 (구현 파일은 아님).

## 개념 메타

에이전트 하나가 여덟을 한자리에서 썼다 (origin 완제품이 없어 토픽으로 묶되, 한 서브도메인이라 하나로). 재귀 셋은 **어휘 배타**로
갈랐다 — `unwind · return value` 는 callStackUnwind 만, `base case · overflow` 는 baseCase 만, `frame · stack · return` 은
recursionSelfCall 이 쓰지 않는다. definition 짝별 겹침 최대 18% (일반어). 기존 `conditional-statement.ts` 의 `contrastWith` 에
branchTakeOnePath 한 줄을 더했다. multiwayBranch ↔ conditionalStatement 가 벡터로 가장 가까울 수 있다고 에이전트가 짚었다.
