# 확률적 자료구조 완제품 — 판정과 배치 사양

절차와 잣대는 `tasks/whole-batch-protocol.md`. 조각 열은
`tasks/probabilistic-piece-batch.md` 에서 끝났다.

## 판정 — 다섯 다 만든다

잣대 셋을 각각 매긴 결과다.

| | IR | 조작 (실측) | 통합 | 판정 |
| --- | --- | --- | --- | --- |
| 블룸 필터 | 강함 — `(h1+i·h2) % m` 이 `+ * %` 로 펴지고 비트 배열은 `list` 에 0/1 이라 비트 연산이 필요 없다 | **m 을 늘리면 최적 k 가 옮겨간다** | 조각 3 | 만듦 |
| Count-Min Sketch | 강함 — 2차원 `list` + 이중 루프 + `min`(예약) | 폭과 깊이가 **서로 다른 것을 만진다** | 조각 2 | 만듦 |
| HyperLogLog | 약함 — 비트 연산이 없어 "앞자리 0 세기" 가 안 펴지고 `pow` 도 없다 | 버킷 1→16 에 오차 78→6% | **조각 둘이 이 축의 두 점** | 만듦 |
| 스킵 리스트 | 약함 — IR 에 난수가 없어 "무작위가 균형을 만든다" 가 빠진다 | 원소 수가 log n 을 그린다 | 조각 2 (만들기+쓰기) | 만듦 |
| t-digest | 약함 — `asin`/`sin` 이 예약에 없다 | δ 가 **꼬리를 가운데보다 빠르게** 고친다 | 조각 1 — 유일한 약점 | 만듦 |

**IR 이 약한 셋도 만든다.** 완제품 59 종 중 17 종이 IR 0 노드이고(`tsne` ·
`linearRegression` · `array` · `stack` · `unionFind` …), "IR 로 안 펴진다" 는
IR 을 두지 않는다는 뜻이지 만들지 않는다는 뜻이 아니다.

**버린 것 0 건이다.** UMAP 과 A\* 는 셋 중 여럿이 약해서 버렸다. t-digest 는 통합
하나만 약하고 조작이 산다.

### 이 판정에 이르기까지 두 번 틀렸다

1. **잣대를 하나로 썼다.** 폐기된 `graph-whole-batch.md` 의 IR 단일 잣대를 집어
   다섯 중 셋을 버리기로 했다. 사용자가 정정했다. 그 일로
   `tasks/whole-batch-protocol.md` 를 세워 잣대를 규범 자리로 옮겼다.
2. **t-digest 를 "조작이 논증을 못 진다" 고 판정했다.** 실제로는 분위수 질의를
   최근접 대표값으로 답한 **내 근사** 탓이었고, 인접 뭉치 사이를 보간하게 고치니
   단조로 떨어졌다. t-SNE 때와 같은 자리다 — 데이터가 안 나오면 코드부터 의심한다.

## 조작 실측

프로토콜이 요구하는 "갈리는가 · 단조로운가 · 읽히는가". **1차 측정에서 다섯 중
넷이 단조가 깨졌고**, 원인은 표본이 작아 우연이 신호를 덮은 것이었다. 단조성을
조건으로 걸고 다시 훑어 아래 조합을 골랐다.

### 블룸 — m 을 늘리면 최적 k 가 옮겨간다

넣는 것 여섯(`apple` `fig` `kiwi` `mango` `elder` `cherry`). 거짓 양성률(%)은
질의 3000 개로 쟀다 — 화면에는 비트 배열과 넣은 키만 그리고 비율은 요약으로 보인다.

```
        k=1    k=2    k=3    k=4    k=5     k=6
m=16   30.9   16.0   28.4   39.9   69.1   100.0     최적 k=2
m=32   18.5    8.0    5.8    8.8   11.0    14.6     최적 k=3
m=64    9.4    1.4    0.8    1.0    1.0     1.9     최적 k=3
```

*대조: m=16 은 k=2 에서 16.0% 로 바닥을 치고, m=32 와 m=64 는 k=3 에서 친다.
자리가 적으면 해시를 적게 써야 하고 넉넉하면 더 써도 된다 — **`m=16·k=6` 은
100% 로 무엇을 물어도 "있다" 가 되는데 `m=64·k=6` 은 1.9%** 다. 그 대비가 이
완제품의 주장이다.*

1차 데이터인 해시 둘 (`h1` 은 Java `String.hashCode` 를 마스크한 값, `h2` 는
FNV-1a 32bit 를 마스크한 뒤 홀수로 만든 값):

```
apple   h1=  93029210   h2=  280767167        mango   h1= 103662530   h2=  242548693
fig     h1=    101380   h2= 1105500693        elder   h1=  96592394   h2=  138038775
kiwi    h1=   3292336   h2= 1073607833        cherry  h1= 785970585   h2= 1232791673
```

*대조 (m=32, k=3): 자리는 `apple [26,25,24]` · `fig [4,25,14]` · `kiwi [16,9,2]` ·
`mango [2,23,12]` · `elder [10,1,24]` · `cherry [25,18,11]`, 켜진 자리 14/32.*

### CMS — 폭과 깊이가 서로 다른 것을 만진다

키 열둘, 빈도는 `20-2i` 로 20·18·16·14·12·10·8·6·4·2·1·1, 스트림 112 개.

```
폭  (d=3 고정)   w=4 165 · w=6 59 · w=8 52 · w=12 26 · w=16 12
깊이 (w=8 고정)  d=1 117 · d=2 74 · d=3 52 · d=4 39
```

*대조: 둘 다 단조 감소한다. 오차합은 여덟 키의 (읽힌 값 − 참값) 합이고 어느
키도 참값보다 작게 읽히지 않는다.*

### HLL — 버킷을 늘리면 튐이 갇힌다

서로 다른 키 96 개(`host-0001` … `host-0096`), murmur3.

```
버킷    1     2     4     8    16
오차   78%   55%   21%   20%    6%
```

*대조: 줄어든다. 버킷 하나면 튀는 레지스터 하나가 전체를 끌고 가고,
나눠 담으면 그 튐이 한 통에 갇힌다.*

**"단조 감소한다" 고 적었다가 고쳤다.** 버킷 4 와 8 은 반올림하면 21% 와 20% 지만
실측은 **20.5 와 20.4** 로 사실상 붙어 있다. 줄어드는 것은 평균적으로 그렇다는
뜻이지 한 걸음마다 반드시 그렇지 않다. 반올림한 표를 보고 단언을 세운 것이고,
에이전트가 실측으로 잡아 `description.ts` 에 그 한 줄을 밝혀 두었다.

**조각 둘이 이 축의 두 점이다** — `leadingZerosTell` 이 버킷 1, `averageTheBuckets`
이 버킷 4. 완제품은 독자가 그 축을 직접 밀어 둘이 한 물건의 두 지점이었음을 본다.

### 스킵 리스트 — 원소 수가 log n 을 그린다

씨앗 161 고정(동전 열을 못박는다). **씨앗 축은 쓰지 않는다** — 자취가 2·2·3·2·4·3
으로 흔들려 읽히지 않았다.

```
n          8    16    32    64   128
스킵     3.9   4.9   5.3   7.4  10.0
한 층    4.5   8.5  16.5  32.5  64.5
log2(n)  3.0   4.0   5.0   6.0   7.0
```

**걸음은 값을 본 횟수만 센다** — 층을 내려서는 것은 걸음에 넣지 않는다. 사양이
이것을 적지 않았는데, 넣어서 세면 6.3 · 8.0 · 9.4 · 12.5 · 16.0 이 되어 아래 표가
전부 어긋난다. 에이전트가 두 해석을 다 재 보고 맞는 쪽을 골랐다.

*대조: 모든 원소를 찾는 평균 걸음이다. 스킵은 log2(n) 과 나란히 늘고 한 층짜리는
선형으로 는다. n=8 에서는 둘이 거의 같다 — 작을 때는 층이 값을 못 한다.*

### t-digest — δ 가 꼬리를 가운데보다 빠르게 고친다

값 200 개, 꼬리가 긴 분포. 분위수 질의는 인접 뭉치 사이 보간.

```
δ           6     12     24     48
q=0.99   45.8   17.2   10.0    1.8      (상대오차 %)
q=0.50    6.5    6.5    1.6    1.0
```

*대조: 꼬리가 45.8 → 1.8 로 스물다섯 배 좋아지는 동안 가운데는 6.5 → 1.0 이다.
자리를 꼬리에 몰아준 값이 꼬리에서 돌아온다.*

## 완제품에만 붙는 규범 (조각과 다른 것)

조각 사양(`probabilistic-piece-batch.md` 의 공통 지침)에서 **뒤집히는** 것들이다.

- **`layout` 을 선언한다.** 조각은 러너에게 맡기지만 완제품은 블록이 넷이다.
  `{ type: 'column', gap: 8, children: [{ ref: 'header' }, { ref: 'stage', padding: '8px 0' }, { ref: 'controls' }, { ref: 'codePanel' }] }`
  — IR 이 없으면 `codePanel` 을 뺀다.
- **`header: { type: 'title-block' }` 를 둔다.** 조각은 두지 않는다.
- **`metrics` 를 둔다** (C5). 이름은 kebab-case 이고 `ctx.metric` 이 부르는 이름이
  `facet.ts` 의 `metrics[].name` 에 **반드시 선언**되어야 한다 — 미선언 메트릭은
  화면에 안 뜨고 조용히 사라진다. `label` 은 열 언어 `LocaleStr`. 접미사는
  `-count` · `-depth` · `-size` · `-sum` 로 통일한다.
- **컨트롤은 `CONTROL_SET.playback` 에 손잡이를 덧붙인다** —
  `[...CONTROL_SET.playback, { widget: 'segmented-slider', action: '<이름>', name: '<이름>', label: '<짧은 이름>', segments: [...] }]`.
  `playback` 은 play · step · pause · reset · speed 다.
  - **손잡이 라벨은 이름이지 설명이 아니다.** `C — 안 틀리려는 마음` 같은 것은
    금지다(대시나 콜론으로 설명을 잇는 패턴을 검사가 잡는다).
- **`mechanismKind: 'reactive'` 를 쓴다.** 손잡이가 있는 완제품은 전부 reactive 다
  (`kmeans` · `svm` · `linearRegression` · `heapBinary`). coroutine 은 손잡이 없는
  재생 전용(`dijkstra`)에만 쓴다.
  - reactive 의 **세 상태**를 지킨다 — 나아가는 중(`running(true)`) · 멈춤
    (`running(false)`) · 입력 대기(`running(false)` + `setComplete(true)`).
    입력 대기에서 재생·한 걸음이 꺼지고 되돌리기와 위젯만 남는다.
  - **되감기는 위젯도 되돌린다** (`resetInputs`). 슬라이더가 15 를 가리키는데
    화면이 3 의 결과를 보이면 조작이 논증을 지는 완제품에서 그 어긋남 자체가
    거짓말이 된다. 되돌릴 때 값만 돌리고 `dispatch` 하지 않는다 — 여기서 또
    보내면 그 걸음이 두 번 세어진다.
- **IR 을 두면 phase 어휘를 맞춘다** (C3). `algorithm.ts` 의 `phase` 값 집합과
  `irs.ts` 의 `phase` 값 집합이 **완전히 일치**해야 한다. 어긋나면 코드 패널
  하이라이트가 조용히 깨진다. `phase` 는 `silent: true` 로 발신하고 kebab-case 다.
  호출부에 리터럴로 나타나야 한다 — `phase('compare')` 헬퍼는 되지만 `PHASES[i]` 는
  안 된다.
- **IR 어휘의 한계** — 배열 · 반복 · 조건 · 대입 · 함수뿐이다. 큐 · 스택 · 맵 ·
  집합이 없고 **비트 연산도 없다**(`IRBinOp` 는 `+ - * / // %` · 비교 · `&& ||`).
  예약 수학 이름은 `exp` · `log` · `sqrt` · `abs` · `max` · `min` · `floor` 뿐이다.

### 조각과 같은 것

- 사람이 읽는 문자열은 **열 언어** — en ko ja zh ar es fr hi id pt.
- `destroy()` 가 기다리던 promise 를 푼다 (전수 검사가 있다).
- `ctx.emit` 의 type 은 리터럴, payload 스키마 주석과 실제 발신을 맞춘다 (C2).
- projector 가 payload 를 좁혀 stage 로 넘긴다 (C9). `initialData` 를 좁히는 것은
  stage 의 `mount` 다.
- 색은 `design-tokens` 경유, hex/rgba 0건.
- 화면에 쓰는 수 뒤에 조사를 붙이지 않는다.
- 등록 파일을 건드리지 않는다. `pnpm install` 을 돌리지 않는다.
- **계측과 전수 검사는 호스트가 배치 끝에 일괄로 돌린다.**
- 대조가 안 맞으면 다른 길로 한 번 더 셈해 보고, 그래도 안 맞으면 근거와 함께
  보고한다. **이 배치에서 호스트는 이미 사양을 다섯 번 틀렸다.**

### 호스트가 사양을 다섯 번 틀렸다

조각 배치에서 다섯, 완제품 배치에서 다섯이다. 전부 에이전트가 잡았다.

| 자리 | 적은 것 | 참값 |
| --- | --- | --- |
| 완제품 판정 | 잣대가 IR 하나 | **셋**(IR · 조작 · 통합). 폐기된 문서를 집었다 |
| t-digest 조작 | "조작이 논증을 못 진다" | 내 근사(최근접 대표값) 탓. 보간하면 단조 |
| HLL 대조 | "단조 감소한다" | 버킷 4·8 이 20.5 대 20.4 로 붙어 있다 |
| 스킵 대조 | "걸음" 의 정의를 안 적었다 | 층 내려서기를 빼야 표가 맞는다 |
| 블룸 IR | `(mask(h1) + mask(i·h2)) % m` | **IR 로 표현 불가능**. 비트 연산이 없다 |

#### 가장 값어치 있었던 것 — t-digest 가 두 번 뒤집었다

내가 "조작이 논증을 못 진다" 고 판정한 것을 에이전트가 **측도 교정**으로 뒤집었고,
그것을 내가 **재검산**으로 다시 뒤집었다. 두 번째 뒤집기에서 **다른 자**(순위
오차)를 함께 댄 것이 결정적이었다 — 두 독립 측도가 같은 방향을 가리켜야 믿을 수
있다.

그리고 갈린 진짜 까닭은 에이전트가 찾았다. **뭉치 경계의 `max(lo+1, …)` 바닥**
때문에 δ 가 커지면 이웃 두 뭉치가 같은 점을 나눠 갖고, δ=48 에서 **무게합이
201** 이 되며 마지막 중심 분위가 1.0025 로 밀린다. 그것이 꼬리 오차를 5.7% 가
아니라 1.77% 로 만든다. **내 스크립트의 성질을 내가 모르고 있었다.**

### 에이전트가 독립으로 같은 벽에 부딪힌 것

- **IR 이 32비트 마스크를 표현하지 못한다.** `bloomFilter` 와 `countMinSketch` 가
  서로 못 보는 채로 같은 자리에 부딪혔고 **다른 답을 냈다** — 하나는 나머지
  분배로 접었고, 하나는 사양대로 두고 판단을 호스트에 넘겼다. 갈렸다는 것 자체가
  사양 쪽 문제라는 증거였고 앞의 쪽으로 통일했다. 블룸은 18 조합 × 306 키 =
  **19,278 건 대조에 불일치 0** 으로 등가성을 증명했다.

### 이 배치가 드러낸 구조적 구멍

- **projector 가 stage 를 `as unknown as` 로 물어 payload 필드명을 바꿔도 타입
  검사가 통과한다.** `tDigest` 에서 실제로 셋을 바꾸고도 통과했고, 화면만 조용히
  빌 수 있었다. **배선 스모크가 유일한 눈이었다.** C9 가 허용하는 자리이지만
  대가가 이것이다 — 검사로 옮길 후보다.
- **C# 예약어 처리가 여섯 transpiler 어디에도 없다.** 블룸이 `base` 를 쓰려다
  emit 을 눈으로 보고 잡았다. `S-transpiler` 의 rename 조항이 사문이었고 사실에
  맞게 고쳤다(별도 커밋 `7c54d6a`). 저장소의 `pca` 도 `out` 을 쓰고 있어 함께
  고쳤다.

### 프로토콜에 올린 것

- **완제품 판정 잣대 셋**을 `tasks/whole-batch-protocol.md` 로 옮겼다. 배치 기록에만
  있으면 어느 것이 최신인지 문서가 스스로 말하지 않는다.
- **코드 패널은 화면과 같은 답을 내야 한다** — IR 로 표현 불가능한 규칙을 사양이
  요구할 수 있고, 그때 주석으로 간극을 밝히는 것으로는 모자라다.
- **조작은 실측한다**, **안 나오면 내 코드부터 의심한다** — t-SNE 와 t-digest 가
  같은 자리에서 걸렸다.

### rule-guard 감사

**Critical · High 0건.** Medium 6 + Low 2, **전부 고쳤다.**

고친 뒤 다섯 패키지 typecheck 전부 PASS.

**C4 는 2/5 인데 IR 을 가진 둘 전부다** — 저장소의 기존 IR id 35 개가 모두
kebab-case(`bfs-iterative` · `bst-recursive` · `avl-rebalance`)인데 이 배치만
camel 이었다. **사양이 IR id 규약을 적지 않아 생긴 갈림**이다.

**C8 의 3 대 2 갈림은 규범이 이미 예언해 둔 자리였다** — `rules/concerns/C8` 에
"완제품 다섯을 격리해 만들었더니 이 대목이 3 대 2 로 갈렸다" 고 적혀 있다.
같은 배치에서 같은 비율로 재현됐다. 사양 미비가 원인이지 저자 부주의가 아니다.

#### 감사가 확인해 준 것 셋

- **`destroy()` 의 "매달릴 것이 없다" 주장이 사실이다.** 다섯 stage 전수에서
  `setTimeout` · `setInterval` · `rAF` · `Promise` · `async` **0건**. "타이머 없음"
  이라 적어 놓고 타이머가 있는 경우가 없다.
- **되감기가 위젯을 되돌린다.** `runner.ts:236` → `control-bar.ts:366` 경로를 끝까지
  따라갔고, **손잡이 여섯 전부 `initialData` 값과 `default: true` 세그먼트가
  일치**한다(m 32/32 · k 3/3 · w 12/12 · d 3/3 · 통 4/4 · n 16/16 · δ 12/12).
  슬라이더가 가리키는 값과 화면이 어긋나는 거짓말은 없다.
- **IR 과 algorithm 이 같은 자리를 셈한다 — 다만 방식이 갈린다.** 블룸은
  `m ∈ {16,32,64}` 가 모두 2의 거듭제곱이라는 **전제에 기대고**(그 전제를 주석에
  명시했다), CMS 는 접기를 `h2` 안쪽에 두어 **전제 없이** 성립한다. 폭 6·12 가
  2의 거듭제곱이 아닌데도 맞는다. **CMS 쪽이 더 튼튼한 접기다.**
