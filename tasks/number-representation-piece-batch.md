# 수와 비트 표현 조각 열 — 배치 기록

2026-09-12. `facets/computer-architecture/` 의 첫 facet 들이다.

규범은 `tasks/piece-batch-protocol.md` 와 `rules/specifics/S-piece.md` 에 있다.
여기 적힌 것은 이 배치에서 무엇을 시켰고 무엇이 나왔는지다.

## 호스트가 틀린 것 — 다섯

**전부 에이전트가 잡았다.** 사양을 쓰는 쪽이 반복해서 같은 종류로 틀린다.

1. **"이 도메인의 첫 facet 이라 install 이 안 돌았다" 를 열 전부에게 적었다.** 동시에 열을 띄웠으니 각자에게 그 말이 참일 수 없다. 셋이 지적했다. 결론(typecheck 를 돌리지 말 것)은 옳았고 근거가 틀렸다. **다음 배치부터는 "새 패키지들이 동시에 생기는 중이라" 로 적는다.**

2. **`silent-truncation` 의 `511 → 255` 가 오독의 덫이다.** 결과가 그릇의 최대값과 같아 "넘치면 최대값에 붙잡아 둔다"(포화 연산)로 읽힌다. 실재하는 다른 동작이라 그럴듯하다. 그대로 두기로 했다 — 걸음이 `300 → 44` 로 먼저 "256 을 뺀 값" 을 보이고 나서 511 이 오므로 앞 걸음을 본 독자가 뒤를 포화로 읽기 어렵고, 글이 `512 → 0` 으로 반박한다.

3. **`silent-truncation` 의 1차 데이터 목록에서 원본 폭 16 이 빠졌다.** "값 셋과 그릇 폭 8 뿐" 이라 적었는데 비트열을 셈하려면 16 도 선언에 있어야 한다. 산문에만 있던 수였다.

4. **`bit-shift` 의 동사가 데이터보다 넓었다.** "끝을 넘어간 비트는 사라진다" 고 적어 놓고 왼쪽 데이터 `3 << 0..5` 는 96 에서 끝나 아무것도 잃지 않는다. 소실은 오른쪽에서만 보인다. 에이전트가 걸음 수를 임의로 늘리지 않고 되물었다. 그대로 두었다 — 시작값을 바꾸면 `3·6·12·24·48·96` 의 배수 사다리가 마지막에서 깨져 본 주장인 곱셈이 흐려진다. **넓었던 것은 데이터가 아니라 동사 문안이다.**

5. **`positional-value` 의 8진 표기가 두 얼굴이었다.** 사양이 `0 5 5` 와 `55` 를 둘 다 줬는데, 여덟 비트를 셋씩 끊으면 앞자리가 0 이라 화면이 "055" 라 말하고 캡션이 "55" 라 말하면 둘 중 하나가 거짓이 된다. 에이전트가 앞의 0 칸만 흐린 글자로 두고 캡션은 읽기를 말하게 했다.

덤으로 **`positional-value` 의 동사가 두 주장을 품고 있었다** — "합으로 갈라진다" 와 "밑이 바뀌어도 같다". 캡션 둘이면 조각 둘이라는 신호라 한 논증의 단계로 묶었다.

## 사양이 답을 주지 못한 어려움 — 둘

사양의 오류가 아니라, **그 데이터로 화면을 만들 수 있는가** 가 열려 있던 자리다.

- **`uneven-float-gaps` 의 65,536배 동적 범위.** 1 의 사이 거리와 65,536 의 사이 거리를 한 축척에 같이 올릴 수 없다. 에이전트가 후보 셋을 명시적으로 버렸다 — 고르게 늘어놓기(사양이 금지한 "고른 눈금" 그 자체), 로그 축(사이 거리가 고른 계단으로 보여 깨려던 믿음을 되살림), 고정 축척 한 프레임(다섯 중 셋이 한 점에 뭉쳐 정지 화면). 답은 **카메라가 물러서는 짜임**이었고, 축척에 기대지 않는 증거로 **빗살**(앞 눈금이 새 칸에 몇 개 들어가는지)을 뒀다.
- **`unrepresentable-fraction` 의 "그릇".** 무엇이 그릇이고 어디서 잘리는지가 사양에 없었다. float32 의 27 자리로 잡고 정규화는 화면에서 설명하지 않은 채 글로 보냈다.

같은 자리에서 `latency-ladder`(캐시 배치)도 50배를 만난다. **"축척에 담기지 않는 양" 은 이 도메인의 되풀이되는 난제다.**

## 에이전트가 스스로 잡은 것

- **`byte-order` 가 한자 리터럴을 찾아 고쳤다.** 캡션 줄바꿈용 정규식의 글자대 경계를 한자로 적었다가 `\u` escape 로 교체했다. 코드의 한자는 금지이고 i18n 리소스의 번역 문안은 대상 밖이라는 구분까지 정확했다.
- **`negate-and-add-one` 이 사양의 대안 데이터를 안 썼다.** 자리올림이 번지는 예로 `+44` 를 줬는데, 검산(`45 + 211`)이 여덟 칸을 전부 훑고 나가므로 **번짐을 공짜로 준다**며 쓰지 않았다. 1차 데이터가 45 와 8 그대로 남았다.
- **`signed-wraparound` 가 반대 방향을 화면에서 뺐다.** 사양이 `-128 - 1 = 127` 을 데이터로 줬지만 넣으면 캡션이 둘로 갈려 조각이 둘이 된다는 이유로 글로 보냈다. 사양보다 S-piece 를 위에 뒀다.
- **`negate-and-add-one` 이 `verify` payload 에 `sum` 을 실었다.** 이 조각에서 합은 수학적으로 늘 0 이라 stage 가 0 을 그려도 화면은 맞는데, 그러면 "화면이 알고리즘과 무관하게 0 을 그리는 셈" 이 된다는 이유였다.

## 검사가 잡은 것

**`bit-mask` 의 projector 등록명이 algorithm 과 같았다** (`registerProjector('bitMask', …)`). 열 중 아홉은 `<이름>Projector` 를 지켰다. `register-names` 전수 검사와 rule-guard 가 **독립적으로 같은 자리를 짚었다.** 두 줄(등록명 + `facet.ts` 의 `module:` 참조)을 고쳐 통과했다.

**다음 배치 사양에 이 조항을 박았다** — projector 등록 이름을 명시해 주는 것.

## 호스트의 도구가 틀린 것

**`catalog.json` 편집이 적용되지 않았는데 성공처럼 보였다.** 포맷 왕복 검사용으로 `JSON.stringify(obj)` 를 수정 *전에* 계산해 두고, 객체를 고친 뒤 그 **옛 문자열**을 파일에 썼다. "facetId 부여 10 건" 이라는 출력은 메모리 상의 객체만 보고 찍힌 것이다. git 이 변경 0 을 보고해서 잡혔다.

**이 세션이 거듭 만난 모양이다** — 확인 수단이 실제 결과가 아니라 중간 상태를 본다. 고친 뒤에는 **파일을 다시 읽어** 10 건을 확인하게 했다.

## rule-guard 가 본 갈림

MUST 위반은 위의 하나뿐이었고, 나머지는 **규범의 문면이 갈림을 허용하는 자리**들이다.

| 갈린 지점 | 비율 | 규범의 상태 |
| --- | --- | --- |
| 걸음 문(gate)의 짜임 | 문-먼저 7 : emit-먼저 3 | S-piece 가 **명시 허용**. 결과가 같아 무해 |
| stage 의 문안 책임 | 자체 translator 6 : projector 위임 4 | 규범 없음. 양쪽 다 C10 통과 |
| 선언값 방어 | fallback 둠 6 : 그대로 씀 4 | 규범 없음 |
| 걸어 둔 것의 집합 이름 | `frames` 4 : `timers` 5 : 기타 2 | S-piece 가 **모양**만 정하고 이름은 안 정함. 모양은 10/10 |
| 캔버스 세로 상수 이름 | `H` 7 : `CANVAS_H` 2 : `STAGE_H` 1 | 규범 없음 |

**걸음 문의 7:3 이 반대 방향의 증거다.** S-piece 가 배치 둘에서 갈린 뒤 문면을 좁혀 둔 자리인데, 이번에도 짜임은 갈렸지만 **결과가 같아 아무 해가 없었다.** 이름이 아니라 **결과**를 못박은 조항이 제 몫을 했다.

### rule-guard 의 권고 하나가 표본 때문에 틀렸다

`irs.ts` 의 `IR` 타입 출처가 새 조각 열 안에서 `@ffacet/core/runtime` 6 : `@ffacet/core` 4 로 갈렸고, rule-guard 는 **"지금 고치면 4 파일, 나중이면 수십"** 이라며 통일을 권했다.

저장소 전체를 재니 **이미 106 : 132 다.** 새 조각의 6:4 는 저장소의 오래된 갈림이 그대로 비친 것이지 새로 생긴 것이 아니다. 규모를 106 배 작게 본 것이다.

그래서 **네 파일만 고치지 않았고, 규범에 조항도 세우지 않았다.** 지금 한 줄을 적으면 기존 106 개가 그 자리에서 유령 위반이 된다 — S-piece 가 `canvas: height` 조항으로 겪고 "규칙이 사실과 어긋나면 다음 감사가 110 건짜리 유령 위반을 만난다" 고 적어 둔 바로 그 구조다. **통일 작업과 조항 신설은 함께 가야 한다.** 별도 과제로 남긴다.

**서브에이전트의 권고는 그 표본이 전체를 대표하는지 호스트가 다시 재야 한다.**
