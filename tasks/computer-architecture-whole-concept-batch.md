## 완제품 — 사양 초안을 에이전트에게 맡겼다

잣대 셋 채점 · 손잡이 실측 · IR 판단 · 공통 안내문을 **에이전트 하나가 초안으로** 썼다 (20 분,
조각 열둘이 도는 동안 나란히). 호스트는 판정 일곱 자리만 검토했고 하나(`branch-history-table`
의 무작위 열이 T 12/18 로 치우쳐 "늘 탄다" 가 67% 를 맞힘)를 되돌려 T 9/18 로 고쳤다.
호스트 컨텍스트에서 시뮬레이션을 돌리지 않은 것이 요점이다.

### rule-guard 가 잡은 것 — 규범의 빈자리 하나

**덮이는 phase (Medium, 여섯).** reactive 의 걸음 경계는 `sleep` 뿐이고 코드 패널은 앞 phase 를
덮는다. 연달아 보낸 phase 는 한 번도 안 켜진다 — `control-hazard` 의 `tally += resolveStage − 1`,
`out-of-order-execution` 의 커밋 루프, `prefetching` 의 기다림 줄. C3 의 "집합이 같다" 는
통과했다. 저장소에 같은 자리가 이미 열네 곳 있다. **프로토콜에 조항으로 넣었다.** 고친 에이전트
여럿이 "걸음 경계마다 켜진 phase 를 모아 IR 집합과 견준다" 는 검사를 스스로 더했다.

그 밖: 손수 만든 대체 번역기 셋(`vars` 를 버려 러너 밖에서 `{n}` 이 날것으로), 테스트의 직접
`.mount` 아홉. 모두 만든 에이전트가 1~2 분에 고쳤다.

## 개념 메타 — 열한 묶음, 서른하나

완제품 하나 + origin 조각이 한 묶음, 묶음마다 에이전트 하나 (2.5 ~ 4.3 분). 앞 배치가 찾은
갈림 기법 셋(어휘 배타 · 주어 층위 · 마주 보는 짝)을 공통 안내문에 넣었고, 열하나가 모두
그 기법으로 definition 을 갈라 **대표 낱말 겹침을 기계로 확인**해 보고했다.

rule-guard: 상대 **화면을 서술한** `contrastWith` note 아홉, **화면과 어긋난 사실** 여덟
(`dualIssue` 의 짝짓기 규칙이 거꾸로, 뒤집힌 뒤 N 이 넷인데 다섯, 코드 패널이 처음엔 빈다는
말 빠짐 등). 모두 쓴 에이전트가 1 분 안팎에 고쳤다. note 조항은 프로토콜에 이미 있는데도
또 나왔다 — 에이전트가 "상대가 무엇을 보이는가" 로 대비를 쓰려는 끌림이 세다.

기존 `spatialLocality` 의 keywords 둘(행·열 우선 순회)은 `rowVsColumnWalk` 로 넘겼다.

개념 278 → **309**. `concept-covers-facets` 가 닫혀 전수 **1854/1854**.

### 공통 안내문이 모호했던 자리

"다른 묶음의 id 는 `facet:<camel>` 로 쓰면 된다" 고 적었는데 `contrastWith` 의 id 는 접두어
없이 쓰는 것이 관행이다. 에이전트들이 기존 파일을 보고 바로 읽었다.
