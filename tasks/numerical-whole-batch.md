# 수치 알고리즘 완제품 배치 — 사양 원본

조각 셋(`tasks/numerical-piece-batch.md`)을 끝낸 뒤의 완제품 배치다. 규범은
`tasks/whole-batch-protocol.md` 이고 이 문서는 **이 배치에서 그것을 어떻게
적용했는가**를 적는다. 둘이 어긋나면 프로토콜이 이긴다.

## 판정 — 다섯 다 만든다

| 완제품 | ① IR 이 여섯 언어로 갈린다 | ② 조작이 논증을 진다 | ③ 조각을 잇는다 | 판정 |
| --- | --- | --- | --- | --- |
| `euclidean` | **강** — `while (b) { a, b = b, a % b }` 가 IR 어휘 그대로 | **강** — 피보나치 인접쌍에서 6→8→10→12→14, 정확히 2 씩 | **없음** (조각 0) | 만듦 |
| `fast-power` | **강** | **강** — 절약 3→6→13→41→90→984 완전 단조 | 조각 1 (`squareAndHalve`) | 만듦 |
| `sieve` | **강** — 배열 표시가 곧 알고리즘 | **강** — 지우개 고정 대 소수 증가 | **없음** (조각 0) | 만듦 |
| `primality` | **강** — `sqrt` 가 예약 이름에 있다 | **강** — 배율 11.9→16.1→21.4→29.4→42.0 | 조각 1 (`divisorPairsSqrt`) | 만듦 |
| `matrix-mul` | 중 — 스트라센의 재귀를 어떻게 펼지가 갈림길 | **강** — 아낀 곱셈 1 → 1,273,609 | 조각 1 (`rowTimesColumn`) | 만듦 |

**버릴 것이 없다.**

### 조각이 0 인 둘을 왜 만드는가

`euclidean` 과 `sieve` 는 잇는 조각이 **하나도 없어** 잣대 ③ 이 아예 없다. 통합
하나만 약해 만든 `t-digest` 보다도 약한 자리다. 그런데도 만드는 근거는 셋이다.

1. **①② 가 둘 다 강하다.** 프로토콜은 "하나만 약한 것으로 버리지 않는다" 고 하고,
   버린 둘(`UMAP` · `A*`)은 **여럿이 약했다.** 이 둘은 하나만 약하다.
2. **`t-digest` 보다 ① 이 강하다.** t-digest 는 IR 이 약했고(`asin` 이 예약에 없다)
   조작만으로 섰다. 이 둘은 IR 과 조작이 다 선다.
3. **카탈로그가 이 둘에만 조각을 안 붙인 것이 설계 판단이다.** 다른 셋은 조각을
   하나씩 가졌는데 이 둘만 없다. 한 화면에 담길 만큼 단순하다는 뜻이고, 실제로
   호제법과 체는 걸음이 짧고 그림이 하나다.

**다만 배치 기록에 남긴다** — 조각 0 인 완제품을 만든 것은 이번이 처음이다.

## 손잡이 — 실측이 끝나 있다

조각 배치와 나란히 재고, 무너진 둘을 갈아탔다. 전말은
`tasks/numerical-piece-batch.md` 의 "곁들여" 절에 있다.

| 완제품 | 손잡이 | 값 | 주 수치 | 실측 |
| --- | --- | --- | --- | --- |
| `euclidean` | 피보나치 인접쌍 | k = 6·8·10·12·14 | 나눗셈 횟수 | 6 → 8 → 10 → 12 → 14 |
| `fast-power` | 지수 | 8·13·20·50·100·1000 | **절약** (단순 − 빠름) | 3 → 6 → 13 → 41 → 90 → 984 |
| `sieve` | 한계 N | 50·100·120 | **지우개가 되는 소수** | **[2,3,5,7] 넷 고정** / 소수 15 → 25 → 30 |
| `primality` | n (소수) | 97·211·409·797·1597 | √까지 대 2..n−1 | 8→38 대 95→1595 (배율 11.9 → 42.0) |
| `matrix-mul` | 재귀 깊이 k | 1~7 (n = 2ᵏ) | **아낀 곱셈** | 1 → 15 → 169 → 1695 → 15961 → 144495 → 1273609 |

### 갈아탄 둘

**`sieve`.** 1 차 손잡이(표시 대 낱낱이 나눗셈)는 둘 다 늘기만 해 배율 3 배에 그쳤다.
갈아탄 뒤의 주장은 **"판을 키워도 지우개는 그대로인데 찾아내는 소수는 배로 는다"** 다.
N=50·100·120 에서 지우개가 전부 `[2,3,5,7]` 넷으로 같고 그동안 소수는 15→25→30 이다.
Aho-Corasick(읽은 글자 21 고정)과 같은 결이다.

**`matrix-mul`.** "크기를 키우면 곱셈이 n³ 으로 는다" 는 참이지만 **화면을 보기 전에
이미 아는 것**이라 조작이 논증을 지지 못한다. 대안 셋(칸당 곱셈 · 곱셈/덧셈 비 ·
한 칸의 걸음)은 전부 손잡이와 같은 수이거나 1 로 수렴해 밋밋했다.

스트라센으로 갔다. **배율(2.5 배)이 아니라 증폭이 주장이다** — 한 겹에서 곱셈 여덟을
일곱으로 줄인 **차이 하나가 고정**인데 재귀가 깊어지면 아낀 곱셈이 1 → 127 만으로
폭발한다.

### fast-power 의 주 수치는 절약이다

빠름 쪽(4 → 6 → **6** → 8 → 9 → 15)은 n=13 과 20 에서 둘 다 6 이라 완전 단조가
아니다. **절약으로 두면 완전 단조**이고, 빠름 쪽은 "지수가 125 배가 되는 동안 곱셈은
네 배도 안 는다" 는 대비로 쓴다.

## 데이터

**구조를 1 차 데이터로 주고 파생값은 대조용으로만 둔다.** 조각 배치에서 호스트가
**존재하지 않는 수**를 사양에 적은 전례가 있으니(접미사 배열 4.00), 수를 적을 때는
그 수가 나오는 데이터를 손에 쥐고 적는다.

| 완제품 | 1 차 데이터 |
| --- | --- |
| `euclidean` | 두 수 (손잡이가 고르는 피보나치 인접쌍) |
| `fast-power` | 밑과 지수 |
| `sieve` | 한계 N |
| `primality` | n |
| `matrix-mul` | 재귀 깊이와 밑 행렬 |

`sieve` 는 **N=120 이 칸 120 개**라 캔버스 폭 620 에서 칸이 5px 이 된다. 격자로 접어
그리거나 N 을 줄여야 한다 — **칸 수를 정하면 칸 폭이 따라온다.**

## IR

**다섯 다 코드 패널을 단다.** 이 배치는 IR 이 곧게 펴지는 쪽이다.

- **어휘는 배열 · 반복 · 조건 · 대입 · 함수뿐.** 큐 · 스택 · 맵 · 집합이 없고
  **비트 연산도 없다**(`IRBinOp` 는 `+ - * / // %` · 비교 · `&& ||`).
- **예약 수학 이름은 `exp` · `log` · `sqrt` · `abs` · `max` · `min` · `floor` 일곱뿐.**
  `pow` 가 **없다** — 그런데 `fast-power` 는 거듭제곱을 직접 셈하는 것이 주제라
  오히려 맞다. `primality` 는 `sqrt` 를 쓰거나 `d * d <= n` 으로 피한다.
- **`ir-interpreter` 의 `&&` 는 짧은 회로가 아니다.** `i > 0 && arr[i-1] == …` 을
  쓰면 오른쪽이 **늘 셈해져** 범위 밖에서 터진다. 문자열 배치에서 **34/34 를 통과한
  것이 우연**이었던 사례가 있다(`undefined + 0 = NaN` 이라 비교가 전부 false 로
  떨어져 답이 마침 맞았다). `if` 를 포개거나 정수 플래그로 갈라라.
- **글자를 변수에 담으면 java emit 이 깨진다** — 이 배치는 글자를 안 다루므로 해당
  없으나, 배열 원소를 변수에 담는 것은 무방하다.
- **`matrix-mul` 의 스트라센이 갈림길이다.** 재귀를 IR 로 펼 수 있는지 먼저 확인하고,
  못 펴면 **곱셈 수를 세는 쪽만 IR 로 두고** 까닭을 `irs.ts` 주석에 적어라
  (`tsne` 가 IR 을 두지 않기로 하고 까닭을 남긴 선례가 있다).

**검수 조건**: IR 이 셈하는 값과 algorithm 이 셈하는 값이 **손잡이 전 값에서** 같아야
한다. 전 조합을 실측해 보고하라. 어긋나면 그것이 거짓말이고 코드 패널을 다는 까닭이
지워진다.

## 공통 지침 — 이 저장소가 실제로 데인 자리들

### 등록 이름 (네 배치 연속 어긋났다)

```ts
registerAlgorithm('<camelCase>', fn, { mechanismKind: 'reactive' });
registerProjector('<camelCase>Projector', factory);
```

- `FacetJson.algorithm` = `module:<camelCase>`, `projector` = `module:<camelCase>Projector`
- **IR id 는 kebab-case** (`'euclidean-imperative'`) — `facet.ts` 의 `ir:` 참조도 같이
- `initialData.type` 도 **kebab-case**

### 취소 삼키기 (C8 — 정본은 하나뿐)

```ts
try {
  input = await ctx.waitForInput();
} catch (err) {
  // reset/destroy 가 reject 한 것은 정상 종료 경로다 (C6·C8).
  if (!ctx.cancelled) throw err;
  return;
}
```

`catch { return; }` 는 **금지**. **문(gate)이 루프 바디의 첫 줄일 때만** 진입 검사를
대신한다 — 문이 바디 중간이면 그 앞 구간이 취소에 안 걸린다. 조각 배치에서 넷이
여기 걸렸고, **레벨이 깊은 루프는 바깥에도 둔다**(안쪽 문이 막아 줘도 그 사실이
안쪽을 읽어야 보이는 것이 문제다).

### 걸음 벽시계

`S-piece` 85–87 행이 **가장 얇은 걸음 800ms** 를 바닥선으로 못박는다. 완제품은
컨트롤바가 있어 조각만큼 빡빡하지 않으나, **자동 재생의 걸음은 같은 잣대로 본다.**

- **규범이 재는 것은 `애니메이션 + stepMs` 이지 `stepMs` 혼자가 아니다.**
- **정지 걸음을 두지 마라** — 판을 세우는 첫 걸음과 마무리 걸음이 특히 걸린다.
- **셈하지 말고 실측하라.** 측정용 검사를 임시로 두고 걸음마다 찍는다.

### 화면 문안

- **열 언어 전부**(en·ko·ja·zh·ar·es·fr·hi·id·pt). 하나라도 빠지면 `facet-i18n` 실패.
- **숫자 라벨은 열 언어로 쓰지 말고 문자열로** (`label: '36'`).
- **뜻이 언어마다 갈리지 않게 하라.** 검사는 키가 다 있는지만 보지 뜻이 같은지는 못
  본다 — 한 facet 의 description 이 다섯 언어에서 거짓을, 다섯에서 참을 말한 전례가 있다.
- **파생값을 문안에 못박지 마라.** 조각 배치에서 `"곱 셋"` 이 안쪽 치수 3 을 상수로
  박아 행렬을 바꾸면 화면이 거짓이 되는 자리가 있었다. `{count}` 로 payload 를 따르게 한다.
- **헬퍼로 감싸지 마라.** `makeReadout(i, key, fallback)` 처럼 묶으면 키와 en 원본이
  변수가 되어 `en-original-matches-declaration` 이 그 문안을 아예 못 본다.
- **고정 폭 자리는 열 언어 중 가장 긴 것으로 확인하라.** 번역이 길어 레이아웃이 깨진
  전례가 있고 그것을 막는 검사는 없다.

### 완제품에만 있는 것

- `layout` · `header`(title-block) · `metrics` 를 선언한다. `title-block` 은 원칙 6 의
  예외 셋 중 하나다(2026-09-11 에 들어왔다).
- 컨트롤은 `[...CONTROL_SET.playback, <손잡이>]`
- `registerAlgorithm` 옵션에 `mechanismKind: 'reactive'` (`FacetJson` 에 그런 필드 없다)
- **분수형 수치를 `ctx.metric` 에 싣지 마라** — control-bar 가 `String(value)` 로 찍고
  metric 은 누적기라 소수 delta 가 부동소수 오차를 쌓는다. 정수만 싣고 평균 같은
  파생값은 stage 가 직접 그린다.
- 시각화는 **자기 패키지 안에 직접 그린다**(원칙 6). 예외는 `control-bar` ·
  `code-view` · `title-block` 셋뿐이다.

### 선언한 문안은 화면에 떠야 한다

고정 데이터에서 **모든 갈래가 적어도 한 번 일어나는지 확인하라.** 문자열 배치에서
선언에 있는 캡션이 뜰 수 없었고 하필 그 갈래가 그 방법이 틀리지 않는 이유였다.

### 스크래치

`/private/tmp/.../scratchpad/` 를 **형제 넷과 공유한다.** 파일 이름에 토픽을 붙여라
(`sieve-measure.mjs`). 측정 스크립트가 서로 덮인 전례가 있고 우연히 발견했다.
**근거의 정본은 스크래치가 아니라 커밋된 테스트여야 한다.**

### 돌리지 말 것

- `pnpm install` 을 각자 돌리지 마라 — lockfile 충돌.
- `pnpm test` 전수를 돌리지 마라 — 남의 미완성 패키지를 물어 흔들린다.
- `packages/bootstrap` · `apps/playground` · `packages/authoring` 를 건드리지 마라.

## 절차

1. **동시에 띄운다.** 완제품도 서로 베낀다 — 지도학습 완제품 셋을 격리해 만들었더니
   셋 다 같은 코어 결함에 걸렸고, 그것이 규범이 아니라 코어 문제라는 증거가 되었다.
2. **전수 검사와 계측은 호스트가 배치 끝에 일괄로.**
3. **카탈로그에 `facetId` 를 붙인다** — 다섯 토픽이 이미 자리를 잡고 있다.
4. **개념 메타를 다시 묶는다.** 지금 조각 셋의 개념이 토픽 이름으로 묶여 있다.
   완제품이 서면 **완제품 하나 + 그 `origin` 조각 전부**가 한 묶음이 되고, 조각 개념의
   `contrastWith` 도 함께 손본다. `euclidean` 과 `sieve` 는 **조각이 없어 혼자 선다** —
   그래서 **기존 개념과 갈리는 것이 더 중요하다**(호제법은 `findRoot` 나 반복 축소
   계열과, 체는 `hashToBucket` 이나 표시 계열과 스칠 수 있다).
