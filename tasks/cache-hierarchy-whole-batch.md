# 캐시 계층 완제품 다섯 — 배치 기록

2026-09-12. 잣대와 절차는 `tasks/whole-batch-protocol.md` 에 있다.

## 판정 — 다섯 다 만들었다

| | IR | 조작 | 통합 | 판정 |
| --- | --- | --- | --- | --- |
| `cache-line` | 선다 | 라인 4·8·16·32B × 두 접근 패턴 | 조각 4 | 만듦 |
| `direct-mapped-cache` | 선다 | 배열 4·6·8·9·12·16라인 → 33·33·33·48·78·100% | 조각 2 | 만듦 |
| `set-associative-cache` | 선다 | 연관도 1·2·4·8 → 미스 15·11·5·5 | 조각 1 | 만듦 |
| `cache-replacement` | 선다 | LRU 5 / MRU 6 / FIFO 7 — **셋 다 갈림** | **0** | 만듦 |
| `write-policy` | 선다 | through 10 / back 5 | 조각 2 | 만듦 |

`cache-replacement` 는 잣대 ③이 비었다(잇는 조각 0). 잣대 ①·②가 둘 다 강하고
저장소에 조각 0 인 완제품의 선례가 있어 만들었다. 대신 **글이 그 자리를 메우게**
사양에 적었다 — 이 화면만으로 개념이 서야 하고 다른 화면을 가리켜 보완할 수 없다.

## 계측 — 운동 조항이 통했다

```
평균 코드 유사도   0.11   (임계 ≤ 0.35)
최고 코드 유사도   0.16   (임계 ≤ 0.50)
최고 좌표 겹침     0.27   (임계 ≤ 0.60)
그림 어휘          6종    (임계 ≥ 5종)
운동 있는 조각     5/5    (임계 ≥ 70%)
```

| | 앞 배치 (수·비트 완제품) | 이번 |
| --- | --- | --- |
| 운동 | **1/4 FAIL** | **5/5 PASS** |
| 평균 유사도 | 0.06 | 0.11 |

**이것이 이 세션의 물음 하나에 답을 준다.** C8 은 규범 문서에 판정표까지 갖추고도
조각 아홉 중 넷이 놓쳤는데, 운동 조항은 **사양에 직접 박으니** 다섯이 다 지켰다.
조항을 어디에 두느냐가 아니라 **에이전트가 읽는 자리에 있느냐**가 갈랐다.

유사도가 0.06 → 0.11 로 오른 것은 같은 요구를 다섯이 받았기 때문이지만 임계와는
거리가 멀어 치를 만한 값이었다.

## typecheck 금지를 푼 것이 결함 둘을 잡았다

앞 배치들에서 "새 패키지라 `pnpm install` 전" 이라며 typecheck 를 통째로 금지했더니
조각 아홉 중 하나, 완제품 넷 중 하나가 타입 오류를 안고 나왔다. 이번 배치 중간에
한 에이전트가 **자기 패키지 하나만 검사하는 길**을 찾았다 — root `node_modules` 로
의존이 해결되므로 `npx tsc -p <dir>/tsconfig.json --noEmit` 은 돌아간다.

도는 셋에게 그 사실을 알렸고, 결함 둘이 잡혔다.

- `direct-mapped-cache` — 쓰지 않는 지역 상수
- `cache-replacement` — **`mountView` 반환형이 오픈 타입이라 `instance.setPolicy?.()` 가
  `{}` 로 좁혀져 호출 자체가 불가능했다.** 손잡이가 죽는 결함인데 눈으로는 안 잡힌다.

**금지의 범위를 잘못 잡았던 것이다.** 워크스페이스 전체(`pnpm typecheck` · `pnpm -r`)는
형제의 미완성 패키지를 물어 금지가 맞지만, 자기 패키지 하나는 그렇지 않다.

## rule-guard — 위반 0 건

C3 phase 등치 5/5 · C8 정본 5/5(금지형 0) · `waitForInput` 앞뒤 5/5 ·
`mechanismKind: 'reactive'` 5/5 · C4 참조 전부 일치 · C5 미등록 0 ·
C10 화면 문자열 리터럴 0 · 32비트 천장 근거 5/5(검사가 다시 잰다).

**사양에 박은 것이 전부 지켜졌다.** 앞 배치들에서 값을 치르고 얻은 조항들이다 —
projector 등록명, C8 정본 모양, `segments[].value` 는 number, 구간 라벨은 단일
문자열, IR 은 배열을 만들 수 없다, `mechanismKind` 의 선언 자리.

### 표본 재기 지시가 두 번 작동했다

두 배치 전 감사가 `IR` 타입 출처를 "지금 고치면 4파일" 이라 권했는데 저장소는 이미
106:132 였다. 그 뒤 사양에 **"통일하라는 권고를 낼 때는 저장소 전체에서 그 갈림이
몇 대 몇인지 먼저 세고 그 수를 권고에 적어라"** 를 넣었다.

이번 감사는 같은 자리를 다시 만나 이렇게 적었다 — *"저장소 전체는 이미 109:147 이다.
이번 다섯을 고쳐도 0.4 퍼센트포인트 움직인다. 두 배치 전 감사가 '4 파일이면 싸다' 고
한 것이 바로 이 지점의 오판이었다."* **자기 이전 오판을 명시적으로 참조해 교정했다.**

죽기 전 남긴 자기 측정 오류도 스스로 고쳐 왔다 — `params\.t` 가 `params.theme` 에도
걸려 "252/252" 라는 수가 아무것도 증명하지 못했다는 것(실제로는 **252 중 96 이 안
받는다**), 그리고 zsh 가 경로 변수를 단어 분리하지 않아 grep 이 열 경로를 한 덩어리로
받았다는 것.

### 권고 하나를 기각했다

`label.cache` 키 둘을 상수로 내리라 했는데, **키 이름만 같고 en 원본이 달랐다.**

| | en 원본 | C10 경계 판정 |
| --- | --- | --- |
| `write-policy` | `cache` (소문자 한 낱말) | 표식 → 상수가 맞다 |
| `direct-mapped-cache` | `Cache` (대문자) | 소문자 조항에 안 걸린다 |
| `cache-replacement` | `Cache slots` (**두 낱말**) | 여러 낱말 구 → 키가 맞다 |

C10 은 "**소문자** 도식 라벨 **한 단어**" 를 표식으로 규정한다. 소문자는 도형에 새긴
라벨이고 대문자로 시작하는 것은 제목처럼 읽히는 UI 레이블이라, 이 갈림은 판정이
제대로 작동한 결과다. **감사가 키 이름이 같은 것만 보고 en 원본을 열지 않았다.**

### 규범 하나를 보강했다

감사가 `write-policy` 의 phase 집합을 한 번 "불일치" 로 잘못 읽을 뻔했다. `irs.ts` 가
phase 를 **위치 인자로 받는 헬퍼**(`decl(name, init, 'fill')`)를 쓰는데 `phase:` 라는
모양만 찾는 grep 에는 안 잡히기 때문이다. C3 에 그 꼴을 허용으로 명시하고, **세는
쪽이 `phase:` 만 보고 판정하지 않도록** 한 문단을 더했다.

## 데이터가 우연히 가려 준 결함 하나

개념 메타를 쓰던 에이전트가 `write-policy/src/projector.ts` 에서 찾았다 —
`caption.fold` 가 "줄 N 을 또 고쳤다" 라고 말하면서 **칸 번호**를 넣고 있었다.
`mark-dirty` payload 에 줄 번호가 아예 없어 projector 는 넣을 것이 그것뿐이었다.

지금 데이터에서 되풀이 고침이 **줄 0↔칸 0, 줄 1↔칸 1 처럼 둘이 우연히 같은 자리**
에서만 나서 화면이 거짓을 말하지 않았다. `writes` 배열이나 칸 수가 바뀌면 곧바로
거짓이 된다.

**검사 13개가 전부 통과하는데 그 13개는 이것을 잡은 적이 없다.** 캡션에 들어간 수가
줄의 것인지 칸의 것인지를 아무도 재지 않았다.

이 배치가 모은 목록에 한 줄이 더 붙는다.

| 못 본 주체 | 모양 |
| --- | --- |
| 검사 | 틀린 값이 **통과한다** (32비트 넘침 · `double`→`int`) |
| 검사 | 대상을 **찾지 못한다** (래퍼 뒤로 숨은 호출 · 주석 속 예시) |
| **데이터** | **우연히 맞아 드러나지 않는다** (`{line}` 에 들어간 칸 번호) |

앞의 둘은 **재는 수단**의 한계이고 이것은 **고른 데이터**의 성질이다. 만든 사람은 자기
데이터로만 보고, 감사는 규칙만 보고, 검사는 자기가 재는 것만 본다. 세 층 어디도 "이
수가 정말 저 이름의 것인가" 를 묻지 않았다. **잡은 것은 화면을 정독한 제삼자였다.**

같은 배치에서 `conflict-miss` 가 "마운트 직후엔 빈 줄이 셋이 아니라 넷이라 라벨이
거짓이 된다" 며 스스로 막은 일이 있었다. 같은 종류인데 한쪽은 만들며 잡았고 한쪽은
놓쳤으며, 갈린 이유는 **주장하는 수를 데이터가 우연히 맞춰 주었느냐**뿐이다.

## 에이전트가 스스로 잡은 것

- **`cache-replacement` 가 자기 검출 스크립트의 오류를 잡았다.** cpp 가 FAIL 로 떴는데
  자기 정규식이 `std::vector<int>&` 를 수학 이름으로 오인한 것이었고, IR 트리를
  구조로 다시 재어 확정했다. **도구를 의심하고 다시 쟀다.**
- **`set-associative-cache` 가 `&&` 함정을 피한 게 아니라 만들지 않았다.** 빈 칸의
  시각을 0 으로 두면 언제나 최솟값이라 LRU 하나로 빈 자리를 먼저 고르게 된다 —
  "자리가 있고 그 자리가 비었는가" 를 물을 자리 자체가 사라진다.
- **`write-policy` 가 계기 검사를 회차별로 고쳤다.** 끝 상태만 보던 것을 회차마다
  값을 뜨도록 바꿔 `{10,10}` → `{10,5}` 를 잠갔다. 누적되면 둘째가 `{20,15}` 가 되어
  **고침 횟수까지 갈려 버리는** 붕괴를 이 검사가 먼저 잡는다.
- **`cache-line` 이 경고받은 세 자리를 각각 검사로 잠갔다** — reactive 는 전수 검사가
  `getAlgorithmMechanismKind` 로, `segments[].value` 는 1차 데이터 사다리와 등치로,
  구간 라벨은 `typeof === 'string'` 단언으로. **"나중에 누가 되돌리면 검사가 먼저
  깨진다"** 는 것이고, 사양에 조항을 적는 것보다 강하다.

## 프로토콜에 올릴 것 — 네 번의 독립 발견

**`ctx.metric` 은 누적 채널이고 러너는 되감기 때만 계기를 비운다.** 손잡이를 돌려 다시
도는 것은 되감기가 아니라, 그대로 두면 판을 거듭할수록 수가 쌓여 손잡이와 무관한 값이
뜬다. 지금 값을 들고 **차이만 보내는 헬퍼**가 필요하고, 계기 이름은 호출부에 리터럴로
남아야 C5 를 지킨다.

**서로 못 보는 넷이 각자 부딪혔다** — `twosComplement`(앞 배치, 델타 0 이면 계기 이름이
통째로 안 실리는 것까지 발견) · `cacheLine` · `directMappedCache` · `writePolicy`.
코어의 구조적 제약이 확실하다.

함께 올릴 것 둘.

- **백분율은 반올림으로 셈한다** — `(x * 100 + n // 2) // n`. 내림으로 하면 사양 표와
  어긋나는 자리가 생기고(`12.5% → 12` vs `13`, `77` vs `78`), 실수를 거치지 않으므로
  java · C# 의 `double → int` 벽도 함께 피한다. 둘이 독립적으로 같은 답에 닿았다.
- **`control-label-fits` 가 segmented-slider 라벨에 `이름 — 설명` 꼴과 24자 초과를
  금지한다.** 사양에 없던 함정이라 `cache-replacement` 가 부딪혀 알아냈다.
