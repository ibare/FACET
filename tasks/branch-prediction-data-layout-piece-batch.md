# 분기 예측 · 데이터 배치 조각 열둘 — 배치 기록

2026-09-18. 흘려보내기 방식의 두 번째 배치. 서브도메인 둘(분기 예측 6 · 데이터 배치 6)을
공통 안내문 둘로 나눠 **한꺼번에 띄웠다.** 규범은 `tasks/piece-batch-protocol.md`.

       piece-check 전체 · 등록 · typecheck · test · scene-audit

**지적이 줄어든 까닭이 도구에 있다.** 첫 배치에서 되풀이된 둘(비리터럴 `t()` · payload
통째 단언)을 `piece-check` 로 옮겼더니, 이번에 셋(`lanes-in-step` · `fetch-ahead` 등)이
**에이전트 선에서** 그 검사에 걸려 스스로 고쳤다. 호스트까지 올라오지 않았다.

## 사양을 쓰며 호스트가 먼저 잡은 것

값을 셈으로 확정하다 **데이터가 주장을 못 보이는 자리** 둘을 띄우기 전에 찾았다 —
첫 배치 `branch-flush` 에서 배운 물음("이 데이터로 동사가 화면에서 일어나는가")을 스크립트로
돌린 결과다.

- `four-state-hysteresis` — 처음 고른 열에서 1비트와 2비트가 똑같이 4 번 틀렸다.
  비교를 버리고 "N 하나로는 선을 못 넘고 둘이면 넘는다" 를 보이는 열로 바꿨다
  (1비트와의 견줌은 `one-bit-double-fault` 가 진다).
- `pattern-from-history` — TTN 12 걸음에서 이력 표와 카운터가 둘 다 4 번 틀렸다.
  교대 무늬 TN 으로 바꿔 3 대 6 으로 갈랐다.

그래도 사양에 한 번 실수했다 — `backward-taken` 에 고치다 만 프로그램 표기가 섞여
나갔다. 곧바로 정정을 보냈고 에이전트는 이미 정본을 골라 쓰고 있었다.

## 계약 카드에 더한 것 — 에이전트가 찾아 왔다

- `messages` 는 **키가 바깥, 언어가 안쪽**. 거꾸로 써도 tsc 는 통과한다 (`misprediction-penalty`)
- `mount` 는 **`initialData` 가 없어도 던지지 않는다** — `canvas-attach` 가 `config: {}` 로
  마운트한다 (`field-order-size` · `row-vs-column-walk` 가 따로 걸렸다)

## rule-guard 가 규범에 넘긴 것 — 결정이 필요하다

- **C8 "모든 루프" 와 관행이 어긋난다.** ctx 를 쓰는 함수 안의 await 없는 루프 중 검사를 둔
  것 23 · 안 둔 것 100. 동기 루프에서는 `cancelled` 가 바뀔 수 없어 검사가 실제로 걸리지
  않는다. "await 없는 동기 루프는 대상이 아니다" 로 문면을 좁히면 갈림이 끝난다.
- **원칙 1 과 stage 의 타입 가져오기.** stage 293 중 31 이 `./algorithm.js` 를 가져온다
  (타입만 21 · 값 10). 원칙 문면이 타입 가져오기를 허용하는지 적어 둘 필요가 있다.
