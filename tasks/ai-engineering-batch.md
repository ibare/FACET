# AI 엔지니어링 조각 스물 · 완제품 열하나 · 개념 서른하나 — 배치 기록

2026-09-18. AI 엔지니어링의 남은 세 서브도메인(검색 증강 · 생성 제어 · 추론 효율)을 닫은 배치.
규범은 `piece-batch-protocol.md` · `whole-batch-protocol.md` · `concept-meta-batch-protocol.md`.

## 시간

```
12:35  사양 초안 에이전트 넷을 동시에 (조각 서브도메인 셋 + 완제품 열하나)
12:41~ 조각 사양 셋 도착 (5.3 ~ 6.7 분) — 호스트는 "판단이 필요한 자리" 만 검토
12:43  조각 열을 띄우고, 하나 끝날 때마다 다음을 넣음 (칸 열)
13:00  조각 스물 완료 — 조각 하나 5.1 ~ 10.1 분
13:00  등록 · typecheck · test · rule-guard 셋(서브도메인마다)
13:05  완제품 사양 도착(27 분, 조각이 도는 동안 나란히) → 열을 띄움, top-k-top-p 는 사양 수정 뒤
14:05  완제품 열하나 완료 — 하나 9.5 ~ 59 분
14:05  개념 메타 열한 묶음 (4.3 분), rule-guard 둘, 감사 지적 되돌림, 커밋
```

조각 스물이 **띄운 뒤 17 분**에 모두 끝났다 (앞 배치 열둘 9.5 분 · 여덟 14.8 분). 칸을 열로 두고
흘려보내 가장 느린 하나가 전체를 붙잡지 않았다.

## 사양 초안을 에이전트에게 — 이번에는 조각까지

앞 배치는 완제품 사양만 에이전트에게 맡겼다. 이번에는 **조각 사양 셋도** 서브도메인마다 에이전트
하나에게 맡겼다 (지시문 한 장 + 앞 배치 사양 본보기). 각자 `sim.py` 로 모든 수를 셈하고, 주장이
데이터에서 갈리는지 `assert` 로 확인하고, "판단이 필요한 자리" 를 보고했다. 호스트가 되돌린 것은
하나뿐이다 — 완제품 `top-k-top-p` 가 k 와 p 를 함께 걸 때 **둘 다 원래 분포에서** 재게 적었는데,
주류 구현(HF 의 TopK → TopP, vLLM)은 k 로 자른 뒤 다시 나눈 분포에서 p 를 잰다. 그 규약으로 다시
재니 주장("작은 쪽이 이긴다")이 서지 않아 "작은 쪽보다도 적게 남을 수 있다" 로 바뀌었다.

사양 초안 에이전트가 **형제 사양을 서로 대조해** 세 자리를 스스로 맞췄다 (맥락 조립이 조각과 같은
거리 셈을 쓰게, 하이브리드가 조각과 같은 불용어를 쓰게, top-k/p 가 조각과 다른 문장을 쓰게).

## 호스트가 낳은 결함 — 전제 각주

지시문에 "예로 정한 값임을 **화면과 설명 글에서** 밝혀라" 라고 썼다. S-piece 는 "전제는 글이 밝힌다.
화면에 각주를 두지 않는다" 인데. 조각 다섯 · 완제품 다섯이 상시 각주를 올렸고, 호스트 자신도 하나를
"상시 캡션이 아니라 괜찮다" 고 넘겼다가 감사에서 되돌렸다. 모두 만든 에이전트가 1 분 안팎에 걷었다.
계약 카드 금지 목록 · 두 프로토콜에 조항으로 넣었고, 전제는 개념 메타가 밝히게 했다.

## rule-guard — 다섯 번, High 0

| 대상 | Medium | 주된 것 |
| --- | ---: | --- |
| 조각 · 검색 증강 | 6 | 각주 4, payload 원소 단언(C9) 2 — 원소 배열 단언은 piece-check 가 못 잡는다 |
| 조각 · 생성 제어 | 1 | payload 가드 없는 소비 |
| 조각 · 추론 효율 | 1 | 운동의 출발값을 `prev` 에서 꺼냄 (S-scene) |
| 완제품 · 생성 제어 | 3 | 캡션의 수가 끝 표식을 낱말로 셈, **판 시작 뒤 걸음 경계가 없어 운동 둘이 한 번도 안 보임** (beam), 글꼴 리터럴 |
| 완제품 · 검색 · 효율 | 5 | 앞 판 덩이가 남아 화면 수 ≠ 계기 (chunking), IR 이 위 3 만 골라 4~8 위 걸음에서 패널이 코드에 없는 줄을 켬 (hybrid), 설명 글의 C(16,4) 를 1001 로 셈, 각주 둘 |

한국어 조사는 조각 스물 · 완제품 열하나 전수 대조에서 **0 건** — 공통 안내문에 "자리 표시자 바로 뒤에
받침 따라 바뀌는 조사를 붙이지 않는다" 를 넣은 뒤다.

짚인 결함 중 둘은 코어의 성질에서 온다. reactive 의 `emit` 에는 지연이 없어 **걸음 경계는 `sleep`
뿐**이다 — 덮이는 phase(앞 배치 조항)와 같은 뿌리에서 "덮이는 운동" 이 나왔다. 그리고 한 조각은
셈을 한 곳으로 모으다 `algorithm.ts` 가 `scene.ts` 를 가져오게 만들었다 (원칙 1 역방향 — 되돌림).

## 방침으로 정한 것 (프로토콜에 옮김)

- **완제품도 화면에 전제 각주를 두지 않는다** — S-piece 조항이 조각에만 걸려 열하나가 5 : 6 으로 갈렸다
- **IR 안의 주석은 영어** — 코드 패널이 어느 언어에서든 그대로 띄운다. 한국어 셋 · 영어 셋 · 없음 하나로 갈렸다

## 기록만 하고 두는 것

- silent `init` 으로 바탕을 그리는 짜임이 저장소에 일곱 (C2 문면은 금한다). 관행이 문면을 앞서 있다
- `draft-then-verify` · `short-waits-for-long` 은 셈을 장면(또는 알고리즘의 순수 함수)에 두고 알고리즘은
  번호만 발신한다. 규칙 위반은 아니나 층 나눔이 흐려지는 쪽이다
- 이 배치에서 개념 메타를 Workflow 도구로 띄웠다 — 사용자가 요청하지 않은 도구다. 에이전트 수와 비용은
  개별 호출과 같았다
