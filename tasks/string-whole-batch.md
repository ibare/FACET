# 문자열 알고리즘 완제품 배치 — 사양 원본

조각 열하나(`tasks/string-piece-batch.md`)를 끝낸 뒤의 완제품 배치다. 규범은
`tasks/whole-batch-protocol.md` 이고 이 문서는 **이 배치에서 그것을 어떻게
적용했는가** 를 적는다. 둘이 어긋나면 프로토콜이 이긴다.

## 판정 — 일곱 다 만든다

잣대 셋을 각각 매겼다.

| 토픽 | ① IR 이 여섯 언어로 갈린다 | ② 조작이 논증을 진다 | ③ 조각을 잇는다 | 판정 |
| --- | --- | --- | --- | --- |
| KMP | **강** — 실패 함수와 주 루프가 배열·반복·조건뿐 | **선다** (2차) | 조각 2 | 만듦 |
| Boyer-Moore | **강** — 나쁜 문자 표를 배열로 편다 | **선다** (2차) | 조각 2 | 만듦 |
| Aho-Corasick | 중 — 트라이를 `노드×알파벳` 2차원 배열로 편다 | **선다** (1차) | 조각 2 | 만듦 |
| 편집 거리 | **강** — 2차원 표 그 자체 | **선다** (1차) | 조각 2 | 만듦 |
| Z-알고리즘 | **강** | **선다** (1차) | 조각 1 | 만듦 |
| 접미사 배열 | 중 — 정렬을 글자 비교 루프로 편다 | **선다** (1차) | 조각 1 | 만듦 |
| Rabin-Karp | 중 — 32비트 넘침 주의 | **선다** (2차, 글의 결을 바꿔서) | 조각 1 | 만듦 |

**버릴 것이 없다.** 뒤의 셋은 잇는 조각이 하나뿐이라 ③ 이 약하지만, 프로토콜의
"하나만 약한 것으로 버리지 않는다" 가 그 자리다 — `t-digest` 가 통합 하나만 약해
만들어진 선례이고, 여기 셋은 ①② 가 둘 다 선다.

**이 배치는 IR 이 유난히 강하다.** 일곱 다 핵심 셈이 배열·반복·조건으로 펴져
이름 붙인 호출 뒤로 숨을 것이 없다. 완제품 59 종 중 17 종이 IR 0 노드인 저장소에서
드문 경우이므로, **일곱 다 코드 패널을 단다.**

## 손잡이 — 실측이 끝났다

조각 배치와 나란히 1차를 재고, 무너진 둘을 2차에서 다시 골랐다. 1차 기록은
`tasks/string-piece-batch.md` 의 마지막 절에 있다.

| 토픽 | 손잡이 | 값 | 주 수치 | 실측 |
| --- | --- | --- | --- | --- |
| KMP | 패턴 길이 | 4·6·8·10·12 | 헛수고 (단순 − KMP) | 79 → 117 → 191 → 297 → 432 |
| Boyer-Moore | 패턴 길이 | 2·4·6·8 | 평균 점프 거리 | 1.84 → 3.33 → 4.63 → 5.44 |
| Rabin-Karp | 패턴 길이 | 2·4·6·8·10 | RK 가 만진 글자 | **120 고정** / 단순 89 → 277 |
| 접미사 배열 | 글의 반복성 | 4단 | 이웃 겹침 평균 | 0.00 → 1.20 → 3.00 → 4.00 |
| Z-알고리즘 | 글의 반복성 | 4단 | 빌려오기 · 아낀 비교 | 0→2→2→6 · 7→11→13→28 |
| Aho-Corasick | 패턴 개수 | 1~5 | 읽은 글자 | **21 고정** / 따로 훑으면 21 → 126 |
| 편집 거리 | 교체 비용 | 1·2·3 | 답의 길이와 바꿈 횟수 | 비용 3 에서 길이가 바뀐다 |

### 무너진 둘을 어떻게 다시 세웠나

**Boyer-Moore.** 1차의 `알파벳 넓이` 는 씨앗 스물 평균에도 5.52 → 6.21 → 6.35 →
**5.71** → 6.16 으로 튀었다. 무작위 글에서 점프는 알파벳 크기보다 패턴 안 글자
배치에 좌우되기 때문이다. `패턴 길이` 로 바꾸니 씨앗 30 중 **29 가 완전단조**,
인접쌍 98.9% 로 섰다. 나쁜 문자 점프의 상한이 곧 패턴 길이라 구조적으로 단조다.

재는 수 넷을 함께 재 **평균 점프 거리**를 골랐다. "아낀 비교" 와 "견준 글자 수"
둘은 약했는데 까닭이 구조적이다 — 단순 견줌이 패턴 길이와 무관하게 늘 글자 수 n
에 붙박이라 **아낄 수 있는 양의 천장이 n 이고**, 패턴 길이 6 에서 이미 천장에 닿아
그 뒤로 안 움직인다.

**Rabin-Karp.** 1차의 `법(modulus)` 은 31→39건, 61→10, 17→0, 127→0 으로 단조가
아니었다. 법과 밑(31)의 산술 관계가 지배한 것이라 화면이 "크면 좋다" 는 **거짓**을
말하게 된다. 폐기했다.

`패턴 길이` 로 바꿨으나 **자연어 글에서는 그것도 무너진다** — 단순 방식도 첫
글자에서 거의 다 어긋나 견줌이 1.00× 로 붙박이라 아낄 것이 없다. **글의 결을
되풀이(`ababab…`)로 바꿔야** 산다. 그러면 RK 가 만지는 글자가 **정확히 2n 으로
고정**되고(구르기가 `m + 2(n−m)` 로 주는 만큼 확인이 `m` 으로 늘어 상쇄하는
항등식이라 씨앗 30 전부 변동폭 0), 그 옆에서 단순 견줌이 89 → 277 로 3.11× 늘어난다.

### 대조 검증

실측 전에 네 구현(단순 · BM · RK · `String.indexOf`)이 찾은 등장 자리를 대조했다 —
알려진 값 32건, 무작위 3,153건, 실측 중 전수 13,020건, **불일치 0**. 프로토콜의
"안 나오면 내 코드부터 의심한다" 를 이번엔 먼저 배제하고 들어갔고, 그래서 1차의
무너짐이 구현 탓이 아니라 손잡이 선택 탓임을 말할 수 있다.

## 데이터 — 완제품마다 글이 달라야 한다

**BM 과 RK 가 같은 글을 쓰면 한쪽이 죽는다.** BM 은 되풀이 없는 자연어에서 점프가
커지고, RK 는 되풀이 글에서만 주장이 선다. 조각과 달리 완제품은 서로 글을 나눈다.

| 토픽 | 글 | 까닭 |
| --- | --- | --- |
| KMP | 되풀이가 있는 글 | 헛수고가 벌어지려면 앞이 겹쳐야 한다 |
| Boyer-Moore | 자연어 60~80자 | 40자에서는 씨앗 30 중 22~29 로 흔들린다. 60자부터 선다 |
| Rabin-Karp | 되풀이 글 60자 (`abab…` 꼴) | 자연어에서는 주장이 무너진다 |
| 접미사 배열 | 반복성이 손잡이 | 손잡이가 글 자체다 |
| Z-알고리즘 | 반복성이 손잡이 | 같음 |
| Aho-Corasick | 패턴 묶음이 손잡이 | 조각의 글을 이어도 된다 |
| 편집 거리 | 낱말 한 쌍 | 교체 비용이 손잡이 |

**RK 의 법은 10⁶ 급으로 크게 둔다.** 조각 `rolling-hash` 의 법 1000 을 그대로 쓰면
헛일치가 끼어들어 120 고정이 깨진다. 1차에서 무너진 그 손잡이를 **화면에서 없애는
것**이 이 설계의 조건이다.

데이터 규약은 조각과 같다. **구조를 1차 데이터로 주고 파생값은 대조용으로만 두며,
수를 손으로 옮기지 않는다.** 실패 함수 · 나쁜 문자 표 · Z 배열 · 편집 표는 전부
알고리즘이 그 자리에서 셈한다.

## 잇는 조각

| 완제품 | `origin` 조각 | 완제품이 더하는 것 |
| --- | --- | --- |
| KMP | `naiveShiftByOne` · `prefixSuffixJump` | 두 방식이 같은 글에서 몇 번 견주는지 나란히 |
| Boyer-Moore | `matchFromBack` · `badCharSkip` | 방향과 근거가 한 걸음 안에서 합쳐지는 것 |
| Rabin-Karp | `rollingHash` | 굴린 값으로 실제로 찾기까지 |
| 접미사 배열 | `allSuffixesSorted` | 줄 세운 것 위에서 이분 탐색으로 찾기 |
| Z-알고리즘 | `matchLengthPerSpot` | Z 배열로 실제 문자열 찾기 |

## 공통 지침 — 이 배치에서 실제로 데인 것들

### 등록 이름 (네 번 났다. 이번엔 사양이 못박는다)

`register-names` 검사가 **projector 이름 ≠ algorithm 이름**을 요구한다. 세 배치에서
세 번 나고 문자열 조각 배치에서 **한 번에 일곱**이 어긋났다. 까닭은 늘 같다 —
사양이 규약을 안 적었다.

```ts
registerAlgorithm('<camelCase>', fn, { mechanismKind: 'reactive' });
registerProjector('<camelCase>Projector', factory);
```

- `FacetJson.algorithm` = `module:<camelCase>`, `projector` = `module:<camelCase>Projector`
- **IR id 는 kebab-case** (`'kmp-imperative'`). camelCase 로 쓰면 C4 위반이고
  `facet.ts` 의 `ir:` 참조도 같이 바꿔야 한다 — 확률적 배치에서 둘이 났다
- `initialData.type` 도 **kebab-case**

### 취소 삼키기 (C8 — 정본은 하나뿐이다)

```ts
try {
  input = await ctx.waitForInput();
} catch (err) {
  // reset/destroy 가 reject 한 것은 정상 종료 경로다 (C6·C8).
  if (!ctx.cancelled) throw err;
  return;
}
```

`catch { return; }` 는 **금지**다 — 취소와 진짜 오류를 함께 삼켜 조용히 멎는
화면이 된다. 되짚기 루프에도 `if (ctx.cancelled) return;` 을 둔다.

### IR 의 한계

- 어휘는 **배열 · 반복 · 조건 · 대입 · 함수뿐**. 큐 · 스택 · 맵 · 집합이 없고
  **비트 연산도 없다** (`IRBinOp` 는 `+ - * / // %` · 비교 · `&& ||`).
- 예약 수학 이름은 `exp` · `log` · `sqrt` · `abs` · `max` · `min` · `floor` **일곱뿐**.
  `pow` 가 없으므로 **Rabin-Karp 의 밑 거듭제곱은 루프로 셈한다.**
- **중간값이 32비트를 넘는지 본다.** 여섯 언어 중 셋은 정수 폭이 유한하다.
  `(a + b) % m` 을 `(a % m + b % m) % m` 으로 접으면 중간값이 커지지 않는다.
  확률적 배치에서 서로 못 보는 둘이 같은 벽에 부딪혀 **다른 답을 냈다.**
- **Aho-Corasick 의 트라이는 `노드×알파벳` 2차원 배열로 편다.** 맵이 없어서이기도
  하고, 펴면 실패 링크가 배열 색인으로 보이는 이점이 있다.

### 코드 패널은 화면과 같은 답을 내야 한다

**IR 이 셈하는 값과 화면이 보이는 값이 어긋나면 그것이 거짓말이고, 코드 패널을
다는 까닭 자체가 지워진다.** 사양에 **"IR 이 셈하는 자리와 algorithm 이 셈하는
자리가 모든 손잡이 값에서 같아야 한다" 를 검수 조건으로 적고**, 에이전트는 전
조합을 실측해 보고한다.

### C# 예약어 (세 번 났다)

`base` · `out` · `ref` · `params` · `lock` · `event` · `string` · `object` 를 IR
식별자로 쓰지 마라. transpiler 는 rename 하지 않는다 (`S-transpiler`). 저장소의
`pca` 가 `out` 을 써서 실제로 고쳤다.

### 열 언어

`messages` 와 `title` · `description` 은 **en · ko · ja · zh · ar · es · fr · hi ·
id · pt 열 언어를 모두** 채운다. 하나라도 빠지면 `facet-i18n` 이 실패한다.

- **숫자 라벨은 열 언어로 쓰지 말고 문자열로 적는다** (`label: '16'`). 블룸 필터가
  `{ en: '16' }` 꼴로 써서 부족 18 로 걸렸다.
- **수식 표기도 열 언어를 채운다.** 감사는 "수식이라 en 하나로 정상" 이라 했으나
  검사가 게이트다.
- **뜻이 언어마다 갈리지 않게 하라.** `bad-char-skip` 의 description 이 다섯
  언어에서 "패턴 길이만큼" (거짓), 다섯 언어에서 "그 글자를 지나친다" (참) 를
  말하고 있었다. 열 언어 검사는 **키가 다 있는지만 보지 뜻이 같은지는 못 본다.**

### 선언한 문안은 화면에 떠야 한다

Z 조각에서 `caption.extend` 가 고정 데이터에서 **한 번도 뜰 수 없었다.** 글은
규칙 전체를 말하는데 화면은 절반만 보였고, 그 절반이 하필 그 방법이 틀리지 않는
이유였다. 고정 데이터를 고르면 **모든 갈래가 적어도 한 번 일어나는지 확인하고,
안 일어나는 갈래가 있으면 데이터를 바꿔라.**

### 첫 등장에서 멈추는가, 글 끝까지 훑는가

**사양이 이것을 안 적으면 "안 본 글자" · "아낀 비교" 같은 수가 통째로 달라진다.**
Boyer-Moore 완제품에서 실제로 갈렸다 — 사양의 건너뛴 비율 41.9% → 71.9% 에 비해
에이전트가 잰 값이 74.0% → 83.1% 였고, 까닭이 그것이었다. 단조는 양쪽 다 섰으나
수가 맞지 않았다.

**잇는 조각과 맞춘다.** 비교 대상(단순 방식 · 따로 훑기)도 **같은 규칙으로** 재야
한다. 한쪽만 일찍 멈추면 견줌 대비가 통째로 거짓이 된다.

### 화면 문안을 헬퍼로 감싸지 마라

전수 검사 `en-original-matches-declaration` 은 **호출부의 en 원본이 선언의 en 과
같은지**를 본다. 읽는 자리를 `makeReadout(i, labelKey, fallback)` 같은 헬퍼로 묶으면
키와 en 원본이 변수가 되어 **검사가 그 문안을 아예 못 본다.** 같은 문안이 여럿이라
묶고 싶어지는 자리가 정확히 위험한 자리다.

**호출부에 키와 en 원본을 리터럴로 둔다.**

### 분수형 수치를 `ctx.metric` 에 싣지 마라

두 가지가 걸린다. control-bar 의 `updateMetric` 이 `String(value)` 라 평균이
`5.833333…` 으로 뜨고, `ctx.metric` 은 **누적기**라 소수 delta 가 부동소수 오차를
쌓는다.

**메트릭에는 정수만 싣고**(겹침 합 · 쌍 수 · 견줌 수), 평균 같은 파생값은 **stage 가
직접 셈해 그린다.** 주 수치가 분수형인 완제품은 매번 이 자리에 걸린다.

### 스크래치 파일 이름에 토픽을 붙여라

배치 에이전트 일곱이 **같은 스크래치 디렉터리를 쓴다.** Boyer-Moore 의 측정
스크립트가 KMP 의 것에 통째로 덮여 쓰였고, 에이전트가 작업 중에 우연히 발견했다.
발견 못 했으면 **남의 수를 제 수로 보고했을 것**이다.

`<토픽>-measure.mjs` · `<토픽>-out.txt` 꼴로 짓는다.

### 완제품에만 있는 것

- `layout` · `header`(title-block) · `metrics` 를 선언한다
- 컨트롤은 `[...CONTROL_SET.playback, <손잡이>]`
- `registerAlgorithm` 옵션에 `mechanismKind: 'reactive'` (`FacetJson` 에 그런 필드는
  없다). reactive 세 상태 — 나아가는 중 `running(true)` / 멈춤 `running(false)` /
  입력 대기 `running(false)` + `setComplete(true)`
- 시각화는 **자기 패키지 안에 직접 그린다**. 공유 View 를 새로 만들지 않는다
  (원칙 6). 예외는 `control-bar` 와 `code-view` 둘뿐

## 절차

1. **동시에 띄운다.** 완제품도 서로 베낀다 — 지도학습 완제품 셋을 격리해 만들었더니
   셋 다 같은 코어 결함에 걸렸고 그것이 규범이 아니라 코어 문제라는 증거가 되었다.
2. **전수 검사와 계측은 호스트가 배치 끝에 일괄로 돌린다.** 도는 중에 돌리면 남의
   미완성 패키지를 물어 결과가 흔들린다. (문자열 조각 배치에서 호스트가 `pca` 의
   IR 식별자를 고치고 그 패키지 테스트를 안 돌려 전수에서 6건 터뜨렸다.)
3. **카탈로그에 `facetId` 를 붙인다.** 일곱 토픽이 이미 `{id, name}` 으로 자리를
   잡고 있고 조각 열하나가 `origin` 으로 그것을 가리킨다. 완제품이 서면
   `facetId: 'facet:<camelCase>'` 를 더한다.
4. **개념 메타를 다시 묶는다.** 지금 조각 열하나의 개념이 **토픽 이름으로** 묶여
   있다(완제품이 없었으므로). 완제품이 서면 프로토콜대로 **완제품 하나 + 그
   `origin` 조각 전부**가 한 묶음이 되고, 완제품 개념을 더하면서 조각 개념의
   `contrastWith` 도 함께 손본다.
