## 사양에서 호스트가 정한 것

- **w-divide 의 w = 0 걸음은 둔다** — 질문이 "왜 w 가 0 이면 점이 되지 못하는가" 까지 품었다.
- **scale-stretches 의 줄이기 걸음은 둔다** — desc "늘이고 줄인다". 그 걸음에서 y 축 꼭짓점이 움직이는 것은 사실대로.
- **depth-test 는 직사각형 판** — triangle-to-pixels 와 갈라 깊이 견줌만 쥐게 했다.
- **orthographic-keeps-size 는 원근과 견주지 않는다** — 견줌은 설명 글에만.

## 이 분야에서 새로 정한 것 — 색은 셈의 값이다

조명 · 보간 · 광선 조각은 셈의 결과가 곧 색이다. 선형 0..1 값을 `rgb(...)` 로 바꿔 칠하는 순수 변환은 색 리터럴이 아니라고
판단했다(S-view Exception 에 올렸다). 반대로 **무엇을 가르는 색** — R · G · B 채널 막대 — 을 단위 벡터 `(1,0,0)` 으로 만든 것은
디자인 색이라 `categorical` 로 돌렸다(color-bleeding 조각 · global-illumination 완제품 둘이 같은 꼴로 걸렸다).

## 감사가 잡은 것

C6 · 장면 경계는 거의 걸리지 않았다(공통 안내문의 줄이 먹혔다). 대신 **설명 글과 캡션이 셈보다 앞서 나간** 꼴이 많았다.

| 꼴 | 예 |
| --- | --- |
| 셈하지 않은 일반화 | depth-test "차례를 바꾸면 달라지는 것은 어느 판이냐뿐" — 셈해 보니 덮어씀 · 버림의 **자리가 맞바뀐다** |
| 사양 문구의 사실 오류 | look-at-direction "참 위가 뒤로 기운다" — 실제로는 **앞으로**(바라보는 쪽으로). 사양 에이전트의 동사 방향이 sim 에 단언되지 않았다 |
| 설명 글의 주어 | light-bounces-many "더하는 몫이 0.6 배로" — 0.6 배로 주는 것은 지나온 몫 |
| 캡션의 결론 | ambient-diffuse-specular "따르는 방향이 없다" · nearest-hit "지금까지의 어느 것보다 가깝다"(견준 값 없이) |
| 반올림 | energy-conserving 70° 에서 보이는 몫의 합이 0.001 어긋남(사양 대조값 유래 — 설명 글이 밝힘) · color-bleeding 반올림 자릿수 서술 |
| 그 밖 | 음수를 ASCII 하이픈으로(넷, 권고로 맞춤) · 스침 판정을 `=== 0` 으로(허용치로) · 운동 중 합이 먼저 뜸(triangle-to-pixels) |

감사 열둘 중 여섯이 위반 0 이었다.

## 호스트 쪽
